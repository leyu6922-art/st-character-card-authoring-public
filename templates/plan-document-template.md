## 五、世界书条目架构（N条目）

### 5.0a 触发策略声明（🚨 必填 — 构建前决定整体触发策略）

> 在逐个声明条目 key 之前，先决定整体策略。T78 教训：先加厚再修结构会适得其反。

| 决策项 | 选项 | 选择 |
|--------|------|:--:|
| 模型/预设上下文预估 | 充足 / 有限 | |
| 主档案触发方式 | 自然角色名直接触发 / 中厚速览+深度档案 / 场景绑定 | |
| Token 负载预估（首轮触发+常驻） | ___ tokens | |
| 选开 vs greeting 模式（G型） | 选开 / greeting / 不适用 | |
| 是否需要分层触发 | 是（速览+深度）/ 否（自然名直接触发全部档案） | |
| 理由 | （一句话：为什么选这种策略） | |

**策略选择指南**：
- 默认：自然角色名直接触发主档案（1500-2500字），高 token 不是硬错误
- 仅在 ST 实测截断/模型质量下降时 → 中厚速览（250-350字自然名触发）+ 深度档案（复合词按需触发）
- 禁止：`角色名档案` 作为唯一 primary key（死代码）

### 5.0b 世界书触发设计矩阵（必填）

> 先声明每条世界书“为什么触发、何时触发”，再写 keys。禁止写完内容后随手填关键词。

| ID | 条目名 | 内容类型 | 触发意图 | 是否首轮需要 | 推荐触发模式 | primary keys | secondary_keys | selective | enabled | 误触发风险 | 处理策略 |
|---:|---|---|---|:--:|---|---|---|:--:|:--:|---|---|
| 0 | OOC防护 | 系统 | 常驻规则 | 是 | 常驻 | [] | [] | false | true | 低 | constant=true, keys=[] |
| 4 | 角色基础档案 | 人物 | 人物按需 | 视greeting | primary-only | 角色专名 | [] | false或true+空secondary | true | 中 | 专名自然触发 |
| 8 | 子地点场景 | 场景 | 场景按需 | 视greeting | 范围绑定 | 子地点词 | 上级地点/阶段 | true | true | 中-高 | 避免裸用泛词 |
| 20 | 事件种子 | 事件 | 手动/条件事件 | 否 | 模块开关 | 事件名 | [] | false | false | 低 | enabled=false |

触发模式选择：
- 常驻规则：`constant=true, keys=[]`
- primary-only：唯一专名/核心角色名；`secondary_keys=[]` 时即使 `selective=true` 也会退化为 primary-only
- 范围绑定：局部泛词必须 `selective=true + secondary_keys=[上级范围]`
- 事件种子：默认 `enabled=false`
- G型选开身份：`constant=true, enabled=false`
- G型greeting身份：`selective=true + secondary_keys` 精确对齐 greeting 首行

### 5.0c 玩家身份与双选开契约（G型/身份卡必填）

> 每条玩家身份卡先声明职责，再决定装载方式。新卡必须复制 `templates/player-agency-modes.example.json`：自动推进与玩家边界/悬停均为 `feature_toggle`、`enabled=false`。它们不能因 comment 含“选开”被误判为身份。

| ID | 条目名 | entry_role / feature_mode | 内容职责 | 默认状态 | 验收 |
|---:|---|---|---|---|---|
| 0 | OOC与身份底座 | `system_constant` | 声明当前身份由玩家扮演，AI不冒充玩家 | 常驻 | keys=[] |
| 1 | 苦主身份 | `identity_toggle` | 定义 `{{user}}`=苦主 | 关闭，UI手动启用 | 一次只开一条身份 |
| 2 | 征服者身份 | `identity_toggle` | 定义 `{{user}}`=征服者 | 关闭，UI手动启用 | 一次只开一条身份 |
| 3 | 自动推进剧情 | `feature_toggle` / `narrative_director` | NPC、环境、一个候选事件可主动推进 | **关闭，UI手动启用** | 不替玩家行动 |
| 4 | 玩家行动边界与场景悬停 | `system_constant` / `player_agency_boundary` | 合并边界和悬停，锁住玩家代理权 | **常驻，enabled=true** | 七类禁止项+接管点+优先于导演 |
| 5 | 角色档案 | `common_content` | 人物素材 | 自然触发 | 人物/称谓自然 key |
| 6 | 独立事件 | `common_content` | 一个局部可发生事件 | 自然触发 | 人物+场景或人物+行动等至少两类 |

组合规则：边界/悬停开启时优先于自动推进；导演只可推动 NPC、环境和一个候选事件，不能替当前玩家说话、思考、决定、移动或结算结果。完整规格与自动门控见 `references/design-patterns/g-type-toggle-and-natural-trigger-contract.md`。

自然事件模式：`enabled=true, constant=false, selective=true`。手动候选事件模式：`enabled=false`，仅用于明确的 UI/EJS/阶段装载。

## 使用说明

1. **必须在构建JSON前写好**，发给用户确认
2. 角色出场频次用 `execute_code` + `re.findall()` 扫描
3. 模板评估参考 `references/novel-archetype-patterns.md` 和 `references/game-mechanics-template-library.md`
4. 条目架构参考 `references/multi-chapter-novel-to-card.md` 的分层表
5. 预估大小参考 `references/novel-to-card-sizing.md`
6. 规划书保存在小说资源目录下：`规划书_v1.md`
7. 用户确认后再开始构建，避免返工
