# G型多视角卡修复审查经验：绿帽快餐 v1.1

## 触发场景
当用户切换模型后要求“审查之前模型做的角色卡”“参照skill流程看看”，不要延续前一模型自述，也不要默认继续写。必须先独立读取成品、构建脚本、greetings、验证脚本输出，按审查流程给出结论；用户确认修复后再改。

## 核心经验

### 1. validate 通过不等于可交付
必须同时跑：
- `validate_card.py`
- `audit_worldbook_triggers.py`
- `enrichment_self_check.py`
- 自定义残留扫描（旧名/本地化/违禁词/年龄边界/{{user}}泄漏）

若 `enrichment_self_check.py` 出现 `🟡 ≥3`，按本skill红线视为不能交付，即使 validate 是 0 error。先修黄项再交付。

### 2. G型选开 greeting 必须“舞台中性”
G型手动选开模式下，开场白不能绑定齐天/野猪等身份。禁止写：
- “你是哥哥/女友/学生/苦主/征服者”
- “你本该阻止/你站在门口/你刚放学回来”
- 只对某个身份成立的心理反应

正确写法：只给客观场景、NPC位置、证据、冲突压力和可交互选择点。身份由启用的选开条目决定。

### 3. 开场白分段与补字
用户明确反感“一大段文字”。每条 greeting 必须自然分段，每段一个焦点：环境→人物→证据→冲突→选择点。

不要用重复模板补字。validate 会报：
- `同一行重复3次`
- `重复句比例过高（疑似补字灌水）`

字数不足时，用该场景独有的证据、动作、旁人反应、余波段落补足，而不是复制通用段。

### 4. 年龄保持不变时的修复策略
如果用户要求“全部年龄保持不变”，不要擅自成年化。处理方式：
- 保留原年龄字段/表述。
- 未成年角色只承担家庭、误会、证据、偷听、保护、心理冲突、风险边界功能。
- 所有成人向推进必须从这些角色身上移除。
- 在 OOC、角色条目、事件种子、关系矩阵中都显式写入边界。

### 5. 本地化/旧名残留扫描
做日本→华人等本地化时，不能只改展示名。最终必须全卡扫描旧名与旧语境：
`野豚|山犬长丸|山犬|长丸|次郎|日本|大日本|支那|野屠`

扫描范围包括：description、scenario、system_prompt、greetings、entry comment、content、keys、secondary_keys。

### 6. 关系矩阵比散落档案更重要
用户要求“事件、种子、关系等核心加厚”时，不要只加厚角色档案。必须新增/重构 NTR关系矩阵条目，按女性×NTR对象单独写关系锚点：
- 关系起点
- 阶段演变
- 行为链
- 触发关键词
- 双视角差异
- 当前状态/后果

### 7. 核心档案触发可达性
validate/audit 会报“核心角色/威胁档案所有开场白均不触发”。修法不是把所有档案常驻，而是在对应 greeting 中自然提到角色名，或改成按需/手动明确说明。G型开场白仍需保持身份中性。

### 8. 长中文内容 file-first
身份条目、角色条目、事件种子、greeting 都应写入 `build/content/*.txt`，组装脚本只读取文件。不要把长中文 fallback 内联在 assemble 脚本里；fallback 也要保持安全版，避免文件缺失时旧露骨文本复活。

## 最低交付门控
交付前必须确认：
- `validate_card.py`: errors = 0
- `enrichment_self_check.py`: 🔴=0 且 🟡=0
- `audit_worldbook_triggers.py`: 无未解释硬风险
- greeting 全部分段，≥1400中文字，无重复补字段
- 旧名/本地化/违禁残留扫描无命中
- 共用层无非系统性 `{{user}}` 泄漏
