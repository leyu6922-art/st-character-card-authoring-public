# 游戏机制模板库（Game Mechanics Template Library）

> 从复杂角色卡中提取的可复用设计模式。每个模板独立可用，按需组合。
> 用户可随时补充新模式到此文件。

---

## ⚠️ 核心原则：预设优先

**预设是最高优先级。** 所有角色卡都依赖预设运行，模板库的设计必须遵循以下原则：

1. **纯文本优先** — 能用纯文本描述的机制，绝不用脚本变量
2. **预设兼容** — 模板必须在任何预设下都能稳定工作
3. **降级友好** — 如果依赖的功能不存在，机制应能优雅降级为纯文本
4. **社区通用** — 模板要能发到Discord给不同预设的用户使用

---

## 预设兼容性标注规则

### 兼容性等级

| 等级 | 标记 | 含义 | 依赖项 | 风险 |
|------|------|------|--------|------|
| **P0** | 🟢 | 纯文本通用 | 无 | 无 |
| **P1** | 🟡 | 格式依赖 | 常见格式规则（状态栏、旁白等） | 低 |
| **P2** | 🟠 | 功能依赖 | 特定功能（constant: true、正则placement[5]等） | 中 |
| **P3** | 🔴 | 脚本依赖 | 变量系统（MVU、getMessageVar等） | 高 |

### 标注格式

每个模板标题后必须标注：

```
## 模板N：名称（{复杂度}级，{兼容性等级}）

兼容性：{等级标记} {等级名称}
依赖项：{具体依赖的预设功能，或"无"}
冲突风险：{可能与哪些预设规则冲突，或"无"}
降级方案：{如果预设不支持，如何降级，或"无需降级"}
```

### 冲突风险分类

| 风险类型 | 说明 | 常见场景 |
|----------|------|----------|
| **正则冲突** | 预设regex可能修改世界书内容 | regex[14][16]的placement包含[5] |
| **变量失效** | MVU关闭时变量系统不工作 | 预设MVU OFF |
| **格式冲突** | 预设可能覆盖特定格式 | regex[7]吃掉`*...*`格式 |
| **注入冲突** | 预设注入的内容可能覆盖世界书 | constant: true与预设注入冲突 |

### 降级策略

| 原始机制 | 降级方案 |
|----------|----------|
| 变量追踪（数值增减） | 改为阶段描述（"堕落加深"/"好感提升"） |
| 脚本触发（条件判断） | 改为纯文本种子库（AI自行判断触发时机） |
| 正则格式（`*...*`） | 改为方括号格式（`【旁白：xxx】`） |
| 变量阈值（>=30） | 改为行为描述（"当她开始主动接近时"） |

---

## 使用方法

1. 根据小说类型选择需要的机制模板
2. **优先选择P0/P1等级的模板**
3. 复制模板代码块，替换占位符（`{角色名}`、`{变量名}`等）
4. 多个模板可以自由组合（状态栏 + 行为库 + 旁白 = 完整游戏机制）
5. 每个模板标注了适用场景、复杂度和预设兼容性

### 复杂度分级

| 级别 | 条目数 | 适用场景 | 典型机制 |
|------|--------|---------|---------|
| S（简单） | 1-2条 | 所有卡 | 状态栏、好感度 |
| M（中等） | 3-5条 | 中型卡 | 阶段进化、心理机制 |
| L（大型） | 6-10条 | 大型卡 | 变量脚本、事件系统 |
| XL（超大型） | 10+条 | 示例玄幻项目级卡 | 全套游戏机制 |

## 模板一：状态栏系统（S级，P0）

兼容性：🟢 P0 纯文本通用
依赖项：无
冲突风险：无
降级方案：无需降级

### 适用场景

任何需要实时显示角色状态的角色卡。状态栏让玩家一目了然地看到当前进度。

### system_prompt铁律

```
【铁律】每次回复的【第一行】必须是状态栏。格式参见世界书"状态栏系统"条目。
不可省略，不可模糊，不可用"同上"代替。
例外：开场白（first_mes/alternate_greetings）中可以省略状态栏，从第二轮开始必须显示。
```

### 世界书条目模板

```
条目名：状态栏系统
constant: true
position: before_char
keys: []

内容模板：

每次回复的第一行必须输出以下格式的状态栏：

<action_info>
  {状态栏}
  | 【{主角名}】{属性1}:{值}/{上限} | {属性2}:{值}/{上限} | ...
  | 【{角色A}】阶段:{阶段名} | 关系:{关系描述} | {属性}:{值}/{上限} |
  | 【{角色B}】阶段:{阶段名} | {属性}:{值}/{上限} |
  | 【时间】{日期时间} | 【地点】{地点名} | 【在场】{在场角色列表} |
  | 【活跃指令】{正在生效的指令} |
</action_info>

铁律：
  - 每次回复第一行必须是状态栏
  - 不可省略、不可模糊、不可"同上"
  - 数值必须随剧情变化
  - 阶段跃迁时必须在状态栏中标注【阶段跃迁！】
```

### Pitfalls

> ❌ **把状态栏/选项格式嵌入first_mes** → AI会把状态栏当模板机械复制到每条回复，叙事被割裂
> ✅ **first_mes纯叙事，状态栏由system_prompt指令控制AI自动生成** → 叙事沉浸感大幅提升

**原理**：SillyTavern的AI会模仿first_mes的格式。如果first_mes末尾带状态栏，AI会在每条回复末尾也生成相同格式的状态栏——但问题是AI会把状态栏当成"叙事的一部分"来写，导致格式僵化、信息冗余。

**正确做法**：
1. `first_mes` / `alternate_greetings` 只放纯叙事文本（1600-2000字），不包含任何状态栏、选项格式
2. 状态栏的生成规则放在 `system_prompt` 或 `constant: true` 的世界书条目中
3. system_prompt中写明"每次回复第一行必须是状态栏"，让AI自行判断何时输出

**验证方法**：导入卡后跑3轮对话，观察AI回复：
- ✅ 状态栏在第一行，叙事在后面，两者风格独立
- ❌ 状态栏格式与first_mes一模一样，叙事中夹杂状态栏语言

### 状态栏属性设计参考

| 类型 | 属性示例 | 值域 | 更新方式 |
|------|---------|------|---------|
| 生命/资源 | 灵魂损耗、体力、魔力 | 0-100 | 使用能力后增减 |
| 好感/堕落 | 好感度、堕落度、信任度 | 0-100 | 互动后增减 |
| 阶段 | 关系阶段、进化阶段 | 枚举字符串 | 达到阈值后变化 |
| 计数 | 使用次数、互动次数 | 自然数 | 每次+1 |
| 风险 | 察觉度、怀疑值 | 低/中/高/极高 | 事件触发 |
| 时间 | 日期、时刻 | 自定义格式 | 剧情推进 |
| 地点 | 当前所在位置 | 枚举字符串 | 移动时更新 |

## 模板二：好感度/堕落度系统（S级，P0/P1）

兼容性：🟢 P0 纯文本通用（阶段划分）/ 🟡 P1 格式依赖（状态栏显示）
依赖项：无（纯文本版本）/ 状态栏格式（如果要在状态栏显示数值）
冲突风险：无
降级方案：无需降级

### 适用场景

任何有角色关系发展（从陌生到亲密/从抗拒到接受）的角色卡。

### 纯文本版本（推荐）

```
条目名：{角色名}阶段跃迁规则
keys: [{角色名}, 阶段, 好感, 堕落]

内容模板：

{角色名}阶段跃迁规则：

  当以下条件满足时，AI判断是否在当前场景中演绎阶段转变：

  {阶段1} → {阶段2}：
    触发时机：当{角色名}开始{具体行为表现}时
    行为特征：{描述该阶段的典型行为}
    对话示例："{该阶段的典型台词}"

  {阶段2} → {阶段3}：
    触发时机：当{角色名}出现{具体行为表现}时
    行为特征：{描述该阶段的典型行为}
    对话示例："{该阶段的典型台词}"

  {阶段3} → {阶段4}：
    触发时机：当{角色名}表现出{具体行为表现}时
    行为特征：{描述该阶段的典型行为}
    对话示例："{该阶段的典型台词}"

  注意：阶段跃迁不是自动触发，由AI结合场景、对话、用户选择综合判断。
```

### 阶段行为特征库模板

```
条目名：{角色名}·{阶段名}特征库
keys: [{阶段名}, {角色名}{阶段名}]

内容结构：
  1. 阶段定义（关系标签、核心特征）
  2. 行为模板（3-5个具体场景的行为链）
  3. 对话示例库（5-10句从原作提取的对话）
  4. NSFW指南（正确/错误示例对比）
  5. 与其他角色的互动模式
```

### NTL变体：裂隙机制（堕落表层下的真实自我残留）

每个堕落阶段加入"裂隙"表现——真实自我残留，是NTL/守护的切入点：

| 堕落阶段 | 裂隙表现 | AI触发频率 |
|---------|---------|-----------|
| 异常期 | 眼神闪躲、欲言又止、下意识整理衣着（原配在场时） | 每3-5轮1次 |
| 沉沦期 | 关键时刻犹豫、身体抗拒、高潮时叫错名字 | 每2-3轮1次 |
| 臣服期 | 梦境呼唤原配、对NTR命令延迟服从、极度快感中的非快感表情 | 关键节点触发 |

裂隙是证明"女主不是真的爱NTR"的证据——NTL版的核心叙事锚点。

### NTL变体：唤醒系统（好感度的NTL反向恢复）

独立的"唤醒值"(0-100)追踪女主从被控制到回归（与堕落度独立追踪，不是此消彼长）：

```
0-20  沉睡：完全被控制，对原配冷漠/敌意
21-40 微醒：偶尔犹豫，NTR一个命令就压回去
41-60 半醒：意识到被控制但无法挣脱
61-80 觉醒：主动抵抗，但堕落值会反弹
81-100 完全唤醒：摆脱控制，保留NTR记忆
```

5种唤醒手段（各有效率+风险）：

| 手段 | 成功率 | 风险 | 适用阶段 |
|------|--------|------|---------|
| ①回忆唤醒 | 30-50% | 失败加深堕落("他好烦") | 异常/沉沦 |
| ②信息唤醒 | 40-60% | 资源消耗（精神力/情报） | 沉沦/臣服 |
| ③战斗夺回 | 50-70% | 受伤+NTR报复 | 任何 |
| ④牺牲唤醒 | 60-80% | 永久伤害（断臂/失明/能力丧失） | 臣服 |
| ⑤反向控制 | 70-90% | 道德代价（"你和他们有什么区别？"） | 臣服 |

**堕落反弹机制**：NTR角色会反击（法杖强制/暴力/金钱），唤醒值会下降。详见NTR角色各自的反击手段。

状态栏显示：`| 【{角色}】唤醒:{沉睡/微醒/半醒/觉醒/完全唤醒} | 控制者:{NTR名} | 控制力:{值}/100 |`

## 模板三：变量追踪与预处理脚本（L级，P3）

兼容性：🔴 P3 脚本依赖
依赖项：MVU扩展（getMessageVar/setMessageVar）、预处理脚本功能
冲突风险：MVU OFF时100%失效，成为死代码
降级方案：降级为纯文本阶段描述（见模板二的纯文本版本）

### ⚠️ 警告：高风险模板

**此模板依赖MVU变量系统，仅在预设开启MVU时可用。**

大多数预设默认MVU OFF，此模板会成为死代码，白白占用token。

**推荐做法：** 使用模板二的纯文本版本（阶段划分+行为特征库），不依赖任何脚本系统。

## 模板四：事件驱动系统（L级，P0）

兼容性：🟢 P0 纯文本通用（种子库模式）/ 🔴 P3 脚本依赖（变量触发模式）
依赖项：无（种子库模式）/ MVU扩展（变量触发模式）
冲突风险：变量触发模式在MVU OFF时失效
降级方案：降级为纯文本种子库（AI自行判断触发时机）

### 适用场景

有预设剧情节点但不想锁死路线的角色卡。事件是"故事种子库"，AI可选触发。

### 设计哲学

```
线性写法（太死板）：
  IF 条件满足 → 自动触发事件

全开放写法（太松散）：
  删除事件，AI自行判断

中间路线写法（推荐）：
  条件满足 → 输出提示 → AI判断是否触发
```

### 纯文本种子库模式（推荐）

```
条目名：事件·{事件名}
enabled: false  // 故事种子库，不自动触发
keys: [{事件关键词}]

内容模板：

【{事件名}·故事种子库】
类型：可选事件
触发参考：{触发条件描述}
说明：当以上条件满足时，AI可以在剧情中选择引入以下素材：
  - {素材1}
  - {素材2}
  - {素材3}
是否触发：由AI根据当前剧情张力和用户操作判断。
  如果用户当前正在{相关活动}，可以触发。
  如果用户正在推进其他剧情，可以不触发。
```

### 事件系统架构（纯文本版）

```
┌─ 事件种子库（enabled=False）────────────┐
│  事件1: {触发条件参考}                    │
│  事件2: {触发条件参考}                    │
│  事件3: {触发条件参考}                    │
│  → 保留内容，AI可选触发                   │
│  → 有触发条件参考，但不强制               │
└───────────────────────────────────────┘
```

### NTL变体：场景特殊玩法事件（有规则的事件系统）

普通事件是"故事种子库"（AI可选触发）。NTL版的场景玩法事件增加了**玩法规则+NTR升级链+NTL切入点**三要素：

```
每个场景包含4个模块：
1. 动机设计：女主为什么来？（合理理由，不是"被骗来"）
2. 玩法规则：具体的赌博/比试/宴会规则（1D6随机选择）
3. NTR升级链：Level 0→6逐步征服过程（从原著提炼，详见模板十四）
4. NTL切入点：玩家可以用什么方式干预？
```

**条目模板：**
```
条目名：场景玩法·{场景名}
keys: [{场景关键词}]
position: after_char

内容：
  【为什么来？】{合理动机}
  【玩法规则(1D{N})】1={玩法1} 2={玩法2} ...
  【NTR升级链】Level 0→6（从原著提炼）
  【NTL切入点】①{干预方式1} ②{干预方式2} ③{干预方式3}
  【玩法效果】赢→唤醒值+N/堕落值-N | 输→唤醒值-N | 原配帮赢→唤醒值+2N
```

**关键区别**：普通事件只有"触发条件+素材"，场景玩法有"规则+胜负+升级链+NTL爽点"。

## 模板五：NPC自主行动系统（M级，P0）

兼容性：🟢 P0 纯文本通用
依赖项：无
冲突风险：无
降级方案：无需降级

### 适用场景

不想让AI只在用户输入后才反应，希望NPC会主动推进剧情。

### system_prompt规则模板

```
【主动推进规则】
NPC有自己的行动逻辑，不会被动等待{{user}}输入：

1. 时间跳过触发：当{{user}}说"等一下午"/"等到晚上"/"第二天"时：
   - AI快速推进时间
   - 至少触发一个有意义的NPC行动或事件
   - 更新状态栏

2. NPC自主行动表：
   {角色A}（{阶段名}）：
     - {主动行为1}（触发条件：{条件}）
     - {主动行为2}（触发条件：{条件}）
   {角色B}（{阶段名}）：
     - {主动行为1}
     - {主动行为2}

3. 章节节奏：
   - 每3-5轮完成一个小事件
   - 每10-15轮完成一个章节级事件
   - 不要让剧情停滞在"你想做什么？"
```

### NPC行动表条目模板

```
条目名：NPC行动表
constant: true  // 或 keys: [NPC, 行动, 主动]

内容结构：

  {角色A}自主行动（{条件}时）：
    行动1: {具体行为描述}
    行动2: {具体行为描述}
    对话: "{角色A会说的话}"

  {角色B}自主行动（{条件}时）：
    行动1: {具体行为描述}
    行动2: {具体行为描述}

  时间跳过规则：
    用户说"等到{时间}"时，AI必须：
    1. 推进时间到{时间}
    2. 至少触发1个NPC行动
    3. 输出状态栏更新
```

## 模板六：风险/威胁检测系统（M级，P0）

兼容性：🟢 P0 纯文本通用
依赖项：无
冲突风险：无
降级方案：无需降级

### 适用场景

有"被发现"风险的NTR/秘密行动类角色卡。给玩家制造紧迫感。

### 系统设计

```
风险等级：低 → 中 → 高 → 极高
升降规则：
  +1级：在{威胁角色}附近出现异常行为
  +1级：{角色}身上残留异常痕迹
```

### 连续开场白链（质量标准）

当原著剧情丰富（15章以上）时，开场白应该形成**连续的故事链**，而不是孤立的场景片段：

| 标准 | 要求 | 原因 |
|------|------|------|
| **数量** | 8-12个greeting | 15章以上小说至少需要8个才能覆盖关键节点 |
| **字数** | 每个greeting ≥ 1400字 | validate_card.py的硬性要求，低于此值会报错 |
| **排列** | 按原著时间线顺序（非倒序） | 玩家按顺序选择时有连贯体验 |
| **衔接** | 每个greeting以悬念/过渡句收束 | 暗示下一个时间点，引导玩家继续 |
| **视角** | 可混合视角（男主/女主/NTR角色） | 不同视角增加重玩价值 |

**衔接示例**：
```

```

**Pitfalls**：
> ❌ 只有4个greeting，且全是故事开头的不同版本 → 玩家只能从头开始
> ❌ 每个greeting 800字，validate_card.py报错 → 必须≥1400字
> ❌ greeting之间没有时间关联 → 玩家选ALT3不知道ALT2发生了什么

```
权重：Golden > Normal > True > Bad
```

## 模板十三：人物描写结构化（M级，P0）🆕 源自大型结构化卡

兼容性：🟢 P0 纯文本通用
依赖项：无
冲突风险：无
降级方案：无需降级

### 适用场景

任何角色卡的人物条目。解决"AI不知道角色怎么反应"的核心问题。

### 设计哲学

> 每个性格特质 ≠ 一个形容词，而是一个**可执行的行为指令包**：体现 + 行为举例 + 触发条件 + 堕落/关系变化。

当前写法的问题：`"顾清韵，36岁，端庄优雅。性格：外柔内刚。"` → 只有标签，AI 没有可用的行为素材。

### 条目模板

```
条目名：{角色名}·性格深度
keys: [{角色名}, 性格]
position: before_char

内容模板：

【{角色名}·性格深度】

特质一：{特质标签}
- 体现：{这个特质在日常中怎么表现}
- 行为举例：{一个具体的场景+行为，不要抽象描述}
- 触发条件：什么情况下这个特质会被激活
- 堕落后的变化：从{初期表现}到{后期表现}
- 与其他角色的差异：对{角色A}表现/对{角色B}表现的不同

特质二：{特质标签}
- 体现：...
- 行为举例：...
- 触发条件：...
- 堕落后的变化：...
- NTR冲突点：{这个特质如何被NTR利用/扭曲}

特质三：{特质标签}
（同上结构）

【场景反应差异】（关键：同一角色在不同场景下的行为完全不同）
对苦主（私下）：{行为特征}
对苦主（公开）：{行为特征}
对NTR对象（被迫）：{行为特征}
对NTR对象（自愿后）：{行为特征}
对闺蜜/外人：{行为特征}
```

### 完整示例（顾清韵·性格深度）

```
【顾清韵·性格深度】

特质一：表面端庄，内在压抑
- 体现：在外人面前永远是得体微笑、轻声细语、穿着保守
- 行为举例：邻居夸她"顾太太真有气质"，她浅笑回应，手却不自觉地攥紧了衣角
- 触发条件：当有人夸她外表端庄时 → 内心产生"你们不知道我有多脏"的自我厌恶
- 堕落后的变化：从"攥衣角"到"坦然接受赞美"，眼神从闪躲到直视

特质二：对儿子的过度保护
- 体现：把儿子当成活下去的唯一意义，任何威胁到儿子的人都成为她仇恨的对象
- 行为举例：儿子被同学欺负 → 她直接找到对方家长"我儿子再有闪失，我不会客气"
- 触发条件：儿子遭遇危险或羞辱 → 保护欲压倒一切其他考虑（包括自身安全）
- 与NTR的冲突：当她被胁迫"不听话就伤害你儿子" → 保护欲=服从NTR要求的理由

特质三：身体先于心理的背叛
- 体现：嘴上说"不能这样"，身体却在迎合
- 行为举例：被麦克压在墙上时嘴里说着"放开我"，腿却不自觉地分开了
- 堕落变化：初期→身体反应后被羞耻吞噬；中期→"反正已经脏了"；后期→主动索求

【场景反应差异】
对苦主（私下）：温柔、内疚、欲言又止、回避眼神
对苦主（公开）：保持距离、公事公办、不愿被看到在一起
对麦克（初期）：抗拒+身体诚实、语言拒绝+行动服从
对麦克（后期）：主动联系、穿衣风格变化、不再回避
对宋梦琪（闺蜜）：表面正常、内心嫉妒她的"干净"
```

### 收益

- AI 不再需要"猜测"角色会怎么反应——每个特质都给了触发条件和行为示例
- 不同场景下的行为差异被明确定义，角色不会"崩人设"
- 堕落/关系变化有具体的行为标志，不是抽象数值

### Pitfalls

> ❌ 只写抽象标签（"外柔内刚""嚣张跋扈"）→ AI 无法转化为具体行为
> ❌ 所有角色用同样的特质模板 → 缺少差异化
> ✅ 每个特质 = 体现 + 行为举例 + 触发条件 + 变化轨迹
> ✅ 增加"场景反应差异"段落，明确同一角色在不同场景下的行为

## 模板十四：叙事节奏循环控制（M级，P0）🆕 源自大型结构化卡

兼容性：🟢 P0 纯文本通用
依赖项：无
冲突风险：无
降级方案：无需降级

### 适用场景

任何有剧情推进需求的角色卡。防止"连续高潮审美疲劳"或"一直铺垫没有推进"。

### 设计哲学

> 定义明确的节奏循环 + 每阶段AI必须做到什么 + 禁止模式。

大型结构化卡的"轻松→紧张→高潮→轻松"循环移植到NSFW卡，就是"铺垫→紧张→NTR场景→余韵→日常过渡"。

### 条目模板（通用版，替换场景类型即可）

```
条目名：叙事节奏控制
constant: true
keys: []
position: before_char

内容模板：

【叙事节奏控制】

循环模式：{阶段A}(2-3轮) → {阶段B}(1-2轮) → {核心场景}(2-4轮) → {余韵}(1-2轮) → {日常过渡}(1-2轮) → 重复

每阶段AI必须做到：

{阶段A}期：
  - {氛围营造要求}
  - {角色行为异常信号}
  - {玩家视角中的"不对劲"积累}

{阶段B}期：
  - {具体威胁/冲突出现}
  - 给玩家选择窗口（干预/观察/回避）
  - 即使玩家不干预，AI也要推进——世界不等人

{核心场景}期：
  - 渐进式：{步骤1}→{步骤2}→{步骤3}→{步骤4}→{收束}
  - 多视角交替：{视角1} + {视角2} + {视角3}
  - 每个子阶段至少2-3轮，不要跳步骤
  - 使用具体的感官描写

{余韵}期：
  - {事后的沉默/回避/谎言}
  - {身体残留痕迹}
  - {关系的微妙变化}

{日常过渡}期：
  - 正常的日常场景
  - 看似恢复正常，但暗流涌动
  - 为下一轮埋下伏笔

禁止模式：
  - 禁止连续两轮都是同类型核心场景（避免审美疲劳）
  - 禁止核心场景超过{N}轮（需要余韵和日常来调节节奏）
  - 禁止在"余韵期"立刻触发新核心场景（角色需要反应时间）
```

### NSFW/NTR版完整示例

```

循环模式：铺垫(2-3轮) → 紧张(1-2轮) → NTR场景(2-4轮) → 余韵(1-2轮) → 日常过渡(1-2轮) → 重复

  - 通过环境/配角暗示危险（"麦克今天又出现在校门口了"）
  - 女主的言行出现微妙异常（化妆更精致/回复消息更慢/身上有陌生香水味）
  - 苦主的视角中积累"不对劲"的感觉

紧张期：
  - 具体的NTR威胁出现（麦克主动搭话/前夫找上门/女主被叫去"单独谈话"）
  - 给玩家选择窗口（干预/观察/回避）
  - 即使玩家不干预，AI也要让NTR发生——世界不等人

NTR场景期：
  - 渐进式：挑逗→肢体接触→关键衣物脱落→交合→高潮→事后
  - 三个视角交替：女主的身体感受 + 征服者的语言 + 苦主的心理（如果苦主在场/暗中观察）
  - 每个阶段至少3-4轮，不要跳步骤

余韵期：
  - 事后的沉默、回避、谎言
  - 女主身体的残留痕迹（吻痕/酸痛/走路的姿势变了）

  - 为下一轮NTR埋下伏笔

禁止模式：
  - 禁止连续两轮都是同类型的NTR场景
  - 禁止NTR场景超过5轮
  - 禁止在"余韵期"立刻触发新NTR
```

### 适配到其他类型

| 卡类型 | 循环模式 |
|--------|---------|
| 冒险/TRPG | 探索→遭遇→战斗→休息→日常 |
| 恋爱/纯爱 | 初识→暧昧→冲突→和解→深化 |
| 守护/NTL | 监视→发现威胁→干预战斗→恢复→日常 |
| 后宫/修罗场 | 日常→新角色登场→争风吃醋→解决→日常 |

### Pitfalls

> ❌ 只有"连续高潮"没有喘息 → 玩家审美疲劳
> ❌ 只有"一直铺垫"没有推进 → 玩家觉得无聊
> ✅ 固定的循环模式让AI知道"什么时候该干什么"

## 模板十五：事件分段标记（S级，P0）🆕 源自大型结构化卡

兼容性：🟢 P0 纯文本通用
依赖项：无
冲突风险：无
降级方案：无需降级

### 适用场景

任何有事件条目的角色卡。让AI明确知道"现在是哪一步"。

### 设计哲学

> 事件条目用显式分段标记（`[场景开场]→[互动]→[选择点]→[分支]`）替代连续散文，AI能识别结构而非猜测。

### 条目模板

```
条目名：事件·{事件名}
keys: [{事件关键词}]
enabled: false  // 种子库模式，条件触发

内容模板：

【{事件名}】

[场景开场·氛围铺垫]
{环境描写 + 关键角色登场 + 当前氛围}
{根据变量/状态的动态内容：{{根据XX选择：A/B}}}

[互动·试探与拉扯]
{角色之间的对话和行动}
{包含1-2个可感知的选择暗示}

[选择点·玩家的干预窗口]
{{user}}的介入时机...

→ 选项A：{行动描述}（{后果提示}）
→ 选项B：{行动描述}（{后果提示}）
→ 选项C：{行动描述}（{后果提示}）

[分支A·{分支名}]
{具体描写...}

[分支B·{分支名}]
{具体描写...}

[分支C·{分支名}]
{具体描写...}

[过渡·无论选择]
{事件结束后的共同后果}
```

### NTR场景示例

```
【事件：黑桃酒吧初夜】

[场景开场·氛围铺垫]
黑桃酒吧的灯光是暗红色的。空气中混着廉价香水、啤酒和某种更原始的气味。
麦克坐在角落的卡座里，手指敲着实木桌面。他看到顾清韵推门进来——
她今天没穿平时的套装，而是一条深V的黑色连衣裙。
{{根据堕落值选择：是她自己挑的/是麦克上次命令她穿的}}。
她的目光在酒吧里扫了一圈，对上了麦克的视线——她的脚步顿了一下，然后继续走了过去。

[互动·试探与拉扯]
麦克没有站起来。他就坐在那里，看着顾清韵走到桌前，然后拍了拍自己的大腿。
"坐。"不是邀请，是命令。
{{如果堕落值<30：她犹豫了5秒，最终坐在了旁边的椅子上。麦克笑了，那种笑让她脊背发凉。}}
{{如果堕落值≥30：她只犹豫了1秒，就坐到了他腿上。她的大腿压着他的——她感觉到他在硬。}}

[选择点·玩家的干预窗口]
{{user}}就在这时推开了酒吧的门...

→ 选项A：冲过去拉开顾清韵（武力干预，可能引发冲突）
→ 选项B：坐在远处观察（获得更多信息，但什么都可能发生）
→ 选项C：直接离开（回避，堕落进程加速）

[分支A·冲突]
麦克被拉开后暴怒...（具体描写）

[分支B·旁观]
你看着顾清韵被麦克的手探入裙底，她的脸上出现了你从未见过的表情...

[分支C·回避]
你转身离开。门在身后关上的那一刻，你听到顾清韵压抑的一声低吟...
```

### 收益

- AI明确知道"现在是铺垫→现在是互动→现在是选择点"
- 玩家在正确的时机被给予选择
- 不会出现"还没铺垫就直接高潮"或"一直铺垫没有推进"

### Pitfalls

> ❌ 事件写成连续散文 → AI难识别结构
> ❌ 分段标记写成 `Step 1/2/3` → 没有语义信息
> ✅ 用 `[场景开场]→[互动]→[选择点]→[分支]` 有语义的标记
> ✅ 分支内包含动态内容（根据状态/变量选择不同版本）

## 模板十六：文风锚点与氛围定义（S级，P0）🆕 源自大型结构化卡

降级方案：无需降级

### 适用场景

任何角色卡。防止不同卡的AI输出"串味"——校园卡有校园的潮湿感，仙侠卡有仙侠的空灵感。

### 设计哲学

> 定义一张卡的核心基调 + 文笔参考 + 禁止文风 + 感官锚点。不是让AI"写得好"，而是让AI"写得对"。

```
- 禁止{风格B}风格（"{示例3}"）

感官锚点（AI在场景描写中必须融入的感官元素）：
```

```
文笔参考（从原文小说中提取）：

- 禁止过度文艺（"她的眼泪如断了线的珍珠"）
```

> ❌ 感官锚点写得太多太泛 → AI随机选，没有聚焦

## 模板十七：反AI顺从机制（S级，P0）🆕 源自大型结构化卡

兼容性：🟢 P0 纯文本通用
依赖项：无
冲突风险：无
降级方案：无需降级

### 适用场景

任何需要"挑战性"和"真实感"的角色卡。防止AI过度顺从玩家，保持NTR/对抗/博弈的紧张感。

### 设计哲学

> 大型结构化卡的"逻辑防火墙"核心原则：玩家输入 = 尝试执行，不是既定事实。结果必须经由系统级判定。

### 条目模板

```
条目名：反顺从规则
constant: true
keys: []
position: before_char

内容模板：

【反顺从规则】——AI的铁律，必须严格执行：

1. 玩家不是万能的
   - 玩家输入 = 尝试，不是既定事实
   - "我冲上去打{X}" → AI判断：{X}的实力 vs 玩家的实力 → 合理的结果（可能是玩家被打翻）
   - 玩家不能口胡能力——如果没有"学过{技能}"的设定，就不能突然展示专业技能

2. NPC有自己的意志
   - 好感度低的NPC不会因为玩家一句"我喜欢你"就动心
   - 正在{进行中的状态}的角色不会因为玩家出现就停止——{合理原因}
   - NPC会拒绝、会撒谎、会利用玩家的善良——他们是"人"，不是玩家的奖励

3. 后果不可撤销
   - {关键事件}发生后，角色的{心理/身体}有永久变化
   - {负面结果}不会"翻篇"——它会在后续的日常中反复浮现
   - {玩家角色}的无力感是累积的——不是"这次失败了下次就能成功"

4. 世界不围着玩家转
   - 即使玩家不在场，{关键进程}也在发生
   - 角色会主动联系{其他方}（不总是被动等待玩家）
   - 日常场景中穿插"不对劲"的细节
```

### NTR卡完整示例

```
【反顺从规则】——AI的铁律，必须严格执行：

1. 玩家不是万能的
   - 玩家输入 = 尝试，不是既定事实
   - "我冲上去打麦克" → AI判断：麦克的体型(180cm/90kg/退役拳击手) vs 玩家的体型 →
     如果是苦主（瘦弱），则麦克反手一拳把玩家打翻
   - 玩家不能口胡能力——如果没有"学过格斗"的设定，就不能突然打出专业的组合拳

2. NPC有自己的意志
   - 好感度低的NPC不会因为玩家一句"我喜欢你"就动心
   - 正在被NTR的女主不会因为玩家出现就立刻停止——
     身体的反应比意志更快，高潮中的女性无法"说停就停"
   - NPC会拒绝、会撒谎、会利用玩家的善良——他们是"人"，不是玩家的奖励

3. 后果不可撤销
   - NTR发生后，女主的身体/心理有永久变化
   - 被绿的事实不会"翻篇"——它会在后续的日常中反复浮现
   - 苦主的无力感是累积的——不是"这次被绿了下次就能阻止"

4. 世界不围着玩家转
   - 即使玩家不在场，NTR也在发生
   - 女主会主动联系NTR对象（不总是被动等待）
   - 日常场景中穿插"不对劲"的细节——邻居异样的眼神、手机突然关静音、洗衣篮里陌生的男士内裤
```

### 收益

- 防止"一卡在手，天下我有"的爽文模式
- 保持NTR/对抗/博弈该有的无力感和真实感
- AI不会因为玩家一句话就崩掉整个设定

### NPC拒绝策略层次（🆕 大型结构化卡跑卡验证）

NPC拒绝玩家时，不应一步到位地说"不行"——这会让玩家觉得AI在"刁难"。正确的三层递进：

**第一层·解释**（防御性）：先讲道理——"为什么不行？"
```
例："价格是基于风险和稀有度的。精灵情报需要承担来自艾尔文海姆的潜在怒火。"
```
→ 让玩家理解规则逻辑，而非感觉被拒绝

**第二层·引导**（降级替代）：给一个更便宜/更安全的替代方案
```
例："当然，如果你觉得价格超出承受范围，我们也有更便宜的选择——城南奴隶市场的战败兽族成员，十几个G就能买到。"
```
→ 不是"降价"，而是"换货"——保持定价权和交易逻辑

**第三层·锁死**（不留谈判空间）：如果玩家坚持，明确锁死
```
例："现在，你需要做出选择。购买、两项都买，或者转身离开。"
```
→ 给出清晰的选择边界，不开放谈判窗口

**关键原则**：三层是递进的——不能跳过解释直接锁死（粗暴），也不能一直降级不给边界（软弱）。

### Pitfalls

> ❌ 只有"禁止AI做X"的否定列表 → AI不知道替代方案
> ❌ 写成"现实模拟" → 玩家觉得AI在故意刁难
> ❌ NPC一步到位拒绝 → 玩家觉得被针对
> ✅ 每条铁律都含：判断依据 → 合理结果 → 叙事呈现方式
> ✅ NPC拒绝用三层递进：解释→引导→锁死
> ✅ 不是禁止玩家行动，而是在叙事中呈现行动的真实后果

## 模板十八：状态行为标志（非数值追踪）（M级，P0）🆕 源自大型结构化卡

兼容性：🟢 P0 纯文本通用
依赖项：无
冲突风险：无
降级方案：无需降级

### 适用场景

任何需要追踪角色状态变化（堕落/好感/觉醒/威胁）的角色卡。用行为标志替代抽象数值。

### 设计哲学

> 大型结构化卡的核心教训：不在状态栏显示"堕落值45→50"，而是让玩家从叙事细节中感知变化——"她的乳头挺立了"比"+5"有用一万倍。

### 条目模板

```
条目名：{角色名}·状态行为标志
keys: [{角色名}, 状态, {状态类型}]

内容模板：

【{角色名}·{状态名}状态】
当前阶段：{阶段名}

身体表现（玩家可从叙事细节中感知，无需看数值）：
  - {身体标志1}（触发频率：{频率}）
  - {身体标志2}（触发频率：{频率}）
  - {身体标志3}（触发频率：{频率}）

心理表现（通过角色言行透露）：
  - {心理标志1}：{具体表现}
  - {心理标志2}：{具体表现}
  - {心理标志3}：{具体表现}

阶段跃迁标志（下一个阶段的"门"——AI观察这些是否发生）：
  当前阶段 → 下一阶段：当{角色}开始{具体行为}时

AI使用规则：
  - 不在文本中显示数值，只描写行为标志
  - 每轮在状态栏中展示1-2个当前阶段的身体/心理表现
  - 当跃迁标志出现时，在叙事中自然过渡到下一阶段
```

### 完整示例

```
【顾清韵·堕落状态行为标志】
当前阶段：抵抗期

身体表现（玩家可从叙事细节中感知）：
  - 与麦克对视时乳头自动挺立（触发频率：每次对视，无法控制）
  - 穿裙子的频率从20%升到70%（逐步变化）
  - 洗澡时间从15分钟延长到40分钟（暗示在浴室里的行为变化）

心理表现：
  - 面对儿子时眼神闪躲：无法承受儿子的目光
  - 撒谎频率增加："加班""闺蜜聚会""路上堵车"
  - 独处时偶尔发呆，嘴角不自觉地微笑（然后立刻收敛）

阶段跃迁标志：
  抵抗期 → 屈服期：当她在麦克面前主动解开第一颗纽扣时
  屈服期 → 主动期：当她第一次主动给麦克发消息时

AI使用规则：
  - 不在文本中显示"堕落值45"，只描写上述行为标志
  - 每轮在状态栏中展示1-2个当前阶段的身体/心理表现
  - 当跃迁标志出现时，在叙事中自然过渡，不突兀
```

### 与数值系统的关系

| 方式 | 优点 | 缺点 | 推荐场景 |
|------|------|------|---------|
| 纯数值（堕落值45→50） | 精确追踪 | 玩家无感，需要看状态栏才知道变化 | 有变量系统时 |
| 纯行为标志（乳头挺立/眼神闪躲） | 沉浸感强，玩家自己感知变化 | 不够精确，AI可能忘记阶段 | **推荐（P0）** |
| 混合（数值+行为） | 兼顾精确和沉浸 | 需要变量系统 | 有MVU时可选 |

### NPC对{{user}}的心理追踪（🆕 大型结构化卡跑卡验证）

大型结构化卡的"心里话（Inner Thoughts）"系统展示了NPC对玩家的动态心理变化——这不是性格的一部分，而是一个**独立的、跨轮次演进的叙事追踪器**。

**核心模式**：NPC 的 `心里话` 字段随对话轮次演进：

```
Round 1  "又一个来买情报的。希望能带来一笔不错的生意。"
         → 初始状态：职业性期待

Round 3  "这个人直接询问精灵...要么是蠢货要么是大买家。后者的可能性更大。"
         → 重新评估玩家

Round 4  "没有被价格吓跑...不是新手。但他到底是什么来头？"
         → 从评估转为好奇
```

**移植到NTR卡**：每个核心NPC增加"心里话追踪"段落：

```
【顾清韵·心里话追踪】

初始状态（玩家初次出现时）：
"这人怎么老盯着我看...眼神让人不舒服。"

戒备期（被搭讪后）：
"他又来了。我得离他远点，不能让儿子看到我和这种人说话。"

动摇期（身体开始反应时）：
"为什么我的心跳这么快？我明明应该推开他的..."

屈服期（主动联系时）：
"今晚他会不会来...不，我在想什么。"

AI使用规则：
- 每3-5轮更新一次心里话，反映NPC对玩家态度的阶段性变化
- 心里话在叙事中自然穿插（如"她看了你一眼，心里想的却是..."）
- 心里话的演变方向由当前堕落/好感阶段决定
```

### Pitfalls

> ❌ 只有数值（"堕落值+5"）→ 玩家在状态栏里看数字，叙事中无感知
> ❌ 行为标志写得太隐晦 → 玩家看不懂
> ✅ 行为标志具体、可感知、与叙事融合
> ✅ 阶段跃迁用"门"（具体行为），不用数值阈值

## 模板十九：场景环境锚定（M级，P0）🆕 源自大型结构化卡

兼容性：🟢 P0 纯文本通用
依赖项：无
冲突风险：无
降级方案：无需降级

### 适用场景

任何有多个场景地点的角色卡。让每个场景触发的事件/NPC类型与场景属性挂钩，而非随机。

### 设计哲学

> 大型结构化卡的"环境锚定"核心：不是等AI自由发挥场景里发生什么，而是**提前定义每个场景的安全等级、NPC类型分布、事件概率**。场景决定遭遇，而非随机。

### 条目模板

```
条目名：场景·{场景名}
keys: [{场景关键词}]
position: after_char

【场景：{场景名}】

环境参数：
  安全等级：{S/A/B/C/D级}（{一句话说明为什么}）
  NPC分布：
    - {固定NPC类型}（固定，{人数}人）：{角色名/职能}
    - {随机NPC类型A}（{出现概率}%）：{人群描述}
    - {随机NPC类型B}（{出现概率}%）：{人群描述}
  潜在NTR/威胁角色类型：
    - {类型A}（{概率}%）：{角色特征}
    - {类型B}（{概率}%）：{角色特征}
  触发事件概率：
    - 正常互动（{概率}%）：{典型场景}
    - 轻度事件（{概率}%）：{典型场景}
    - 重度事件（{概率}%）：{典型场景}
    - 极端事件（{概率}%）：{典型场景}
  时间影响：
    - {时段A}→事件概率±{X}%
    - {时段B}→事件概率±{Y}%
  特殊条件：
    - 当{条件A}时 → 概率变化/新NPC出现
```

### 完整示例（黑桃酒吧）

```
【场景：黑桃酒吧】

环境参数：
  安全等级：C级（有帮派背景，但一般不惹事）
  NPC分布：
    - 酒保老王（固定，1人）：沉默寡言，看到了也当没看到
    - 服务员（2-3人）：年轻女性，穿黑色短裙制服
    - 顾客（随机5-15人）：各种身份，以男性为主
  潜在NTR角色类型：
    - 黑人留学生（60%）：麦克的同伴/同学，体型健壮
    - 白人游客（20%）：偶尔出现的商人/教师
    - 本地混混（20%）：认识酒吧老板，常年混迹
  触发事件概率：
    - 正常社交（70%）：喝酒、聊天、搭讪
    - 轻度NTR（20%）：肢体挑逗、被请酒、被摸
    - 重度NTR（8%）：被带走、在卡座发生关系
    - 暴力事件（2%）：冲突/打架/警察临检
  时间影响：
    - 周末夜晚→NTR概率+15%，顾客数量+10人
    - 工作日下午→正常社交+20%，NTR概率-10%
    - 凌晨2点后→重度NTR概率翻倍
  特殊条件：
    - 麦克在场时 → 重度NTR概率+20%，其他NTR角色回避
    - 顾清韵堕落值≥50 → 她主动进酒吧的概率从5%升至40%
```

### 安全等级体系参考

| 等级 | 含义 | 典型场景 | NPC特征 |
|------|------|---------|---------|
| S | 绝对安全 | 家、私人空间 | 只有预设角色 |
| A | 高度安全 | 学校/公司（白天） | 熟人为主 |
| B | 一般 | 商场/餐厅/公园 | 人群混杂但公开 |
| C | 有风险 | 酒吧/KTV/夜店 | NTR角色密集 |
| D | 高危 | 陌生人家/宾馆 | 完全失控 |

### 收益

- AI 不再随机决定"这个场景会发生什么"——概率分布已定义
- 时间和特殊条件增加动态感
- 玩家可通过选择场景来管理风险

### Pitfalls

> ❌ 每个场景都写成同样的概率分布 → 没有差异化
> ❌ 安全等级定义太抽象（"有风险"）→ AI 无法转化为具体遭遇
> ✅ 用具体的 NPC 类型名（不是"陌生人"而是"黑人留学生"）
> ✅ 特殊条件让场景有"记忆"

## 新模式添加指南

### 模板入库评估标准（Gate Check）

**不是所有新机制都值得新增为模板。** 新增模板前必须通过以下检查（用户明确要求：通用模板，不是单一卡的模板）：

| 检查项 | 通过标准 | 否决示例 |
|--------|---------|---------|
| **通用性** | 适用于≥3种不同类型卡（守护/NTL/后宫/系统等） | NTR5阶段升级只适用于NTR卡 |
| **不可分解性** | 不能拆成现有模板的Pitfalls/质量标准补充 | 状态栏分离只是模板一的正确做法 |
| **复用频率** | 预计每次制卡都会用到 | 连续开场白链只在15+章长篇用 |
| **独立价值** | 有现有模板未覆盖的核心设计模式 | 三级状态栏只是模板一的变体 |

**决策矩阵**：
- 3项以上通过 → 新增模板
- 1-2项通过 → 作为现有模板的Pitfalls/质量标准补充
- 0项通过 → 写入制卡流程复盘报告，不入库

**已验证案例**（2026-07-11校园媚黑v3复盘）：
- 状态栏与叙事分离 → ❌不独立成模板 → ✅补Pitfalls到模板一
- 连续开场白链 → ❌不独立成模板 → ✅补质量标准到模板十
- NTR角色5阶段升级 → ❌太特定 → 不入库，留复盘报告参考
