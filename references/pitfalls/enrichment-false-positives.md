# enrichment 假阳性处置规则

> 建立于：v1.15 合并包执行中实证。

## 1. R18 空壳检查 × 策略博弈关系条目

**症状**：enrichment_self_check --r18 对不对称博弈格式的关系条目报 🔴：
```
R18空壳[X] 'P4·刘宇×骆鹏：明确对手' 抽象规则N处但具体动作/语言/身体/场景/阶段链仅2类
```

**原因**：R18 启发式检查要求条目覆盖 ≥4 类可复用链条（动作链/语言链/身体反应/场景链/阶段链）。策略博弈关系条目写的是权力博弈结构（A想从B得到什么/误判/筹码/边界），天然不含动作链和身体反应链。

**处置**：**确认假阳性后放行。不要在策略博弈关系条目里灌肉戏凑链条数。**

**识别方法**：检查条目 comment 是否含 `×` 且内容以博弈格式为主（`【A想从B得到什么】`/`【双方分别误判了什么】` 等）。

---

## 2. 场景"缺少安全等级定义"× 空间功能模型

**症状**：enrichment 对空间功能模型格式的场景条目报 🟡：
```
场景[X] '场景·XXX' 缺少安全等级定义
```

**原因**：enrichment 检查 `安全等级|S级|A级|B级|C级|D级|隐私` 关键词。空间功能模型将安全信息嵌入空间拓扑（监控位置、窗户可见性、进入控制、固定声音中的风险信号）——不用旧 A/B/S 标签。

**处置**：确认场景已有空间拓扑+进入路径+固定声音+痕迹→**放行**。不要恢复旧标签格式。

**识别方法**：检查场景条目是否有 `【空间拓扑】`/`【进入与离开路径】`/`【固定声音】` 三段以上——有则视为已嵌入安全信息。

在 enrichment 报告末尾，对这些假阳性写明：

```markdown
## enrichment 假阳性确认

| [53-59] 6条场景 | 缺安全等级 | 空间功能模型用嵌入描述替代标签 | 放行 |
```
