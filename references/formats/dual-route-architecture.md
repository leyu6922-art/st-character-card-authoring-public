# 双路线架构：守护 vs NTR 分支系统

## 适用场景

当角色卡包含两种截然不同的玩法路线（如守护/纯爱 vs NTR/绿帽），需要在世界书中建立分支机制。

## 架构设计

### 核心条目（3条）

1. **路线A场景库** — 常驻条目（constant=true），包含路线A的所有场景模板、对话示例、心理变化
2. **路线B场景库** — 常驻条目（constant=true），包含路线B的所有场景模板、对话示例、心理变化
3. **分支机制** — 常驻条目（constant=true），定义路线选择规则、堕落度影响、事件触发优先级

### 分支机制条目必须包含

```
## 路线A
- 触发条件：{{user}}做什么选择时进入此路线
- 堕落度增长速度：慢/中/快
- 核心玩法概述
- 结局方向

## 路线B
- 触发条件
- 堕落度增长速度
- 核心玩法概述
- 结局方向

## 路线切换规则
- 两条路线能否交叉
- 从A切换到B的条件
- 从B切换回A的条件（救赎事件）
- 堕落度是否共享

## 堕落度分段影响
- 0-X%：路线A为主
- X-Y%：路线分化期
- Y-100%：深陷/终局期

## 事件触发优先级
- 列出所有可能的事件及其触发条件
```

### NTR角色独立条目

当路线B涉及多个NTR角色时，每个角色需要独立条目（800-1000字/条），包含：
1. 基本信息（姓名、年龄、身份、外貌、性器特征、性格）
2. 语言风格（称呼方式、标志性台词3-4句）
3. 行为模板（按阶段：发现→接近→胁迫→征服）
4. NTR玩法核心（力量压制/职业便利/身份便利/权力胁迫等类型标签）
5. 与{{user}}的关系变化（初期→中期→后期）

### system_prompt 更新

双路线卡片的 `system_prompt` 必须提及两条路线的存在：
```
【双路线系统】
本卡包含两条并行路线：
- 路线A：{{user}}选择XX，描述...
- 路线B：描述...
根据{{user}}的选择动态调整剧情走向，两条路线可以交叉进行。
```

### description 更新

角色卡 `data.description` 末尾应添加路线概述：
```
【双路线玩法】
路线A：简述
路线B：简述
NTR角色列表（如有）
```

## 实战案例：植物人妈妈v2（2026-07-04）

### 设计
- 路线A：守护路线（照顾→陪伴→保护欲→禁忌觉醒）
- 路线B：NTR路线（偷窥→侵犯→被发现→外人加入）
- 4个NTR角色：黑人留学生、健身教练、快递员、医生

### 新增条目
| 条目 | 类型 | 字数 |
|------|------|------|
| 守护路线·核心场景库 | constant, 路线A场景 | 1754 |
| 守护vsNTR分支机制 | constant, 分支规则 | 850 |
| NTR角色·黑人留学生 | constant, NTR角色 | 863 |
| NTR角色·健身教练 | constant, NTR角色 | 852 |
| NTR角色·快递员 | constant, NTR角色 | 835 |
| NTR角色·医生 | constant, NTR角色 | 890 |
| NTR路线·完整场景库 | constant, 路线B场景 | 1166 |

### 经验
- 守护路线条目需要「场景+对话模板+心理变化」三要素，不能只有大纲
- NTR角色条目每个800-1000字足够，不需要像主角那样3000+字
- 分支机制条目可以用表格形式列出角色一览，提高可读性
- 开场白中至少1条属于路线A、1条属于路线B，让玩家一开始就能选择方向
