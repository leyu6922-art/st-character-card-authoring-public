# 多参考卡设计模式（Multi-Reference-Card Design）

## 核心思想

复杂角色卡往往需要多张参考卡，每张负责不同维度。不要试图从一张参考卡中提取所有设计模式。

## 分工模式

| 参考卡 | 负责维度 | 提取内容 |
|--------|---------|---------|
| 角色深度型（如"参考卡"） | 角色条目质量 | 行为模板/NSFW指南/关系阶段/对话示例/日记系统 |
| 系统架构型（如"参考卡v4.2"） | 游戏机制 | 变量追踪/事件驱动/预处理脚本/面板格式/骰子池 |
| 世界观型（如大型奇幻卡） | 世界构建 | 种族/地理/政治/经济/文化体系 |

## ⚠️ 分析前门控（2026-07-11 大型结构化卡案例）

**先做卡类型匹配判断，再决定分析深度：**
- 参考卡是TRPG大世界冒险卡 → 你做的是NSFW/NTR叙事卡 → 只提取2-3个P0级模式即可
- 参考卡是同类NSFW卡 → 值得深度分析
- 不要因为一张卡"看起来厉害"就投入10倍于产出的分析时间

**系统架构型卡预设依赖检测：**
- system_prompt=0字 + 大量regex_scripts + 条目含getvar/setvar → P3依赖，换预设残废
- 大型结构化卡实测：通用预设下前端面板报错、变量更新失效、大量条目触发异常
- **提取原则**：只提取去掉预设依赖后的纯文本设计（分段标记、逻辑防火墙、事件种子库等P0/P1级），不提取MVU/正则/P3级设计

## 分析流程

1. **确定卡的类型**：NTR/冒险/养成/剧情 → 决定需要哪些维度
2. **为每个维度找参考卡**：
   - 角色深度：找条目数少但每条目3000-5000字的卡
   - 系统架构：找有getvar/setvar/脚本系统的大型卡（200+条目）
   - 世界观：找有完整世界设定的卡
3. **逐张分析**：用execute_code解析JSON，逐条目读取content
4. **提取可移植模式**：不是照搬内容，而是提取设计模式。**只提取P0/P1级（纯文本通用/格式依赖），P3级（脚本依赖）只记录不下发**
5. **整合到规划书**：将提取的模式写入新卡的规划书中

## 示例玄幻项目案例

| 参考卡 | 条目数 | 文件大小 | 提取的模式 |
|--------|--------|---------|-----------|
| 参考卡 | 13条 | 207KB | 角色3000-5000字标准、NSFW正确/错误示例、关系五阶段线、日记系统、事件系统 |
| 参考卡v4.2 | 469条 | 3MB | ~~stat_data变量结构（P3）~~、~~getvar/setvar追踪（P3）~~、~~@@preprocessing预处理（P3）~~、~~<UpdateVariable> JSON Patch（P3）~~ → **实际可用：分层逻辑防火墙（P0）、分段标记（P0）、事件种子库（P0）、结构化输出格式（P1）、道具系统模板（P1）、NPC生成管道（P3不可用）、随机池（P2需预设）** |

两张卡合计实际可用模式约5-8个（去掉P3依赖后），全部整合到规划书v5.0中。

## 系统架构型参考卡的关键设计模式

### ⚠️ 从大型结构化卡提取的P0/P1级可移植模式（已去预设依赖）

### 1. 分层逻辑防火墙（P0）
代替简单的OOC防护。将校验分为：世界设定→能力→资源→状态→物理五层。纯文本，零依赖。

### 2. 分段标记体系（P0）
50+条目的大型卡用 `➡️` 空条目标记区块（系统区/角色区/场景区/事件区）。零成本。

### 3. 事件种子库（P0）
事件条目 `enabled=false`，由AI在条件满足时判断是否触发，而非线性强制推进。

### 4. 道具/机制结构化模板（P1）
品质/使用条件/效果/副作用/进化路线/反噬条件 六段式描述。纯文本+格式依赖。

### 5. <action_info>面板格式（P1）
```
<action_info>
  {面板标题}
  | 数据行1: 值 |
  | 数据行2: 值 |
</action_info>
```
格式依赖，但不需脚本。用于状态栏/战斗结算/跃迁提示等。
