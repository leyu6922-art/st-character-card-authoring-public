# 角色卡创作陷阱库（完成前必读）

本文档汇总了所有实测踩过的坑。**每次做卡完成后、交付用户前，必须逐条自检。**

---

## 🔴 一级陷阱（会导致卡片完全不可用）

### T01: ST导入格式 vs 导出格式混用

**症状**：导入酒馆后世界书条目全部显示为关闭，需要手动逐个开启。

**根因**：SillyTavern有两套格式，字段名完全不同。正确格式用 secondary_keys / insertion_order / 31字段extensions。详见SKILL.md条目格式章节。

**铁律**：全部统一用v3正确格式（实测验证，能跑的卡统一使用此格式）。

---

### T02: 开场白写进世界书条目

**症状**：酒馆看不到切换按钮，备选开场白完全不显示。

**铁律**：
- 主开场白 → `data.first_mes`
- 备选开场白 → `data.alternate_greetings`
- 世界书条目 → 只放设定/规则/角色档案，绝不放开场白

---

### T03: alternate_greetings 放错层级

**症状**：ST编辑器显示"0 / 0"个备选开场白。

**铁律**：必须在 `data.alternate_greetings`，不能在 `data.extensions` 里。

---

## 🟡 二级陷阱（会导致返工或内容错误）

### T04: NTL转换时修改原文角色设定

**铁律**：保留所有角色原始设定一字不改，只改结构（谁变{{user}}、谁变NPC）和视角（开场白、system_prompt）。

### T05: NTL转换后开场白视角未同步

**铁律**：改了{{user}}身份 → 所有开场白必须从新视角重写。

### T06: 首次生成不达标

**铁律**：开场白目标1500字/个，写完立即用len()验证。不达标当场补，不等用户反馈。

### T11: 开场白中嵌入状态栏或emoji

**铁律**：开场白=纯叙事。emoji全量扫描替换（ord(ch)>0xFFFF）。写入后re.findall扫描raw JSON。

### T07: 写入后未回读验证

**铁律**：每次写入JSON后必须回读验证条目数和内容。

---

## 🟠 三级陷阱（会导致体验问题）

### T08: Discord简介使用表格

**铁律**：用列表+加粗+箭头，不用表格。

### T09: 参考卡格式未检测

**铁律**：用户提供了参考卡 → 先检测字段名和结构，再对齐生成。

### T10: 原著小说章节未验证完整性

**铁律**：做卡前必须验证章节数（本地 vs 在线）。

### T12: Discord简介含违禁词被自动删除（2026-07-05 实测确认）

**症状**：Discord帖子发布后被自动删除（用户称"数删"），或内容无法发送。

**根因**：Discord作为海外平台，对年龄相关内容有自动化审核。以下词汇会直接触发拦截：
- `萝莉` / `luoli` / `loli`（最常见触发词）
- `幼女`
- `童贞`
- 具体低龄数字 + 身体描写组合

**铁律**：
1. 生成Discord简介后，**必须扫描全文违禁词**
2. 发现违禁词立即替换：萝莉→少女/娇小，幼女→少女，童贞→初次
3. 只检查简介/帖子文案；角色卡description只有在手动复制进帖子时才需要检查
4. 用户有时需要纯文字版简介（无emoji/markdown），也要提供

**验证命令**：
```python
forbidden = ['萝莉', '幼女', '童贞', 'luoli', 'loli']
for word in forbidden:
    if word in intro_text:
        print(f"WARNING: 违禁词 '{word}'，帖子会被删除！")
```

**详见**：平台专用禁词表（不随公开版分发）

### T13: 旁白格式未写入system_prompt（2026-07-08 示例玄幻项目案例实测）

**症状**：first_mes中有大量 `*【旁白：...】*` 格式的旁白解说，显示正常（斜体灰色）。但从第二轮AI回复开始，旁白完全消失——AI不再使用旁白格式。

**根因**：system_prompt中没有旁白规则。AI只在first_mes中看到了旁白的示例，但system_prompt没有要求继续使用这个格式。Gemini等模型不会从first_mes自动学习格式约定。

**铁律**：system_prompt必须显式写旁白规则，不能依赖first_mes的示例。格式：

```
【旁白规则】在叙事关键节点使用旁白解说，格式为 *【旁白：解说内容】*（星号包裹方括号，酒馆中显示为斜体灰色文字）。旁白用于：
- 机制解释：道具使用流程、指令效果等
- 风险提示：危险情况、注意事项
- 进度提示：数值变化、阶段跃迁
- 行动引导：列出当前可选行动方案
- 角色心理：NPC的内心想法和潜意识变化
每轮回复至少包含1-2段旁白，穿插在叙事段落之间，不要集中在末尾。
```

**验证方法**：新开对话后，检查AI第2-3轮回复是否包含 `*【旁白：` 格式。如果只有first_mes有旁白、后续回复没有，说明system_prompt缺少旁白规则。

### T14: execute_code多轮修改不写盘（2026-07-10 羞涩继子案例实测）

**症状**：在多个 `execute_code` 调用中分别修改 JSON 数据，但只有最后一次写了文件，前面的修改全部丢失。

**根因**：每个 `execute_code` 是独立执行环境，不共享内存。调用1修改了 `d["first_mes"]` 但没 `json.dump()`，调用2读文件时拿到的还是旧内容。

**铁律**：
1. 每次修改数据后必须在**同一个 execute_code 调用内** `json.dump()` 写盘
2. 或者在一个 execute_code 中完成所有修改再统一写盘
3. 写盘后必须回读验证（T07）

---

### T15: 身体描写库keys过于泛化（2026-07-10 羞涩继子案例实测）

**症状**：多个角色的身体描写库条目共享泛化key（"身体"/"描写"/"屁股"），导致每次提到身体描写，所有角色的身体库同时触发，浪费token且注入不相关内容。

**根因**：身体描写库条目的key没有限定角色名。"陈妍希·身体描写库"和"瓦妮莎·身体描写库"的key重叠率>60%。

**铁律**：
1. 身体描写库条目**必须**以角色名为主key（如"陈妍希"/"妍希"）
2. 去掉跨角色共享的泛化词（"身体"/"描写"/"外貌"）
3. 保留该角色特有的身体特征词（如"乳瓜"/"白皙" 陈妍希；"巨乳"/"蜂腰" 瓦妮莎）
4. 同一key触发的条目数≤2为宜，超过说明key太泛

---

### T16: 角色档案外貌段与身体描写库内容重复（2026-07-10 羞涩继子案例实测）

**症状**：角色档案的"外貌描写"段落与身体描写库的"整体印象"段落内容高度相似（>50%），造成token浪费。

**铁律**：
1. 角色档案外貌段改为**引用性描述**（1-2句概括+指向身体描写库的引用）
2. 详细的身体描写集中在身体描写库条目中
3. 用 SequenceMatcher 检查条目间相似度，>40%需处理

---

### T17: 常驻条目有keys导致截断（2026-07-10 万恶后宫系统案例）

**症状**：validate_card报23个错误"常驻条目必须keys=[]"。

**根因**：constant=True的条目始终加载，keys字段（触发条件）无意义。有keys的常驻条目在ST截断逻辑中可能被误判为可丢弃。

**铁律**：构建时对所有constant=True条目强制keys=[]。
```python
for e in entries:
    if e.get('constant'):
        e['keys'] = []
```

---

### T18: 常驻条目过多导致首轮token超限（2026-07-10 万恶后宫系统案例）

**症状**：首轮token 8796 > 8000上限。validate_card报错。

**根因**：初始设计24个常驻条目（包括所有角色档案）。角色档案不需要常驻——角色出场时通过keys触发加载即可。

**铁律**：
- 常驻条目上限：**6-8个**（不超过10个）
- 只有纯规则/世界观/状态栏设为常驻
- **所有角色档案（包括主角）设为触发式**
- 万恶后宫系统修正：24→6常驻，token 8796→5032

**修正流程**：
1. identify哪些条目是"纯规则"（不依赖特定角色出场）
2. 这些保留常驻，其余全部改为触发式
3. 重跑token负载检查直到<8000

---

### T19: 角色权重未灵活分配条目大小（2026-07-10 万恶后宫系统案例）

**症状**：出场最多的角色（顾月凝1307次）条目反而最薄（967字），出场少的配角（陈琪56次）条目反而厚。

**根因**：机械按"核心/重要/配角"三级分配条目大小，未考虑出场频次。

**铁律**：条目大小应按 出场频次×剧情权重 分配：
- 出场1000+次的角色：条目2000-3000字 + 行为模板
- 出场300-1000次：条目1500-2000字
- 出场100-300次：条目800-1200字
- 出场<100次：条目500-800字或合并
- 行为模板的字/次比（条目字数÷出场次数）应≥1.0

---

每次做卡完成后，运行 validate_card.py。passed=False 时必须修复所有 errors 再重跑。
