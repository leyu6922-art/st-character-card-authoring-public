# 计划书达标评估方法论

## 背景

2026-07-05 示例玄幻项目案例。用户做完计划书v4.0（14KB/10章节）后，主动要求评估是否达到直接写卡标准。对比参考卡"参考卡"（13条/207KB）后发现差距巨大。

## 评估所需材料

1. 计划书（.md）
2. 小说原文（全部章节，至少读关键章节）
3. 参考卡JSON（如果用户指定了）
4. 当前已有的JSON骨架（如果有的话）

## 评估维度详解

### 1. 角色行为模板深度

**达标标准**：每个核心角色有≥1500字的行为模板

参考卡做法（顾清裕案例）：
- 朋友阶段：3890字，含具体行为模式、性爱表现、绿帽事件中的表现、日常互动、心理状态
- 混沌期：5207字，含触发条件、身体状态、初始反应、心理变化
- 归真期：3811字+5013字，含沟通模式、腹黑揭秘录、挑逗三步法

当前计划书做法：
```
异变期（堕落0-49）：
  关系：师徒。内力变黑，心境变化，一日三省记录异常。
  行为：收徒、引导亲密、寻找臭味。无性爱。
```
→ 只有15行概述，没有具体行为描写

### 2. 原作对话引用

**达标标准**：每个角色≥5句直接从原文摘录的对话

小说36.4万字中有大量可用素材：
- 角色D："徒儿，这里的话……可不行哦，毕竟为师还是傲天的未婚妻，可是要为他守贞的呢。"
- 角色A："大姐……大姐……傲天哥哥他称赞我了……但是……像柔儿这种下贱肮脏的坏女人，哪有资格获得傲天哥哥的赞美啊"
- 厉红霞："如果一个男人能征服世界，厉红霞就立志要做能征服这个男人的女人。"
- 角色B："我被强奸了，我不干净了。"

计划书中完全没有引用。

### 3. NSFW指南质量

参考卡做法：
- 2782字的NSFW指南
- 正确示例（200字具体描写）
- 错误示例（对比什么是不该写的）
- 互动模式（具体对话+动作描写）

计划书做法：只有"角色D·NSFW指南（骨架）"标题

### 4. 系统机制详细度

参考卡做法：
- 绿帽事件系统：3360字，含触发机制、告知机制、运作原理、演变规则
- 功法系统：2362字，含源流、特性、子宫认主机制
- 预处理脚本：getvar/setvar实现动态追踪

计划书做法：
- 事件自动触发：8行表格（事件名+触发条件+效果）
- 相机系统：4行概述
- 没有脚本系统

### 5. 条目覆盖度

计划书14条覆盖：OOC防护/世界观/武道体系/相机指南/状态栏/角色D(5条)/龙傲天/NTR矩阵/剧情推进/行为模板

缺失的关键角色：
- 角色A（赎罪心理系统、迷奸→扭曲轨迹、NSFW指南）
- 厉红霞（五毒刑讯、权力欲望、NSFW指南）
- 角色B（萝莉娃娃+被胁迫心理）
- 角色C（龙傲天母亲+商业精英）
- 龙琪儿（先天病弱妹妹）
- 噩梦/炼狱/冤魂系统
- 备选开场白

### 6. 参考卡深度对标

| 指标 | 参考卡 | 当前计划书 |
|------|--------|-----------|
| 条目数 | 13条 | 14条（骨架） |
| 文件大小 | 207KB | 52KB |
| 条均字数 | 3000-5000字 | ~500字 |
| NSFW指南 | 2782字+正确/错误示例 | 骨架标题 |
| 角色数 | 1个（极深度） | 6+个（极浅度） |
| 原作对话 | 大量引用 | 无引用 |
| 脚本系统 | getvar/setvar | 无 |

  [缺失条目清单]

  Step 2: 参照参考卡深度，为每个核心角色写详细行为模板+NSFW指南
  Step 3: 将计划书从14KB扩充到40-50KB
  Step 4: 然后再开始写JSON

## 关键教训

1. **计划书的"章节多"≠"深度够"**：10个章节但每个只有概述性描述，不如5个章节但每个3000字的详细规范
2. **小说素材是金矿**：36.4万字的原作对话和场景描写，比AI凭空编造的质量高10倍
3. **参考卡是最好的标尺**：直接对比参考卡的条目深度，比任何抽象标准都有效
4. **用户会主动要求评估**：不要等到写完卡才发现计划书不够——在计划书阶段就做门控检查
