# 触发审计失败后的全新重做流程

> 来源：2026-07-15 校园示例卡婊子记守护卡 v1 → v2 重做。适用于旧卡不仅有单点错误，而是世界书触发架构、条目厚度、事件种子和流程门控整体不合格的情况。

## 何时不要补丁式修卡

满足任意 3 项，优先全新重做而不是在旧 JSON 上打补丁：

- `validate_card.py` 未通过，且错误包含结构字段缺失（如 extensions 不完整、addMemo、spec 等）。
- `audit_worldbook_triggers.py` 报告存在硬泛 key 或多个 greeting 误触发。
- 有多条 `secondary_keys` 但顶层 `selective=false`，说明旧卡没有真实触发设计。
- 条目数量明显低于计划书目标（例如计划 35-42 条，实际 12 条）。
- 没有事件种子库，关键剧情节点无法按需展开。
- 多主题大条目把多个角色/威胁/NPC 混在一个 content 中。
- 核心角色条目明显偏薄，缺行为模板、语言指纹、守护窗口、场景反应差异。
- 旧卡没有世界书触发设计矩阵，keys 是后填的。

## 正确顺序

1. **保留旧卡，不覆盖**
   - 旧卡只作为反例和审计输入。
   - 新文件命名 `{卡名}_v2.json` 或 `{卡名}_全新重做.json`。

2. **重新跑原型判定**
   - 即使旧计划已有原型，也按 §1.0 决策树重判。
   - 必须让用户确认：B型守护 / A型恶堕 / G型多视角 / 其他。

3. **重新统计源文件**
   - 统计章节、中文字数、角色频次、关键场景频次。
   - 注意章节标题可能有全角空格；正则用 `^\s*(序章|第一章|part2...)\s*$`，不要只匹配行首无空格。

4. **写新版规划书，而不是直接构建**
   新规划书必须包含：
   - 为什么不修旧卡；
   - 旧卡审计结论摘要；
   - 原型判定；
   - 角色范围；
   - 威胁NPC范围；
   - 模板匹配；
   - 剧情节点；
   - 世界书条目架构；
   - **世界书触发设计矩阵**；
   - key 禁止表；
   - selective 使用原则；
   - validate + audit 双验证目标；
   - 用户确认项。

5. **构建采用 write_file-first**
   - 大段中文内容先写入 `v2_parts/*.txt`，再由组装脚本读取。
   - 避免 execute_code 内联长中文导致 T58 内容截断。

6. **交付前双报告**
   - `validate_card.py` 必须 passed=True。
   - `audit_worldbook_triggers.py` 生成 Markdown 报告，硬风险=0。
   - 新报告随卡一同归档。

## 规划书里的触发设计重点

- 系统常驻：`constant=true, keys=[]`。
- 分区标记：`constant=true, keys=[]`，content 极短，不承担剧情触发。
- 人物专名：通常 primary-only，不把外貌词塞进 secondary 当备注。
- 场景条目：使用专名或复合短语，禁止裸 `家/学校/老师/唱歌/体育馆/房间`。
- 事件种子：默认 `enabled=false`。
- `secondary_keys` 只用于范围绑定；不用 selective 就清空。

## 交付状态判断

- “流程治理/审计脚本完成” ≠ “卡本体可归档”。
- 卡本体只有在 validate 通过、触发审计硬风险为 0、审查模板和加料自检完成后，才能说完成。
