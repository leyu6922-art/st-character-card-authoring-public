# 多参考卡设计模式（Multi-Reference-Card Design）

## 核心思想

复杂角色卡往往需要多张参考卡，每张负责不同维度。不要试图从一张参考卡中提取所有设计模式。

## 分工模式

| 参考卡 | 负责维度 | 提取内容 |
|--------|---------|---------|
| 角色深度型（如"参考卡"） | 角色条目质量 | 行为模板/NSFW指南/关系阶段/对话示例/日记系统 |
| 系统架构型（如"参考卡v4.2"） | 游戏机制 | 变量追踪/事件驱动/预处理脚本/面板格式/骰子池 |
| 世界观型（如大型奇幻卡） | 世界构建 | 种族/地理/政治/经济/文化体系 |

## 分析流程

1. **确定卡的类型**：NTR/冒险/养成/剧情 → 决定需要哪些维度
2. **为每个维度找参考卡**：
   - 角色深度：找条目数少但每条目3000-5000字的卡
   - 系统架构：找有getvar/setvar/脚本系统的大型卡（200+条目）
   - 世界观：找有完整世界设定的卡
3. **逐张分析**：用execute_code解析JSON，逐条目读取content
4. **提取可移植模式**：不是照搬内容，而是提取设计模式
5. **整合到规划书**：将提取的模式写入新卡的规划书

## 示例玄幻项目案例

| 参考卡 | 条目数 | 文件大小 | 提取的模式 |
|--------|--------|---------|-----------|
| 参考卡 | 13条 | 207KB | 角色3000-5000字标准、NSFW正确/错误示例、关系五阶段线、日记系统、事件系统 |
| 参考卡v4.2 | 469条 | 3MB | stat_data变量结构、getvar/setvar追踪、@@preprocessing预处理、<action_info>面板、<UpdateVariable> JSON Patch、事件驱动架构（标题+阶段+信号）、骰子池、性格池 |

两张卡合计提取15+个可移植设计模式，全部整合到规划书v5.0中。

## 系统架构型参考卡的关键设计模式

从大型结构化卡提取的可移植模式：

### 1. stat_data变量结构
```json
{
  "角色A": { "属性1": 值, "属性2": 值 },
  "世界": { "时间": "...", "地点": "..." },
  "事件": { "当前事件": null, "阶段": null }
}
```
通过 getMessageVar('stat_data.角色A.属性1') 读取。

### 2. @@preprocessing预处理
每轮回复开始时自动执行，读取变量→检测阈值→触发事件→设置本地变量。
```
<%_
var x = getMessageVar('stat_data.角色.属性', {defaults: 0});
if (x >= 阈值) { setLocalVar('事件触发', true); }
_%>
```

### 3. 事件驱动架构
每个事件有：标题、阶段列表、每阶段的场景脚本、每阶段结束的变量更新。
阶段切换通过 <UpdateVariable> JSON Patch 实现。

### 4. <action_info>面板格式
```
<action_info>
  {面板标题}
  | 数据行1: 值 |
  | 数据行2: 值 |
</action_info>
叙事文本紧跟面板后面。
```

### 5. <UpdateVariable> JSON Patch
```xml
<!-- SYSTEM_COMMAND_START -->
根据本轮剧情，在<UpdateVariable>中更新以下变量：
  将'stat_data.角色.属性'增加 [数值]
<!-- SYSTEM_COMMAND_END -->
```
