# 交叉验证·修复核验清单

**适用场景**：另一个 Hermes 窗口已经对角色卡做了修复/裁剪/修改，本窗口需要独立验证其修复是否全面。

**核心原则**：信任但验证。另一窗口的修复可能漏掉系统条目中的残留引用——这些是最容易被漏掉的地方。

---

## Step 1: 确认修复范围

先读取另一窗口的修复清单（用户会提供或你可以从会话中提取）。确认：
- 删了哪些角色/条目
- 改了哪些系统条目
- 改了哪些开场白/卡壳
- 新增了什么

## Step 2: 运行 validate_card.py

```python
exec(open(r"<HERMES_HOME>/skills/creative/st-character-card-authoring/scripts/validate_card.py").read())
passed, errors, warnings = validate_card(card_path)
```

**先跑脚本，不要肉眼扫JSON。** 结构性问题（缺addMemo/keys非空/ID不连续）脚本抓得比人快。

## Step 3: 已删角色全卡残留扫描

当另一窗口声称已删除角色并清理引用后，**必须独立跑一次全卡扫描**。以下是最容易被遗漏的位置：

### 3.1 系统条目 content（最容易漏）

| 条目类型 | 常见残留模式 | 本session案例 |
|----------|------------|-------------|
| `[3] 反顺从规则` | NPC举例用了已删角色 | `吕玲珑初期强烈抗拒淫乱`→应改为林夕颜 |
| `[8] 淫妻兴奋度系统` | 角色速度对比用了已删角色 | `李映月最快，吕玲珑最慢`→应改为朱新菜 |
| `[0] OOC防护` | 背景设定引用已删系统 | `"美汁汁儿系统"已激活`→应改为穿越者身份 |
| `[1] 状态栏` | 角色阶段列举含已删角色 | `朱紫霞:{淡然/挑逗/沉迷}`→需删除 |
| `[6] NPC信息边界` | 信息规则举例含已删角色 | `姜媛媛和儿子瓜蛋的母子乱伦`→需重写 |
| `[7] NPC行为独立性` | 并行行动举例含已删角色 | `朱紫霞在挑逗安胜、瓜蛋在偷看`→需重写 |
| `[9] 分享选择系统` | 示例配对含已删角色 | `"让映月去陪安胜和瓜蛋"`→需替换 |
| `[10] 共享规则` | 推手角色引用已删角色 | `掌门朱紫霞是最大的推手`→需替换 |

### 3.2 开场白 content

扫描所有 alternate_greetings 和 first_mes 中是否直接提到已删角色名。

本session案例：`ALT1开头「朱紫霞下山访友去了」`——朱紫霞已删，描述她"不在场"同样需要移除。

### 3.3 条目 content（非系统条目）

针对5个核心角色以外的所有条目，搜其content中是否包含已删角色名。

**注意**：
- 条目的 comment/标题中不会有已删角色（另一窗口大概率检查过了）
- 但 content 内可能残留，特别是：
  - 语料库中的原文对话（如李映月台词「二师姐也在～」中的「六师兄」）
  - 共享规则条目中的角色一览
  - 场景条目中的固定NPC分布

### 3.4 允许的特例

以下引用可以不删，但需确认标记了「已云游/已不在」等说明：
- 角色出身背景（如「朱新菜是掌门朱紫霞（已云游）的女儿」）
- 原文语料库不可修改的原文对话

## Step 4: 确认裁剪条目是否删干净

搜索所有条目，确认**连comment都搜不到**已删角色的条目名。

Python 扫描模板：
```python
deleted_chars = ["朱紫霞", "安胜", "姜媛媛", "瓜蛋", ...]
for e in entries:
    content = e.get("content", "")
    comment = e.get("comment", "")
    for char in deleted_chars:
        if char in content:
            # 检查是否为允许特例
            if e["id"] not in allowed_exception_ids:
                print(f"  ❌ [{e['id']}] '{comment}' → '{char}' 在content中")
        if char in comment:
            print(f"  ❌ [{e['id']}] comment包含 '{char}'")
```

## Step 5: 完整性验证

| 检查项 | 方法 |
|--------|------|
| 裁剪后的角色数是否等于预期 | `len(set(角色集))` |
| 每个保留角色是否有基础设定条目 | 每个角色至少1条+1条语料库 |
| 新加入角色（如赵旺）是否有足够深度 | ≥600中字，无元描述（"已不在本卡"） |
| 事件种子是否≥2个 | 1个群交+1个情景类 |
| 开场白5条≥1400字 | validate_card已覆盖 |
| 常驻keys=[] | validate_card已覆盖 |
| 无元描述残留 | 搜"已不在""已删除""此条目"等 |

## Step 6: 报告格式

按以下格式输出：
```
✅ 确认项（另一窗口正确修复的）：
  - ...

❌ 漏修项（本窗口发现的）：
  - [位置] 残留 → 建议修复方式

🟢 允许保留：
  - [位置] 角色 → 理由
```
