# 三重验证工作流：Agent 规划 → GPT 审核 → 决策采纳

> 适用：需要外部视角验证复杂技术方案的阶段路由/预设修改/版本规划场景。
> 案例：艳母的荒唐赌约 v1.17.2 推荐预设自动路由版（2026-07-18）。

---

## 1. 问题

SillyTavern 角色卡/预设的技术方案涉及多层约束（ST 世界书机制、预设 Core 结构、Regex 处理链），单靠 Agent 静态分析容易漏坑。比如本案例中 Agent 最初未发现：

- 预设存在启用的 `HTML注释-去除` Regex；
- `status_top` 是共享变量而非空闲接口；
- World Info 没有最新优先级概念。

直接执行存在隐患。

---

## 2. 工作流

### 阶段一：Agent 起草方案（审查决策窗口）

1. 读取当前基线（角色卡 JSON、预设 JSON）；
2. 本地文件核验关键字段（entries keys/secondary/regex/prompts）；
3. 输出《问题分析文档》和《修改规划书》；
4. **明确限制**：只做规划，不修改任何文件。

### 阶段二：用户将方案交给 GPT 审核

用户将 Agent 输出的文档发给 GPT（第三方 LLM，无本地访问），要求：

- 指出技术错误；
- 指出架构漏洞；
- 提出替代方案。

### 阶段三：审查决策窗口选择性采纳

Agent 收到 GPT 回复后：

1. **本地核验 GPT 的每个指正**：用 execute_code 读取预设/卡文件，确认事实是否正确；
2. **分类处理**：

| 类别 | 处理 |
|---|---|
| 真实 bug（如 HTML 注释会被清理） | 必须修正方案 |
| 架构冲突（如 status_top 被占用） | 必须修正方案 |
| 优化建议（如方括号 vs XML 标签） | 部分采纳，保留备用 |
| 过度复杂化建议 | 暂不采纳 |
| 重复建议 | 跳过 |

3. **输出审查决策文档**：明确写出每条建议的采纳/不采纳理由；
4. **输出修正后的修改方案**：角色卡方案 + 预设方案。

### 阶段四：执行窗口落地

另一个 Agent 窗口读取决策文档，按方案执行，输出交付报告。

### 阶段五：审查决策窗口核验报告

读取交付物，抽检关键字段，确认报告与产出物一致，给出最终审核结论。

---

## 3. 关键决策原则

### 3.1 本地核验优先

不要盲目相信任何一方（包括 Agent 自己的初始分析和 GPT 的反馈）。每次收到外部审核意见后，必须用 `execute_code` 读取实际预设/卡文件确认事实。

本案例实证：GPT 指出 HTML 注释会被删除，本地打开的预设确实有启用的 `HTML注释-去除` Regex，核验通过才采纳。

### 3.2 选择性采纳，不全盘照搬

| 原则 | 说人话 |
|---|---|
| 真实 bug 必须修 | 会导致自动路由失效的硬伤 |
| 架构冲突必须修 | 变量冲突、系统不兼容 |
| 风格建议可以暂不采纳 | GPT 推荐方括号，但判断 XML 标签更适合扩展 |
| “可能不行”不要立即改 | 等实机验证 |

### 3.3 控制复杂度

用户偏好：**不用太复杂，真正有 bug 才修，小瑕疵跳过**。

不要因为 GPT 提出 8 条建议就全部执行。区分：

- 必须修：导致功能失效的硬伤（HTML 注释被删、变量被覆盖）
- 可以修：改善稳定性的优化（scan_depth、Min Activations）
- 暂不修：完美主义扩展（ROUTE_EVENT、多格式兼容）

### 3.4 双版本定位

当方案有两个不同目标用户群时，做分离：

- v1.17.2 推荐预设自动路由版：社区主推，开箱即用
- v1.17.1a AN 权威版：高级用户，跨预设兼容

**不宣称“一张卡同时兼容所有场景”**。

---

## 4. 产物清单

一轮完整的三重验证应输出：

```
参考资料/
  ├── 问题分析文档.md          ← Agent 初稿
  ├── 修改规划书.md            ← Agent 初稿
  ├── 审查决策总文档.md        ← 收到 GPT 回复后
  ├── 新版本角色卡修改方案.md   ← 修正后
  └── 推荐预设_修改版方案.md    ← 修正后
```

执行窗口输出：

```
vX.Y.Z_修改报告.md
vX.Y.Z_审计报告.md
推荐预设自动路由版_使用说明.md
推荐预设自动路由版_实机测试清单.md
```

---

## 5. 本案例关键教训

| 教训 | 细节 |
|---|---|
| HTML 注释不可靠 | 许多预设会启用 regex 清理 |
| 共享变量是陷阱 | status_top 被占用前必须核验 |
| World Info 无优先级 | 多个 marker 同时存在 = 同时触发 |
| 最小字段原则 | route_state 只放必要字段，自然语言字段扩大误触发面 |
| 自动版与 AN 版不可混 | 历史保留和 AN 当前 marker 会撞 |
