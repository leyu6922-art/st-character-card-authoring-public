# 2026-07-15～16 制卡流程复盘：交付门控与内容厚度经验

> 来源：多张测试卡/流程卡的正文复盘（校园示例卡、催眠助理、绿冠星空、黑绿足球、绿帽快餐、周雨晴、示例角色项目等）。本文件记录可复用流程经验，不记录一次性任务进度。

## 1. validate 通过不等于可交付

`validate_card.py` 只证明 JSON 结构可导入。交付前必须同时满足：

- `validate_card.py`: errors=0；
- `audit_worldbook_triggers.py`: 硬风险=0，secondary 忽略=0，泛 key 无硬误触发；
- `enrichment_self_check.py`: 红项=0；legacy/严格 profile 下若脚本提示“黄项≥3不能交付”，不得主观放行。开放玩家主导 profile 仍阻断红项，但普通黄色内容诊断不因数量自动阻断；事实、代理、触发和构建错误始终不能放行。
- residue/本地化/构建残留扫描通过；Discord/社区词只影响发布简介/帖子文案，发布专项用 `--publish-text <简介.md> --strict-platform/--strict-age`；
- 开场白完整、分段、无重复灌水、无截断；
- build 源、计划书、最终 JSON 同步，可复现组装。

## 2. 触发质量比卡体积更关键

高 token/高字符数只是诊断信号，不是绝对失败。真正要看：

- first_mes 是否误触发无关深度档案；
- `secondary_keys` 是否因顶层 `selective=false` 被 ST 忽略；
- 是否存在裸泛 key（如“家/学校/妈妈/胸部/体位/危险”等）；
- 首轮加载的是结构化协议，还是多角色档案/关系/场景/状态栏/旁白/NPC自主/反顺从混杂；
- 输出义务是否由角色卡自身写死。

计划书必须包含世界书触发设计矩阵：触发意图、是否首轮需要、primary/secondary、selective、enabled、误触发风险、按需不触发是否可接受。

## 3. 外部预设/API/模型安全不是卡质量失败项

社区用户会使用不同预设和模型。Gemini 安全策略、破限力度、网关断流、某个预设的输出义务过重，只能作为 ST 运行环境排查，不应写成角色卡交付失败。

角色卡流程只判定卡自身：key 准确性、secondary/selective、常驻必要性、人物关系、内容厚度、事件/场景/语料实用性、主流预设兼容性。

## 4. G 型选开模式专项坑

G 型默认选开模式时：

- 共用层（角色/场景/事件/语料/NPC规则）不得残留 `{{user}}`；必须用具体角色名；
- 只有“选开身份”条目可以定义 `{{user}}`；
- 选开身份条目应为 `constant=true + enabled=false + keys=[]`，comment 标明“选开”；
- greeting 必须视角中性，不能默认用户是苦主或征服者；
- greeting 模式只是社区发布备选，不是默认。

## 5. 开场白完整性不是字数问题

开场白必须：

- ≥1400 中文字，但不得 pad_to/重复灌水；
- 自然分段，不能一整块密集文本；
- 结尾完整，有行动钩子；
- 无未闭合引号/括号、无明显复制原文到半截；
- G 型选开 greeting 不得出现身份锁死句；
- 做完后扫描重复行、异常短尾、截断尾巴。

## 6. R18/NSFW 卡不能只写规则

守护卡、C 型成长线、E 型禁忌关系也可能是 R18 卡。不能因为不是传统 NTR/NTL 就只写机制。

可生成内容必须包含：

- 动作链：行为推进与反应升级；
- 语言链：命令/挑衅/嘴硬/声音变化/服从或反抗；
- 身体反应：表情、呼吸、姿态、肢体、声音等；
- 心理链：身份自尊、抗拒理由、羞耻点、认输点；
- 场景链：空间压迫、风险、可介入点。

比例建议：70% 动作与感官 + 20% 心理变化 + 10% 状态总结。禁止只写“性张力升级规则”“逐渐服从”“失败后被侵蚀”这类抽象描述。

## 7. 事件种子必须能发动剧情

严格/引导事件种子可包含：触发前提、参与角色、空间、核心冲突、用户可介入点、成功路径、失败路径、半成功代价、后续影响、可复用台词/动作素材。

开放情境种子不写成固定结果脚本：保留自然入口、可观察压力、NPC/环境可能反应、玩家接管点、开放方向和事实锚点；成功/失败/半成功只有在项目显式声明相应事件 profile 或守护合同后才检查。

## 8. 关系矩阵与 NTR 关系条目不能薄

核心女性×核心 NTR 男性的关系条目要有：阶段演变、行为链、女方态度变化、NTR 男性手段差异、苦主/旁观者信息边界、场景触发词、典型台词、后续事件。不要把关系条目写成 100～300 字备注。

## 9. 构建链路必须可复现

大卡采用 file-first：条目源文件 → all_entries/build 数据 → assemble → 最终 JSON。

交付前确认：

- 最终 JSON 与 build 源同步；
- 重新 assemble 不会覆盖回薄版本；
- `data.spec/spec_version` 不丢；
- top/data 字段同步；
- 修复最终 JSON 时必须同步 build 源。

## 10. 子代理产物必须验收

子代理输出常见问题：开场白不足、条目未达字数、内容被安全过滤变薄、只写结构不写可用素材、文件未真正写入。主代理必须统计字数、读回内容、检查结构与实用性后再合并。

## 11. 建议新增/保留自动门控

- 开场白完整性检查；
- G 型选开专项检查；
- R18 内容密度抽查；
- 关系矩阵厚度检查；
- 构建链路同步检查；
- 本地化/residue/构建残留扫描；发布简介/帖子文案专项扫描（仅平台可见文案，不扫描卡 JSON）。
