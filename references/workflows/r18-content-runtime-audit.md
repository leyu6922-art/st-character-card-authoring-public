# R18内容与运行触发审查补丁

适用场景：用户反馈“卡不色”“没有肉文感觉”“只有系统没有过程”，或对任何R18/NSFW角色卡做成卡审查、修卡审查时使用。

## 核心教训

R18卡的质量不等于“存在色情规则条目”。真正影响跑卡体验的是：

1. **内容是否具体**：是否写了动作链、语言链、身体反应链、心理崩塌/服从链。
2. **内容是否可达**：具体R18示例/阶段链是否会在首轮或对应场景触发。
3. **内容是否贯通**：system_prompt、常驻规则、角色档案、关系条目、开场白、mes_example是否都指向同一R18卡型。
4. **内容是否按卡型服务玩法**：C型征服者卡要写“{{user}}怎么推进、目标怎么被玩弄、她如何抗拒/嘴硬/失控/屈服”，而不是泛泛写暧昧氛围。

## 用户反馈识别

当用户说：
- “一点都不色”
- “太保守”
- “没有肉文感觉”
- “我指的色情是主角怎么玩弄她们”
- “语言、动作行为等等”

不要继续只补“氛围/系统/规则”。应切换到**R18过程层修复**。

## R18过程层最低结构

每个核心目标至少要有以下结构之一：

```markdown
【{角色名}·R18行为指南】
描写重心：70% {{user}}动作/感官/控制 + 20% {{user}}心理/征服感 + 10% 目标状态。

场景反应差异：
- 初期：她如何轻视/拒绝/嘴硬。
- 中期：她被触碰后哪些动作、声音、身体反应开始失控。
- 后期：她如何被训练出条件反射、主动配合或服从。

被玩弄过程示例：
- 具体场景。
- 具体动作链：做了什么→她怎么反应→继续做什么→反应升级。
- 具体语言链：羞辱/命令→嘴硬→声音变调→破碎回应→屈服或条件式服从。
- 具体身体链：触碰部位、肌肉/呼吸/姿势/湿润/颤抖等客观反应。
```

## 按卡型判断“色情怎么写”

### C型/NTL/征服者卡
核心是{{user}}主动推进，R18内容必须服务“征服链”。

必须写：
- {{user}}如何利用身份、权限、把柄、场景、系统、道具推进；
- 目标女性如何从轻视/抗拒到身体反应失控；
- 攻略阶段 L0-L5 或等价阶段；
- 失败/阻力：职位、警惕、信息量、场景风险，而不是一键屈服。

错误写法：只写“她脸红、气氛暧昧”。
正确写法：写清“怎么被逼近、怎么被触碰、怎么嘴硬、怎么声音变、怎么身体先屈服”。

### NTR苦主/恶堕卡
核心是苦主无力、女主堕落、NTR方推进。R18内容必须包含女主身体反应与苦主信息边界/旁观痛感。

### 守护/反NTR卡
核心是风险、唤醒、干预窗口。R18内容不能只服务施害方爽感，要写“威胁正在发生、{{user}}如何阻止/夺回/承担代价”。

### E型禁忌后宫/权力后宫卡
核心是保密闭环、日常/私下双模式、成员间关系协调。R18内容必须写公开伪装与私下服从反差。

## 运行触发审查：比内容存在更重要

修R18后必须跑触发审计并人工检查：

- R18主规范是否常驻或首轮可达？
- 具体示例库是否只靠“色情台词示例/性爱阶段”这类人工key？如果是，玩家自然对话很难触发。
- 核心关系条目是否用 `A×B` 作为唯一key？这通常是死key，应改为自然角色名+关系词或selective。
- 随机玩法核心（随机NPC、随机场景、随机事件、攻略阻力、奖励/反噬）是否在first_mes/alternate中触发？如果不触发，AI只知道概念，不知道表格。

## 13步报告时效规则

任何一次成卡后，如果又做了以下修改，旧13步报告作废，必须重新生成：

- 新增/删除世界书条目；
- 修改常驻系统条目；
- 修改system_prompt/first_mes/alternate_greetings/mes_example；
- 修改keys/secondary_keys/selective/constant/enabled；
- 大规模加厚角色档案或R18内容。

报告中的文件大小、条目数、常驻数、warnings数量必须与当前卡一致。

## 修复顺序

不要在触发失效时继续堆内容。推荐顺序：

1. 备份当前JSON。
2. 修system_prompt：写清最终卡型、R18输出规范、随机玩法推进规则。
3. 修触发：让核心玩法/R18阶段链首轮或对应开场白可达。
4. 修key：人工key改自然key或selective。
5. 再补内容：未覆盖角色、关系、事件种子。
6. 跑 validate_card.py、audit_worldbook_triggers.py、enrichment_self_check.py。
7. 重新生成13步交付门控报告。
