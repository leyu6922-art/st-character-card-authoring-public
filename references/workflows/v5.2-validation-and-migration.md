# v5.2 Validation, Migration, and Delivery Boundaries

## Purpose

v5.2 keeps the established file-first card pipeline while separating **schema validity** from **Leyu production quality**. It changes no production-card content and does not infer untested SillyTavern behavior from CCv3 alone.

## Validation profiles

```bash
# CCv3 schema only: standard root/data fields, required and optional typed fields, Lorebook metadata and entry fields.
python scripts/validate_card.py CARD.json --profile ccv3-core --format json

# Default: existing Leyu production quality gates plus structured issue output.
python scripts/validate_card.py CARD.json --profile leyu-production --format json
```

- `ccv3-core` does **not** require top-level exporter mirrors or `data.spec/data.spec_version`.
- `leyu-production` always runs `ccv3-core` first, then retains greeting thickness, production entry conventions, trigger checks, relationship checks and G-mode checks.
- `data.spec/data.spec_version` are permitted compatibility extras. Add an ST-export-specific rule only after a fresh, versioned ST export/round-trip fixture proves the behavior.

## Manual-toggle identity contract

Use this only for Leyu G-mode manual identity selection:

```json
{
  "constant": true,
  "enabled": false,
  "keys": [],
  "secondary_keys": [],
  "selective": false,
  "comment": "…（选开）",
  "content": "{{user}}…"
}
```

A manual-toggle identity is activated in the ST World Info UI; it is not a keyword-routed module. The production validator emits stable IDs such as `MANUAL_TOGGLE_KEYS_NONEMPTY` when this contract drifts.

## Safe artifact operations

### Write JSON

```bash
python scripts/atomic_write_json.py INPUT.json OUTPUT.json
```

The writer serializes without a BOM, parses its temporary output before replacement, creates a timestamped backup when replacing an existing target, uses `os.replace()`, and reports SHA-256.

### Migrate an older card

```bash
# Preview only; no file changes.
python scripts/migrate_card.py INPUT.json

# Explicitly write a new file.
python scripts/migrate_card.py INPUT.json --output OUTPUT.migrated.json --write

# Explicit semantic changes require explicit flags.
python scripts/migrate_card.py INPUT.json --output OUTPUT.json --renumber-ids --set-prevent-recursion true --normalize-unicode --write
```

Migration preserves Lorebook metadata (`description`, `scan_depth`, `token_budget`, `recursive_scanning`, `extensions`) and existing IDs/recursion/Unicode by default. It maps only documented legacy integer positions (`0 → before_char`, `1 → after_char`) and emits only CCv3 `position` values. ST-native positions (`2/3/4`) are rejected rather than silently guessed. Every `--write` validates the migrated payload against `ccv3-core` before an atomic replacement. `fix_card_format.py` and `safe_write_card.py` are compatibility wrappers only; do not use them in new build scripts.

## Trigger and build integrity

- `scripts/lib/worldbook_matcher.py` is the one matcher used by `validate_card.py`, `audit_worldbook_triggers.py`, and `analyze_token_load.py`; validator recursion simulation also calls it, so enabled/selective/secondary/regex/case/whole-word semantics cannot diverge.
- `analyze_token_load.py` is read-only; it no longer rewrites keys or card JSON.
- `check_build_sync.py` canonicalizes semantic fields. It detects drift in entry keys, secondary keys, enabled/constant/selective state, `case_sensitive`, `priority`, `name`, extensions and regex scripts. It also compares `character_book` name/description/budgets/recursion/extensions whenever the build source carries metadata; a legacy pure-entry source reports that metadata cannot be checked rather than claiming coverage.
- For production enrichment, three **different** blocking warning rule IDs fail delivery. Three repetitions of one root cause remain warnings so templates are not over-counted.

## Optional sibling capabilities

Preset and native-stage checks are optional capabilities, not implicit installed dependencies. When a user selects one of those delivery branches but the sibling script is missing, `final_delivery_gate.py` returns a named `CAPABILITY_MISSING` delivery failure rather than an internal error.
