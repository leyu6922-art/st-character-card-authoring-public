# 首次生成太薄的根因分析与扩充工作流

## 问题根因

首次生成79KB/22条目时，用户反馈"太薄了，人物设定不够完全，人物关系不明朗，场景也很粗糙，玩法不明显"。

根因分析：
1. **角色条目只有200-500字**，只写了基本档案没有行为模板和对话示例
2. **"配角群像"合并条目**，5个角色挤在1346字里，每个角色只有250字
3. **场景条目太粗糙**，"场景：杜龙打屁股"只有300字，没有完整的感官描写链
4. **缺少玩法系统**，没有堕落度/控制等级/阶段解锁等可玩性条目
5. **缺少关系矩阵**，角色之间的凌辱偏好和互动模式没有明确
6. **缺少对话示例库**，原文1833条对话中只引用了极少部分

## 扩充到150KB的工作流

当首次生成不达标或用户要求"加厚"时，按以下流程操作：

### 第一步：诊断（读取现有卡，列出不足）
```python
with open(path, 'r', encoding='utf-8') as f:
    card = json.load(f)
entries = card['data']['character_book']['entries']
for e in entries:
    print(f"[{e['id']}] {e['comment']}: {len(e['content'])}字 {'常驻' if e['constant'] else '触发'}")
```
检查项：
- 角色条目是否 < 1500字？→ 需要扩充
- 是否有合并条目（如"配角群像"）？→ 需要拆分
- 是否有场景条目 < 500字？→ 需要扩充感官描写
- 是否缺少玩法系统？→ 需要新增
- 是否缺少关系矩阵？→ 需要新增

### 第二步：扩充角色条目
1. 重新读取原文，提取每个角色的对话（至少5句）
2. 为每个角色写行为模板（至少2个场景的完整行为链）
3. 扩充外貌描写（从原文提取具体描写，不要用"身材好"这种概括）
4. 添加身体反应模式（被凌辱时的具体反应链）

### 第三步：拆分合并条目
- "配角群像" → 每个配角独立条目
- "场景库" → 每个场景独立条目（打屁股/巨乳乳交/丝袜足交/一字马/口交深喉/直播/当马骑各自独立）

### 第四步：新增系统条目
必备系统条目（大型卡）：
1. 关系矩阵 + 控制系统详解
2. 堕落度/好感度系统（阶段划分 + 触发条件）
3. 场景感官描写模板（按场景分类的描写库）
4. 对话示例库（按角色分类的原文对话）
5. 外貌描写库（按角色分类的身体/穿着描写）
6. 环境氛围库（场景环境 + 五感描写）
7. 关键道具象征系统
8. 禁忌规则与底线保护

### 第五步：验证
运行 validate_card.py，确认文件大小和token负载达标。

## 扩充后合并重复条目工作流

扩充时会产生大量"原始+扩充"条目对（如id=3恶魔相机+id=132恶魔相机·扩充）。这些必须合并，否则token浪费严重。

### 触发条件
扩充完成后条目中有"·扩充"或"·扩充版"后缀的条目。

### 合并步骤

1. **扫描所有条目**，按关键词分组（角色D/角色A/厉红霞/场景/NSFW等）
2. **识别"原始+扩充"对**：相同主题 + 一个有"扩充"后缀
3. **处理链式合并**：如59→76→130（赎罪循环→赎罪循环·扩充→赎罪循环·扩充），全部合并到id=59
4. **执行合并**：将扩充内容追加到原始条目，用`━━━ {扩充条目名} ━━━`分隔
5. **删除扩充条目**
6. **验证**：确认无残留"扩充"条目

### 合并脚本模板

```python
# 定义合并对: (原始id, 扩充id)
merge_pairs = [
    (3, 132),    # 恶魔相机使用指南
    (19, 106),   # 噩梦/炼狱/冤魂系统
    # ...更多对
]

# 处理链式合并 (A→B→C 全部合并到A)
merge_plan = {}
for orig, exp in merge_pairs:
    if orig not in merge_plan:
        merge_plan[orig] = []
    merge_plan[orig].append(exp)

# 执行
for orig_id, exp_ids in merge_plan.items():
    orig = by_id[orig_id]
    for exp_id in exp_ids:
        exp = by_id[exp_id]
        orig['content'] += f"\n\n━━━ {exp.get('comment','')} ━━━\n\n" + exp['content']

# 删除扩充条目
entries = [e for e in entries if e['id'] not in all_expanded]
```

|------|--------|--------|------|
| 条目数 | 132 | 88 | -44(-33%) |
| 文件大小 | 601.7KB | 550.9KB | -50.8KB(-8%) |
| 残留"扩充"条目 | 42 | 0 | ✅ |

合并后平均条目深度从~1200字提升到~1655字（因为扩充内容融入原始条目）。

## 质检→评估→实装循环

当质检报告产生多条优化建议时，按以下流程处理：

### 步骤1: 评估完成状态
对每条建议，检查当前卡是否已覆盖：
- ✅ 已完成：有对应条目且内容充分
- ⚠️ 部分完成：有框架但缺详细内容
- 📋 待实装：完全没有

### 步骤2: 必要性判断
不是所有建议都需要完成。判断标准：
- 🔴 关键级：缺失会导致世界观重大缺失或系统逻辑矛盾 → 必须做
- 🟡 重要级：影响深度和可玩性 → 评估性价比后决定
- 🟢 优化级：锦上添花 → 低优先级，卡可运行后再说

### 步骤3: 优先级排序
推荐顺序：系统完整性 > 世界观补全 > 角色深度 > NSFW细节 > 待实装角色

### 步骤4: 逐条实现
每次只做1-2条最高优先级的，做完验证再继续。

### 示例玄幻项目实测

10条建议的处理结果：
- 5/10 已完成（天道种子/脚本/变量/龙琪儿/王启）
- 4/10 部分完成（条目深度/NSFW/天命事件链/Phase3）
- 1/10 待实装（祝青萱/胧月素子）

最高ROI的单项：建议2（巫帝烛龙+姬轩辕暗线）— 做完后建议8（天命事件链）自然补全。

## 原作素材提取→条目构建

当需要为世界观/角色补充详细设定时，从小说原文中提取：

### 方法
```python
# 1. 确定目标章节（通常ch10-12是后期世界观揭露）
# 2. 搜索关键词
keywords = ['烛龙', '姬轩辕', '玄女', '太一', '天道种子']

for fname in target_chapters:
    with open(path, 'r', encoding='utf-8') as f:
        content = f.read()
    for kw in keywords:
        idx = content.find(kw)
        if idx != -1:
            snippet = content[max(0,idx-80):idx+250]
            # 提取场景和台词
```

### 提取内容分类
- **台词**：直接引用原作对话，标注章节出处
- **场景描写**：提取完整的感官描写段落
- **设定细节**：外貌/能力/关系/历史的具体描述
- **行为模式**：角色在不同情境下的具体反应

### 写入条目的格式
```
━━━ {角色/系统名}·详细设定（原作第X章）━━━

【身份】一句话定义
【外貌】从原作提取的具体描写（不是概括）
【性格】关键特征 + 原作对话佐证
【能力】具体机制 + 原作描写
【台词库（原作第X章）】
• "台词1"
• "台词2"
```
