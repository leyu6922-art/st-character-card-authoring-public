### T58: execute_code写入条目内容实际字数远低于预期（2026-07-13·示例G型卡世家G型卡实证）

**症状**：Agent在execute_code中写了看起来很长的content字符串（如妹妹基础档案写了约2000字），但JSON保存后回读发现实际只有642中文字。多个条目都出现同样问题——写入时"感觉很长"但实际只有目标的30-50%。

**根因**：execute_code块中的Python字符串变量，在被make_entry()函数处理后可能丢失内容（如clean_forbidden()替换后、字符串拼接问题），或者agent在execute_code上下文中倾向于写更精简的内容。具体机制不明，但**结果一致**：连续多个execute_code批次的条目都偏薄。

**铁律**：
1. **每次execute_code写入条目后，立即回读JSON验证实际字数** — 不信任变量中的"感觉长度"
2. 用 `sum(1 for c in content if '\u4e00' <= c <= '\u9fff')` 统计中文字数
3. 不达标（<目标字数的80%）→ **当场在同一execute_code中扩写**，不存入"待扩充"队列
4. 目标字数：角色条目≥2000中文字、场景≥800字、事件种子≥150字

**验证模板**（每个批次写入后立即运行）：
```python
import json
with open('/tmp/phaseN.json', 'r', encoding='utf-8') as f:
    entries = json.load(f)
for e in entries:
    cn = sum(1 for c in e.get('content','') if '\u4e00' <= c <= '\u9fff')
    if cn < 500:
        print(f"❌ ID{e['id']} [{e.get('comment','')[:20]}]: {cn}字 — 需扩充!")
```
