### T76: first_mes泛词连锁触发（2026-07-15·周雨晴卡实证）

**症状**：validate_card或手动审计发现first_mes触发大量条目（12条/4960字），token负载暴涨。条目keys使用了first_mes场景描写中的常见词（"客厅""身体""堕落""日常""沐浴""味道""体香""反应"等），首轮全部命中。

**根因**：first_mes是场景描写，自然会包含大量环境/人物/动作词汇。如果条目keys直接用这些词，first_mes一加载就会触发几乎所有条目。

**修复**：keys不能用first_mes场景中的常见词。改用场景专属短语：
| 原泛key | 改为 |
|---------|------|
| `客厅` | `沙发上偷摸` / `客厅偷偷` |
| `身体` | `敏感点` / `敏感带` |
| `堕落` / `堕落度` | `堕落进度` / `关系阶段` |
| `日常` | `叙事节奏模板` |
| `沐浴` | `浴室play` / `一起洗澡` |
| `味道` / `体香` | `雨晴气味` / `体香记忆` |
| `反应` | `大腿内侧` / `敏感带` |
| `关系` | `关系矩阵` / `角色互动` |
| `内心` | `内心独白` / `雨晴心理` |

**验证**：`[k for k in entry.keys if k in first_mes]` 为空 = 安全。周雨晴卡实测：12条→3条，4960字→1161字。

**铁律**：每张卡构建完成后，必须检查每个条目的keys是否与first_mes中的高频词重叠。重叠条目>5个 = 必须优化。

### T77: greeting双版本拼接+重复氛围句填充（2026-07-15·周雨晴卡实证）

**症状**：每个alternate_greetings内部有两种重复模式：
1. **双版本拼接**：同一场景写了两个版本（A版简短+B版详细），中间用空行分隔，B版末尾还有重复填充句
2. **重复氛围句**：场景结尾的环境描写句被复制粘贴7-11次作为填充（T48的变体）

**诊断**：
```python
line_counts = {}
for line in text.split('\n'):
    s = line.strip()
    if len(s) > 15:
        line_counts[s] = line_counts.get(s, 0) + 1
dups = {s: c for s, c in line_counts.items() if c > 1}
```

**修复分两层**：
1. **双版本拼接**：识别重复场景起始行（同句出现2次且行号差>5）→删除第二版本（含其重复填充）
2. **重复氛围句**：smart_dedup（保留首次出现，删除后续重复）

```python
def smart_dedup(text):
    lines = text.split('\n')
    seen = set()
    cleaned = []
    for line in lines:
        s = line.strip()
        if len(s) > 15 and s in seen:
            continue
        if s:
            seen.add(s)
        cleaned.append(line)
    return '\n'.join(cleaned)
```

**清理后必须≥1400字**→用新感官/心理/互动内容补写，禁止再用重复句填充。

**铁律**：每个greeting构建后必须跑重复句检测。零重复是硬性要求。

### T78: 跨窗口审查报告的处理流程（2026-07-15·周雨晴卡实证）

**场景**：用户从另一个Hermes窗口独立审查同一张卡，给出修正报告。报告大方向正确但有几处需要修正。

**典型修正模式**：
1. **token影响表述夸大**：如"7个greeting同时占prompt"——实际只有玩家选择的1个进chat history
2. **复合关键词违反T70**：建议"胸部描写库""后背位详解"等死key→条目永远不触发
3. **常驻条目数偏高**：建议9条但实际该卡类型5-7条就够
4. **修复顺序错**：建议先加厚再修结构→加厚加剧token爆炸

**处理流程**：
1. 逐条核验修正报告（不盲从，不忽略）
2. 确认正确的发现，标注哪些已验证
3. 修正错误/夸大的部分，给出修正理由
4. 合并形成最终修复方案
5. **修复顺序铁律**：结构字段→greeting去重→常驻瘦身→触发key分层→validate→再考虑加厚

**铁律**："先加厚再修结构"会适得其反。token空间不足时加厚只会加剧截断。

### T79: trigger key分层设计（2026-07-15·周雨晴卡实证）

**问题**：18组关键词重叠（如"胸部"命中3条、"体位"命中3条、"危险"命中2条），导致一个关键词连锁触发多条无关条目。

**分层策略**：
- **轻量场景条目**（场景触发）：用自然但具体的词。如"乳交""后背位""学校厕所""差点被发现"
- **深度档案条目**（描写库/体位详解）：用专属标签。如"周雨晴视觉描写""体位描写库""女仆play台词"

| 泛关键词 | 轻量触发改法 | 深度档案改法 |
|---------|------------|------------|
| 胸部 | 乳交 / 用胸 / 胸口压住 | 周雨晴胸部描写库 |
| 体位 | 后背位 / 骑乘 / 面对面做 | 体位描写库 |
| 危险 | 差点被发现 / 门外脚步声 | 家庭暴露风险规则 |

| 父母 | 爸妈在客厅 / 妈妈上楼 | 父母角色设定 |

**验证**：检查所有触发条目的keys是否存在重叠。目标：零重叠。周雨晴卡实测：18组→0组。

**铁律**：关键词重叠数必须归零。一个关键词只应命中一条条目。
