# 触发质量 vs 裸 Token 负载

> 来源：2026-07-15 对比大型结构化卡 v4.2、萧谴写卡助手 V4.5.1、校园示例卡守护 v2、示例G型卡 G v2、小西 G、示例关系卡 G 的触发审计。

## 核心结论

卡顿/截断/空回不能只看文件大小、世界书总字符、首轮请求体大小。更关键的是：

1. 首轮到底触发了哪些条目；
2. 触发条目是否与当前场景相关；
3. `secondary_keys` 是否真的生效；
4. 是否存在普通句也会触发的泛 key；
5. 输入内容是结构化协议，还是高密度叙事素材；
6. 模型每轮被要求输出多少东西（状态栏、旁白、多 NPC、反顺从、阶段推进等）。

大型结构化卡首轮可达 7 万+字符常驻仍流畅，是因为它的大多是结构化协议/变量/数值表/生成规则；我们的卡 1.5～2.5 万字符也可能卡，是因为常把人物深度档案、NTR关系、场景、状态栏、旁白、NPC行为和反顺从一起拉入 prompt，并要求模型生成高密度剧情。

## 对比样本

| 卡 | 文件大小 | 条目 | enabled常驻 | first_mes触发非常驻 | 首轮注入字符 | 关键现象 |
|---|---:|---:|---:|---:|---:|---|
| 大型结构化卡 v4.2 | 2986 KB | 469 | 44 | 0 | 72,431 | 大，但首轮只加载结构化常驻协议 |
| 萧谴写卡助手 V4.5.1 | 739 KB | 19 | 2 | 0 | 3,647 | 大条目全部由明确命令触发 |
| 校园示例卡守护 v2 | 214 KB | 38 | 7 | 8 | 20,130 | first_mes 拉起多个人物/威胁档案+场景 |
| 示例G型卡 G v2 | 280 KB | 51 | 11 | 9 | 22,561 | secondary 被忽略，泛 key 误触发 |
| 小西 G | 166 KB | 39 | 8 | 13 | 16,132 | `家/学校/教室` 普通句也能触发 |
| 示例关系卡 G | 315 KB | 47 | 8 | 4 | 21,192 | 触发条数少，但单条人物档案极大 |

## 诊断顺序

修卡时不要先加厚，按以下顺序：

```text
触发审计
→ 修泛 key
→ 修 selective/secondary
→ 常驻瘦身
→ greeting 去重/降污染
→ 再考虑加厚内容
```

## 判断标准

### 好的高负载

- 触发条目高度相关；
- 内容以结构化规则/表格/协议为主；
- 输出任务稳定；
- 有 regex/MVU/summary/变量体系分担状态；
- 泛 key 反证测试不误触发。

### 坏的低负载

- 普通句能触发场景/人物条目；
- first_mes 同时拉起 5+ 深度人物档案；
- `secondary_keys` 写了但顶层 `selective=false`；
- 同一角色名触发基础档案、阶段、语料、关系线多条；
- 每轮强制输出状态栏+旁白+NPC行动+阶段推进+反顺从；
- 输入虽然少，但全是高压叙事素材。

## 修复策略

### 1. 用“速览 + 深度档案”双层

不要让角色名一出现就加载 2000～8000 字深度档案。

```text
雪乃 / 林美娟 / 纪容
→ 触发 300～600 字自足速览

雪乃档案 / 林美娟深度档案 / 纪容语料库
→ 按需触发 2000+ 字深度内容
```

速览必须自足。ST 不会因为速览里写了“请触发深度档案”就二次触发深度档案。

### 2. 场景词范围绑定

错误：

```json
{"keys": ["家", "学校", "老师", "客厅"], "selective": false}
```

正确：

```json
{"keys": ["客厅", "卧室", "浴室"], "secondary_keys": ["比企谷家"], "selective": true}
```

或更稳：

```json
{"keys": ["比企谷家客厅", "校园示例卡五楼空教室"]}
```

### 3. 不要盲目把所有条目改成复合 key

核心角色主档案如果只有 `角色名档案` 这种死 key，会变成永远不触发。正确策略是：自然名触发速览，深度档案使用专用 key。

### 4. 不要盲目给所有 secondary 开 selective=true

如果 secondary 只是备注词，开启 selective 会让条目死触发。先判断触发意图：范围绑定才开 selective；普通按需条目就清空 secondary 或保留 primary-only。

### 5. 减少每轮输出义务

很多截断来自输出侧，不是输入侧。避免每轮同时强制：状态栏、旁白、多 NPC 自主行动、阶段推进、反顺从判定、信息边界、后续钩子。常驻只保留总控，详细规则按需触发。

## 必跑工具

```bash
python scripts/audit_worldbook_triggers.py <卡文件.json> -o <触发审计报告.md>
```

关注报告中的：

- 每个 greeting 的触发条目；
- 普通句反证测试；
- `有secondary但顶层selective=false`；
- 泛 key；
- 首轮深度档案数量；
- 常驻条目数与内容性质。
