# 世界书插入位置与深度取舍指南

> 来源：吸收公开社区方法论后按本项目口径重写；未随仓库分发原始教程。
> 定位：内容应该放在提示词结构哪个位置的**决策指南**。字段级 JSON 写法见 `../formats/worldbook-entry-structure.md`；触发可达性见 `trigger-quality-vs-token-load.md`。一切以提示词查看器 / Prompt Itemization 实测为准——不同预设的包裹结构不同。

## 一、桶型结构与 U 型注意力

酒馆把提示词按「预设头部 → 预设功能提示词 → 世界书 → 聊天历史 → 用户输入 → 预设思维链/格式 → 预设底部」排成桶型。LLM 注意力呈 U 型分布：**头尾效力最强，中部最弱**。

推论：
- 最重要的内容放世界书的头和尾；"我不舍得让 AI 漏掉任何内容，全堆头部"不可行——当所有东西都是最高优先级时，最高优先级就失去了意义。
- 同为「角色定义之前」的条目，`insertion_order` 越小越靠顶部（效力高），越大越靠近中部。

## 二、三分层内容放置策略

| 内容层 | 是什么 | 放哪里 |
|---|---|---|
| 基建 | 核心玩法/叙事基调/世界基本规则（战斗、生产等） | 角色定义前，重要性越高 order 越小 |
| 背景 | 地理、势力、人际关系等"漏读了也不至于跑不下去"的设定 | 角色定义后偏中部（接受注意力较弱） |
| 人设 | 重中之重；总览概要进常驻，详情按触发 | 角色定义后、order 尽量大（靠近正文一侧） |

角色描述栏本质是「角色定义前/后之间」的一个位置，多数内容放世界书按位置和顺序管理更清晰。

## 三、动态深度 D0–D4 的取舍

- **D0**（用户输入之后）与 **D1**（用户输入之前、紧贴最新正文）效力接近甚至超过世界书顶部。适合放变动频繁的内容（对缓存友好）、格式要求、最想强调的东西；MVU 变量一般也在这里。
- **D1 比 D0 危险**：D1 夹在正文与用户输入之间，塞入大段设定会造成上下文断层，让 LLM 丢失正文积累的情绪惯性、混淆正文与用户输入。D1 只放少量格式/用户输入纠正类内容；格式要求放预设尾部效力通常更好。
- **D0 超载**（数千 token 变量）会稀释 LLM 对用户输入的注意力，需配合标签强调或复述用户输入等手段。
- **D2/D3/D4** 更容易割裂连续正文楼层，默认不推荐；出于缓存优化或插叙规则确需使用时，不要全堆同一深度。
- 同类功能的提示词放在一起，比东一块西一块对 LLM 友好得多。

## 四、本 skill 链语境标注

1. 阶段卡的常驻锚点（全程因果档案、记忆闸门）当前用 `position: before_char + depth: 4 + ignore_budget` 配置（见 `phase-memory-gate-architecture.md`），与本指南"重要常驻靠头部"的结论一致；`system_prompt` 压缩锚点承担尾部强调职责。
2. 本指南的"绿灯激活滞后一轮"告诫面向普通关键词卡；原生标题阶段卡靠 Greeting 首轮自带标题 key 规避了该问题，不构成对标题路由的质疑（同见 `../design-patterns/persona-contradiction-modeling.md` §五）。
3. 位置/深度调整属于内容组织优化，**不改变**触发语义；调整后仍须过 `audit_worldbook_triggers.py` 与交付门控，并以 ST 实机 Prompt Itemization 复核实际装载顺序。
