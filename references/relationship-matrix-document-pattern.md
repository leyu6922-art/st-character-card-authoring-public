# 关系矩阵文档模式（2026-07-19·艳母的荒唐赌约实证）

> 角色卡构建前的参考资料形态之一：多方位矩阵文档。用于系统化整理一个角色与多个其他角色之间的关系，供后续世界书条目构建直接使用。

## 适用场景

小说中核心角色（通常是女主/男主）与4+个重要角色有深度互动，需要：
- 逐角色梳理关系演变轨迹
- 提取每个关系的专属语料库（对话引用）
- 建立行为链模板（AI可直接使用）
- 对比不同角色间的关系差异

## 文档结构模板

每个核心男性角色的章节应包含以下子节（一致性很重要）：

```
### X.N 郎玉诗 × [角色名]——[关系类型标签]

#### 一、关系本质
一句话概括。

#### 二、关系演变[4-6]阶段
表格：阶段 | 章节 | 玉诗态度 | 对方态度 | 身体反应
+ 每个阶段的关键行为链（原文对话+场景描写）

#### 三、调教策略深度分析
核心理念 + N大核心手段（每手段含：名称/原文证据/效果分析）

#### 四、玉诗对该角色的行为模式
态度关键词、称呼与互动模式、在群交中的位置

#### 五、专属语料库
分类整理原文对话引用：
- 征服/命令语料
- 温柔/关心语料
- 炫耀/宣示语料
- 玉诗对该角色的回应语料

#### 六、阳具特征与玉诗反应
表格：尺寸/形状/核心能力/玉诗反应/特殊能力/玉诗评价

#### 七、行为链模板（AI可直接使用）
2-3个具体模板，格式：
[场景描述]
1. 动作/对话 → 2. 反应 → ... → 10. 结束状态
```

## 厚度标准（2026-07-19实证）

| 角色重要度 | 每角色目标字数 | 章节数 |
|-----------|-------------|--------|
| 最核心（2人） | 10,000-12,000字/人 | 7个子节全部覆盖 |
| 核心（2-3人） | 5,000-8,000字/人 | 7个子节覆盖 |
| 重要配角 | 2,000-3,000字/人 | 精简版（3-5个子节） |

总文档目标：150KB+（供后续世界书条目构建使用）

## 额外章节（按需添加）

完成四人关系章节后，可追加以下总结性章节：

1. **总结对比**：控制力排序、身体反应排序、心理反应对比、称呼系统、场景-反应交叉矩阵、语料风格对比
2. **场景级细节补充**：每人选取3-4个关键场景做逐行为链+对话+分析的深度展开
3. **深层心理学分析**：需求层次对应、控制-服从光谱、身份影响、恐惧-享受坐标、底线突破方式
4. **互动对话场景重建**：每人选取2-3个典型对话场景完整重建（含分析）
5. **不可替代性分析**：哪些角色是不可替代的，哪些是可替代的，为什么
6. **日常相处细节补充**：非调教场景下的互动细节，展示关系的"日常面"
7. **称呼与反应触发机制**：称呼→效果→生效条件→失效条件→冲突场景

## 工作流要点

1. **先读全部参考资料**（小说提取文档、章节摘要等），再开始写
2. **逐角色写**，不要一次性写全部——保证每个角色的质量
3. **原文对话引用必须精确到章节**——「对话内容」（第N章）
4. **行为链模板用编号列表**——10步左右，AI可直接执行
5. **阳具差异化**——每个男性的尺寸/形状/核心能力必须不同
6. **不要添加用户未要求的内容**——用户说"只补充关系"就只补充关系（参见T114）

## 用户范围控制教训（2026-07-19）

**错误做法**：用户要求"加厚文档，150kb以上"，我写了58KB扩展包含13个新章节（调教策略对比、行为链模板库、心理独白语料库、场景描写语料库、120章事件时间线、关系矩阵详细展开等）——用户回复"只需要补充和五个核心男性的关系就可以"。

**正确做法**：
- 当用户说"只需要补充X"时，严格只补充X
- 不要预判用户需要什么——等用户说
- 150KB是总目标，但内容范围由用户指定
- 如果只补充X就能到150KB，那就好；如果不够，再问用户是否要补充其他内容

**后续追加**：用户进一步缩小范围——"去除肖斌，只保留核心四人"。这说明用户对角色重要性有清晰的层级划分，不要假设所有提及的角色都是"核心"。
