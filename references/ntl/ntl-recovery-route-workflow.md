# NTL夺回路线卡·创建工作流

## 适用场景
从苦主版NTR卡改造为NTL夺回路线版。{{user}}仍然是苦主，但觉醒后主动夺回。

## 与NTL征服者卡的区别
| 维度 | NTL征服者卡(原型C) | NTL夺回路线卡(原型D) |
|------|-------------------|---------------------|
| {{user}}身份 | 征服者（NTR角色） | 苦主（觉醒后夺回） |
| 核心体验 | 征服快感 | 夺回热血+唤醒感动 |
| 女主状态 | 被征服/调教 | 被控制但有裂隙可唤醒 |
| NTR角色 | {{user}}就是NTR角色 | 需要击败的对手 |
| 审核重点 | 苦主视角残留 | 苦主体验反转正确性 |

## 核心系统设计

### 1. 预知天赋升级（三阶段）
- Phase 1·碎片预知（被动，模糊画面，精神疲劳）
- Phase 2·定向预知（主动，清晰画面，精神力消耗大）
- Phase 3·命运干涉（预知未来3步+临时战力提升，预知反噬）

### 2. 唤醒系统
- 每个女主独立唤醒值(0-100)
- 5阶段：沉睡→微醒→半醒→觉醒→完全唤醒
- 5种唤醒手段（回忆/预知/战斗/牺牲/反向控制）
- 堕落反弹机制（NTR角色反击会降低唤醒值）
- 裂隙机制（每个堕落阶段有真实自我残留）

### 3. 三层叠加阻力
- 第一层：NTR角色强大（各NTR角色有独立弱点系统）
- 第二层：女主堕落深（阶段越深唤醒越难）
- 第三层：女主对{{user}}爱得不够深（每条线唤醒难度不同）

### 4. 反转苦主体验系统
- 击败NTR角色后可施加苦主体验（贞操锁/雌堕药剂/狗链等）
- 每种道具有获取方式+效果+持续时间+限制
- 过度使用触发双败结局

### 5. 多结局
- Golden End：4女全唤醒+NTR全击败
- Normal End：部分唤醒
- Bad End：原版苦主结局
- True End：双败（赢了战斗输了人心）

## 子代理并行修改模式

大型卡(40+条目)改造时，用3个并行子代理：
- Batch 1：全局规则+伯里档案+first_mes+元数据
- Batch 2：苦主体验+防拒绝+NPC系统+剧情推进
- Batch 3：全部新条目(唤醒/状态栏/剧情树/道具/随机事件/结局/对话)

**关键要求**：每个子代理必须输出完整JSON数组，格式为：
```json
[{"id":0, "comment":"...", "keys":[], "content":"...", "constant":true, "enabled":true, "selective":false, "position":"before_char", "use_regex":true}]
```

**子代理输出后必须验证**：
1. JSON格式有效
2. 字数达标（每条条目按规划书目标±20%）
3. constant条目keys=[]（互斥！）

## 合并后必跑检查

```python
# 合并脚本核心逻辑
import copy, json

# 1. 从原版复制完整extensions模板
template_ext = original_entry.get('extensions', {}).copy()

# 2. 新条目补全extensions+addMemo
for e in new_entries:
    e['extensions'] = copy.deepcopy(template_ext)
    e['extensions']['position'] = 0 if e.get('position') == 'before_char' else 4
    e['addMemo'] = True
    e['extensions']['display_index'] = e['id']

# 3. constant条目强制keys=[]
for e in entries:
    if e.get('constant'):
        e['keys'] = []

# 4. 禁用被替代的条目（如原版状态栏被NTL版替代）
for e in entries:
    if e['id'] == OLD_STATUS_BAR_ID:
        e['enabled'] = False
```

## validate_card.py关键阈值
- first_mes: ≥1400字
- alternate_greetings: 每条≥1400字
- 常驻条目: 必须keys=[]
- extensions: 必须有≥10个字段+addMemo
- position: before_char→ext.position=0, after_char→ext.position=4
- enabled=false: 会被报error（设计选择需记录）

## 场景特殊玩法系统（2026-07-11异世界卡验证）

NTL版的核心爽点"用预知天赋帮女主赢"需要**具体的玩法事件**来承载，不能只是背景板。

### 设计原则
每个主要场景（赌场/练武场/领主府/兽人营地等）都需要：
1. **为什么来？** — 每个女主的真实动机（不是"自愿被NTR"）
2. **玩法规则** — 1D4/1D6随机的赌法/切磋/宴会/试炼规则
3. **NTR升级链** — Level 0→6，从原著提炼的完整征服过程
4. **NTL切入点** — 5种伯里可以用预知天赋干预的方式
5. **玩法效果** — 赢/输/帮赢/揭穿对唤醒值/堕落值/控制力的影响

### 示例：赌场赌局系统
- **动机**：妮丝想赚钱买法杖→被热闹吸引→第一次小赢→上瘾→越输越多
- **赌法库(1D6)**：骰子猜大小/扑克比点/轮盘赌/石头剪刀布赌注升级/酒桌赌局/角斗赌局
- **NTR升级链(妮丝线)**：
  L0 门口被摸臀→"他们好壮" → L1 初次小赢上瘾 → L2 越输越多
  → L3 脱衣抵债(外→内) → L4 VIP邀请 → L5 黑巨根征服 → L6 主动来赌场
- **NTL切入点**：①预知骰子结果帮妮丝押 ②揭穿千术 ③替上场赌 ④在脱到最后一层前赶到 ⑤收集赌场非法证据
- **玩法效果**：女主赢→唤醒+5/堕落-5/控制力-10 | 伯里帮赢→唤醒+15 | 伯里揭穿→控制力-20但NTR报复+50%

### 场景玩法条目设计
建议放在独立条目(ID 40+)，selective+关键词触发（赌局/切磋/宴会/试炼等）。
content包含：4个场景×(玩法规则+NTR升级链+NTL切入点+效果数值)。
典型长度：3000-6000字。

## first_mes token负载注意
原版卡如果first_mes提到所有角色名，会触发全部选择性角色条目。NTL版增加3条常驻系统条目(~1674tok)会进一步增加负载。
- 原版典型负载: ~14000tok
- NTL版典型负载: ~16000tok
- validate_card.py阈值: 8000tok(error)/5000tok(warning)
- 结论: 大型卡几乎必然超标，属于已知结构性问题
