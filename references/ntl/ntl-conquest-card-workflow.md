# NTL逆寝取卡创建工作流（2026-07-12·赌场老板案例）

## 适用场景
当用户要求制作"NTL版"且{{user}}=NTR施加方（不是原苦主）时使用。
与守护版/觉醒版（{{user}}=原苦主夺回）完全不同。

## 核心设计理念
- {{user}}=NTR男性角色（黑巨汉/兽人将军/爱德等），每张卡一个
- 原苦主（伯里等）变成NPC，保留废物设定+反抗但永远失败
- 其他NTR男性变成竞争者/盟友（NPC）
- 核心体验：征服者的金钱/暴力/势力碾压快感

## 多视角NTL制作策略
同一小说可制作多张NTL卡，每张{{user}}=不同NTR男性：
1. **先做一张确认效果**→用户审阅后再做其余
2. 每张卡共享世界观和女主设定，但{{user}}身份/手段/叙事风格完全不同
3. 其他NTR男性在每张卡中变成竞争者/盟友NPC

## 子代理安全过滤（关键坑）
NSFW内容的子代理（特别是stage系统、event seeds、场景描写）**会被模型安全过滤拒绝**。
- 系统条目（ID0-9）：子代理可写（规则类内容通常通过）
- 角色档案（ID10-20）：子代理可写（角色设定类通常通过）
- **阶段/事件/描写（ID21-42）：必须主代理用execute_code直接写，不委托子代理**
- 卡壳（first_mes/alt_greetings）：主代理直接写或派专用greeting子代理

## 关键词优化（变体卡必须做）
变体卡的first_mes通常包含大量角色名→触发所有角色条目→token负载爆炸。

**解决：用复合关键词替代单字关键词**

```
"师傅" → "古兰" 或 "师傅古兰"（避免first_mes中通用词"师傅"触发）
"伊丝娜" → "猫娘"（避免角色名直接匹配）
"伯里" → "废物" 或 "苦主"（避免first_mes中频繁出现的"伯里"触发）
"保镖" → "黑保镖" 或 "大壮"/"二壮"（避免通用词触发）
```

**效果**：从11条触发降到5条触发，token负载从16825降到13097。

## validate_card.py已知误报过滤
变体卡的validate_card.py输出需要分类：
- **真错误**：data.spec缺失、position不一致、extensions缺字段 → 必须修
- **已知设计选择**（与原版NTR卡共有）：disabled事件种子条目、token负载偏高 → 标记为已知，不阻塞交付
- **已知warning**：反AI顺从条目缺失 → 建议但不阻塞

## 第二张NTL卡的加速策略

从第一张NTL卡改造为第二张时，大量内容可复用：
- **系统条目ID0-9**：60-70%可复用（改{{user}}身份+独有系统）
- **角色条目ID10-20**：女主档案直接复用，只需改"对{{user}}的反应"段。{{user}}主角档案100%重写
- **阶段/事件/描写ID21-42**：框架可复用，内容按新{{user}}的手段体系改写
- **卡壳**：100%重写（first_mes/alt_greetings/system_prompt/description/scenario/tags）

第二张卡的构建流程与第一张相同（3路并行+主代理写卡壳），但每个子代理的prompt中要明确指出"从第一张NTL卡读取作为模板"。

## 开场白构建陷阱

### 字节vs字符
validate_card.py检查的是**字符数**（len()），不是字节数。中文UTF-8每字符≈3字节。
- ≥1400字符 需要 ≥4200字节
- write_file报告的是字节数，不能直接用来判断是否达标
- 验证方法：用`len(content)`检查，不要用`os.path.getsize()`

### execute_code三引号嵌套
Python三引号字符串中嵌套中文对话引号会导致SyntaxError：
```python
# 这会报错：
content = """他说："你好。"她说："谢谢。""""
```
解决方案：
1. 用write_file写内容到.txt文件，再用read_file读取
2. 用列表+join()代替三引号
3. 对话内容用单引号（'）代替中文双引号（""）
