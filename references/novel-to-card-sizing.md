# 小说→角色卡 预估分析流程

在正式写卡前，先用此流程预估卡的规模，避免做大了膨胀或做小了遗漏。

## 第一步：抓取+基础数据

1. 抓取全部章节到本地（参考 web-novel-scraper skill）
2. 统计：总章节数、实际总字数（alicesw 标称字数常虚标 1.5-2x，以实际提取为准）
3. 按卷/阶段划分章节区间

## 第二步：角色出场频次扫描

用正则扫描全部文本中每个角色名的出现次数，识别：
- 核心女主（出场300+次 → 需要最厚的条目）
- 重要配角（100-300次 → 中等厚度）
- 边缘角色（50-100次 → 轻量条目或合并）
- 路人级（<50次 → 考虑是否入卡）

```python
import os, re
from collections import Counter

d = "/path/to/novel_chapters"
all_text = ""
for f in sorted(os.listdir(d)):
    with open(os.path.join(d, f), encoding='utf-8') as fh:
        all_text += fh.read()

# 已知角色名列表（从阅读中提取）
known_chars = {"角色A": 0, "角色B": 0, ...}
for name in known_chars:
    known_chars[name] = len(re.findall(name, all_text))

for name, count in sorted(known_chars.items(), key=lambda x: -x[1]):
    print(f"  {name}: {count}次")
```

## 第三步：剧情结构分析

阅读首章、中间转折章、末章，提取：
- 叙述视角（第一人称苦主 / 第三人称上帝 / 多视角）
- 剧情阶段数（如：发现期→沉沦期→扩展期→终局）
- 每阶段的核心场景和新引入角色
- 主题标签（公厕化/会所/直播/催眠/洗脑等）

## 第四步：对标已有卡的基准

| 参考基准 | 小说字数 | 角色数 | 条目数 | 大小 |
|---------|---------|--------|--------|------|
| 交配学校 | 4.7万 | 7 | 25 | 108KB |
| 示例角色项目 | 10.8万 | ~6 | 33 | 149KB |
| 圣馨医院 | 9万 | ~8 | 40 | 210KB |
| 堕绿仙家 | 16.3万 | ~8 | 43 | ~200KB |
| 抵受不住亲姐姐 | 长篇108章 | ~8 | 68 | 222KB |
| 人妻妈妈娼馆 | 23万 | ~8 | 45 | 182KB |
| 逆转贞操观 | 22万 | 15 | 48 | 249KB |

关键规律：
- **条目数主要取决于角色数量**，不是小说字数
- **单条目大小取决于素材密度**（原文越长，对话引用和行为模板越丰富）
- **世界观复杂度是隐形变量**（仙侠体系 >> 现代都市）
- 小说字数 → 影响单条目素材丰富度；角色数量 → 决定条目总数
- 角色数量的权重高于字数
- **短篇小说（<5万字）的卡大小主要受条目数驱动**：47K字+7角色→25条→108KB（条目结构开销占比高），而不是内容字数驱动。短篇卡的每个条目必须更充实（从原文提取对话+行为模板），否则总内容字数不够撑起条目
- **15+角色的卡需要更多条目**：逆转贞操观15角色→48条→249KB，比同字数的8角色卡（45条/182KB）更大，因为每个角色需要独立条目

## 第五步：内容预算规划（关键！必须在构建前完成）

目标文件大小确定后，先计算内容预算，避免"初始太薄→多轮扩充"的低效循环：

```
条目结构开销 = 条目数 × 1.8KB（31字段extensions）
其他JSON开销 ≈ 12KB（顶层字段+system_prompt+description等）
内容字节预算 = (目标KB × 1024 - 条目结构开销 - 其他JSON开销)
每条目平均内容字数 = 内容字节预算 / 条目数 / 3 bytes/char
```

示例（目标260KB/48条目）：
- 结构开销：48 × 1.8KB = 86.4KB
- 其他JSON：12KB
- 内容预算：(260 - 86.4 - 12) × 1024 / 3 ≈ 55,000字
- 每条目平均：55,000 / 48 ≈ 1,146字

⚠️ 实测教训（逆转贞操观案例）：初始构建时条目平均500-800字→文件仅111KB→需要4轮扩充到249KB。正确做法：首次构建时角色条目目标1500-2000字，系统条目800-1200字，开场白1500字/个。

## 第六步：输出预估

综合以上分析，给出：
1. 预估条目数范围（如 55-65 条）
2. 预估大小范围（如 200-260KB）
3. 最接近的参考卡（如"接近人妻妈妈娼馆"）
4. 卡的特殊挑战（如"女主一人撑1249次提及，需要极厚的行为模板条目"）
5. 内容预算（每条目平均字数×条目数=总内容字数）

## 第七步：确定{{user}}视角和小说原型

在条目设计之前，必须确定{{user}}身份和小说原型类型。参考 `references/novel-archetype-patterns.md`：

| 小说类型 | 推荐{{user}} | 理由 |
|----------|-------------|------|
| 系统/后宫流 | 男主/征服者 | 系统绑定在男主身上 |
| 纯NTR | 苦主/被绿者 | 情感体验在"发现真相"的痛苦 |
| 征服者视角NTR | 征服者 | 用户享受"绿别人"的快感 |
| 禁忌/乱伦 | 家庭成员之一 | 根据核心关系决定 |
| 多视角群像 | 上帝视角 | AI扮演所有人 |

**决策关键**：系统/能力绑定在谁身上？→ {{user}} = 那个人

原型选择决定了模板组合、条目架构和开场白设计，必须在规划书阶段确定。

## 案例：新婚妻子-NTR

- 29章/4卷/26.5万字
- 核心女主芷姗1249次，5女性+5男性+丈夫
- 现代都市无复杂世界观，但场景密度高（公厕/会所/网站/公司/公园）
- 预估：55-65条/200-260KB，接近人妻妈妈娼馆但芷姗条目更厚

## 案例：逆转贞操观

- 61章/22.2万字，15角色（核心8+重要3+配角4）
- 后宫/贞操观逆转/伪娘，现代都市
- 9个P0模板采用，独特机制：药剂体系/VR洗脑/贞操带/堕落三阶段/百人斩进度
- 最终：48条目/249KB/6开场白
- 教训：初始条目太薄（500-800字）→4轮扩充→应从一开始就按预算规划内容量
