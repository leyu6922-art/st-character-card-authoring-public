# 手动选开身份模式（G型子选择）

> **状态**：2026-07-13 · 生产级卡片已在使用此模式（催眠NTR卡，30条目）
> **定位**：G型多视角内置卡的**触发机制子选择**——保留双层世界书架构，视角段启用方式从 greeting 驱动切换为手动条目开关

---

## 一、原理

```
世界书中有 N 条身份条目，全部 constant=true, enabled=false
  ↓
玩家在 ST 世界书 UI 中手动启用一条（如启用「苦主」条目）
  ↓
条目内容注入 prompt → {{user}} 成为该身份 → AI 按该身份叙事
  ↓
想切换？禁用当前身份，启用另一条 → 下一轮 {{user}} 就变了
```

**零依赖**：不依赖 greeting 关键词、不依赖 selective AND 逻辑、不依赖 ST 扫描机制。只依赖 ST 世界书 UI 的 enable/disable 开关。

---

## 二、条目结构

```json
{
  "id": 3,
  "comment": "龟龟{{user}}（选开）",
  "constant": true,       // ← 常驻条目，但...
  "enabled": false,       // ← 默认关闭，玩家手动开启
  "keys": ["{{user}}", "你", "夏星"],
  "position": "after_char",
  "content": "{{user}}是夏星，20岁...（角色定义）"
}
```

**与 G 型 greeting 模式的关键差异**：
- `constant: true`（不是 `selective: true`）
- `enabled: false`（不是 `enabled: true` + 依赖关键词触发）
- `keys` 可以非空（玩家手动启用后，keys 中的角色名不会误触发其他条目——ST 中 `enabled=false` 时 keys 不参与扫描）
- **不需要** `secondary_keys`、`selective` 等字段

---

## 三、适用场景

| 场景 | 选开模式 | greeting 模式 |
|------|:--:|:--:|
| 玩家需要在**同一会话中**切换身份 | ✅ | ❌ |
| 想自己开局（不需要手动输入关键词） | ✅ | ❌ |
| 不想让玩家手动操作世界书 UI | ❌ | ✅ |
| 简单、"选择 greeting 即选择身份"的体验 | ❌ 过度 | ✅ |
| 2-3 个固定身份、不需要中途切换 | 可用 | 更简单 |

## 四、构建规则

### 4.1 身份条目

```python
# 每个身份一条 constant + enabled=false 条目
{
    "constant": True,
    "enabled": False,        # 玩家手动开启
    "keys": ["{{user}}", "角色名", "你"],  # 可以带 keys
    "position": "after_char", # 或 before_char（角色定义通常放前面）
    "comment": "XXX{{user}}（选开）",  # "选开"标注方便玩家识别
    "content": "{{user}}是XXX...（完整角色档案+行为规则+叙事视角）"
}
```

### 4.2 共用层

和 greeting 模式完全一致：零 `{{user}}`，用具体角色名。角色/场景/事件条目 `constant=false, enabled=true`。

### 4.3 交付说明

必须告知用户：
```
1. 导入卡后打开ST世界书UI
2. 找到标注「选开」的身份条目（comment含"选开"）
3. 启用你想要扮演的身份（点击开关）
4. 所有标注「选开」的条目一次只启用一条
5. 想切换身份：禁用当前，启用新身份 → 下一轮生效
```

#### 🆕 选开模式的 greeting 必须是视角中性的

**设计坑**：如果选开条目定义 `{{user}}`=李明（苦主），但 greeting 写的是"你从背后搂住她的腰"（麦克的行为）→ 角色冲突。选开条目加载后覆盖了 `{{user}}` 定义，但 greeting 文本中的场景和叙事视角不会跟着变。

**规则**：选开模式的 greeting 不预设 `{{user}}` 的具体身份：
- ✅ 写：场景描写、NPC 位置、环境氛围、发生的客观事件
- ❌ 不写：`{{user}}` 的内心独白、身份绑定的行为（"你无力地握紧拳头" vs "你自信地搂住她的腰"）、视角化的情感反应

**理念**：这和 G 型共用层的哲学一致——greeting 也是共用层的一部分。让选开条目定义"你是谁"，让 greeting 只负责"你在哪，周围有谁"。

**示例（中性 greeting）**：
```
南山别墅的客厅，夜色已深。林美娟坐在沙发上，手机屏幕的冷光映着她的脸。
她的表情复杂——疲惫、愧疚、还有某种你读不懂的情绪。茶几上放着两杯没动过的茶。

她抬起头，看到你，嘴唇动了动，似乎想说什么，但最终只是叹了口气。
```

这条 greeting 无论 {{user}} 是苦主李明（妻子背叛）还是麦克（征服后的事后），都能自然衔接——因为不预设 {{user}} 的立场和反应。

## 五、与 greeting 模式的关系

两种模式**共享 G 型核心架构**：
- ✅ 共用层：双层世界书，零 `{{user}}`
- ✅ 视角层：每个身份有独立定义条目
- ✅ 一卡替代多卡

**仅触发机制不同**：
- Greeting 模式：`selective=true` + secondary_keys 匹配
- 选开模式：`constant=true` + `enabled=false` 手动开关

**构建时选择**：agent 在 §3.3b 构建阶段问自己："玩家需要中途切换身份吗？→ 是 → 选开模式"

---

## 六、简化方案（最少改动）

如果不想完整实现选开模式的结构化条目，可以走**极简路线**：

```
1. 共用层不变
2. 不做专门的"选开"身份条目
3. 直接把 greeting 模式的视角段从 selective 改为 constant + enabled=false
4. 玩家在 ST 中手动 toggle
```

这样构建工作量最小——现有的 G 型 greeting 模式卡片只需把视角段条目的 `selective` 改为 `constant`、`enabled` 改为 `false`、删掉 `secondary_keys`，就变成了选开模式。
