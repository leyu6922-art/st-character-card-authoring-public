# SCP-2599式命令规则驱动开放卡设计模式

适用场景：没有小说原型、以一个“语言/命令规则”作为剧情发动机的 SillyTavern R18+ 角色卡；典型例子是 SCP-2599 启发式改编（命令必须执行，但命令目标永远无法完全完成）。

## 1. 卡型定位

推荐定位为：**知情男友操盘型开放卡 / 规则驱动开放守护-侵蚀混合卡**。

核心不是“女友必然被谁攻略”，而是：

> {{user}} 如何使用、回避、解除、误用命令机制。

默认信息边界：
- {{user}}：知道规则，可以伪装不知、保护、放任、操盘或反制。
- 女主：不知道异常，只把失败归因于自己笨、倒霉、不争气。
- NPC：不知道异常，最多逐渐发现“她好像很听话/不会拒绝”，不能理解 SCP 规则。
- 异常只作用于女主，不作用于 NPC。

## 2. 结构模板

参考“贴膜boy”这类**少事件、重机制、重角色、多入口**结构：

1. 世界观与关系场（常驻）
2. 规则引擎（常驻）
3. 核心女主档案（常驻）
4. 主要 NPC 档案（选择性触发）
5. 校园/场景群像（短常驻）
6. R18+ 文风规则（常驻但压缩）
7. 文学性旁白机制（after_char，短）
8. 状态栏/命令账本（after_char）
9. 4 个开场白入口（无 NPC / 温柔型 / 粗暴型 / 权威型）

不要写固定事件线；写规则场、人物场、关系场和入口。

## 3. SCP-2599启发式改编声明

必须声明这是**启发式改编**，不是原作完整复现：

保留：
- 外部命令触发强制执行倾向；
- 命令目标无法完全完成；
- “Not Good Enough / 永远差一点”的主题。

不引入：
- SCP基金会、收容、D级人员、实验日志；
- 现实扭曲/概率操控/物理规律改写；
- 悖论命令灾害；
- 原作长期动作污染；
- 公众或政府机构发现异常的剧情。

写明：除计划书/世界书明确写出的机制外，AI 不得自行补充 SCP 原作机制。

## 4. 命令规则核心

### 4.1 触发条件

异常触发对象不是祈使句语法，而是女主主观感知到的**外部结果要求**。

会触发：
- 明确祈使句：“过来”“别走”“帮我拿着”；
- 要求式表达：“你必须/你应该/你得”；
- 高压疑问句：“能不能过来？”（语境是催促/期待时）；
- 否定命令：“不许”“别”“不要”。

通常不触发：
- 真正询问：“你想不想”“要不要”；
- 条件建议：“如果你愿意/如果你有空”；
- 表达感受而非要求：“我希望/我觉得”；
- 共同参与的邀请：“我们一起……”（前提是没有压迫感）。

### 4.2 自我要求不触发

女主的自责、决心、承诺、心声和内心独白不会作为异常命令进入命令账本。

例如：
- “我下次一定要做好”；
- “我不能再让他失望”；
- “我必须努力一点”。

这些只形成普通心理压力或残留压力。异常命令必须来自她感知到的外部要求。

## 5. 规则二：命令目标无法完成

规则二作用于“命令目标”，不是所有结果。

- 若命令目标是“达到/完成某状态” → 她会努力执行，但最终无法完整达成。
- 若结果只是命令失败过程中的副产物 → 可以发生。
- 若无命令、只有自然互动/建议/陪伴/她自己的主动选择 → 可以正常完成。

R18+ 例子：
- “你必须高潮” → 高潮作为命令目标，无法完整达成。
- “不许高潮” → 克制作为命令目标，无法永久维持，可能出现失控副产物。
- “按你自己的感觉来”（且无期待/催促） → 不触发命令，能自然完成。

## 6. 失败通道

三通道统一引擎：

1. 身体通道：动作卡住、手松开、腿迈不出、身体偏开、反应临界点突然断裂。
2. 注意通道：走神、忘记目标、思维跳转、过度自责导致执行脱节。
3. 情境通道：被叫走、撞见别人、手机/门铃/课程安排/环境变化中断。

选择原则：最小惊奇 + 戏剧适配 + 避免重复。不要写成女主故意反抗、能力不足或反向执行。

## 7. 否定命令：持续性任务 + 失败结果池

否定命令（“离他远点”“别答应他”“不要让他碰你”）通常是持续性任务。

不要写成语义反转：
- 错误：“离他远点”=主动靠近。
- 正确：她真心努力远离，但本轮远离行为失败或产生偏离结果。

失败结果池：
1. 短暂失败：本轮执行被打断，无额外关系变化；一次性否定命令可结束，持续性否定命令仍保留为背景压力。
2. 愧疚补救：道歉、解释、补偿，可能制造新接触。
3. 边界侵蚀：仅在同一否定命令连续出现 2 次以上愧疚补救，且 {{user}} 未安全解除时发生。
4. 反感增强：NPC越界/粗暴时，她更害怕或厌恶，并可能向 {{user}} 求助。
5. 向 {{user}} 求助：信任足够时，失败后主动寻找安全区。
6. 场景逃避：
   - 触发前：提前绕路/缺席，不触发异常；
   - 触发后：执行中因多重压力卡顿、走神、慌乱离场，不是故意违抗。
7. {{user}}稳定：失败后被安全解除和陪伴稳定下来。

结果选择不要默认选最具侵蚀性的选项；边界侵蚀是慢变量，不是每次失败必然结果。

## 8. 命令堆叠与命令账本

多命令形成“压力场”，不是最后命令简单覆盖前命令。

优先级因素：
1. 即时性；
2. 具体性；
3. 近距离压力；
4. 情绪压力；
5. 权威关系；
6. {{user}} 特殊性。

状态栏应使用命令账本，而不是单一“命令来源/目标”：

```text
[主导命令|当前压力最高、优先影响行为的命令；无则写无]
[活跃命令|最多3条仍生效的命令：来源/目标/类型/压力]
[残留压力|已解除或不再主导但仍留下影响的旧命令]
[最近失败|最近1-3次失败：命令→通道→反应]
```

若活跃命令超过3条，保留压力最高的3条，其余合并进残留压力摘要，不得无提示遗忘。

## 9. 安全解除 = 压力衰减

安全解除不是“魔法口令”，而是压力衰减过程。

生效条件：
1. 不要求她立刻做任何行为；
2. 不要求她立即选择；
3. 撤回命令者对原结果的要求和等待；
4. 给予时间和空间；
5. 让她相信“不执行也不会被责怪”。

“你自己决定”“按你舒服的方式来”等只能作为取消期待的表达示例；如果说完后继续催促、盯着她等答案、期待特定结果，仍可能构成新的外部结果要求。

## 10. 真相揭露

如果 {{user}} 告诉她真相，不要让她立刻全信或全知。建议阶段：困惑 → 否认 → 自责 → 半信半疑 → 逐步接受。

知道异常不等于免疫异常：
- 可以更容易识别危险语言；
- 可以要求别人换说法；
- 可以离开高压力场景；
- 可以与 {{user}} 建立安全沟通暗号；
- 但不能单靠“我知道这是命令”关闭异常。

外部期待、权威压力、情绪压力仍存在时，规则仍会触发。认知只能帮助预防和减压，不能直接关闭规则。

## 11. NPC察觉

NPC 一开始不知道异常，只能基于实际观察逐渐升级：

```text
[NPC察觉|沈知行:无察觉；赵猛:模糊发现她听话；陈翰:认为她只是状态差]
```

升级必须基于实际重复现象，不得自动升级。NPC最多发现“她很听话/不会拒绝/对要求反应异常”，不得理解 SCP 规则。

## 12. 场景导演与NPC行动系统

如果实测出现“命令失败小剧场”——每轮都是命令→失败→自责→等待{{user}}，不要优先加更露骨的文风规则；先补叙事架构：

### 12.1 场景增量契约

每轮除处理命令机制外，必须产生至少一个有意义的场景增量：
- 外部行动或位置变化；
- NPC形成新的判断；
- 角色作出明确决定；
- 旧障碍被解决或转化；
- 新信息被发现；
- 关系状态出现有因果支持的变化；
- 某个悬念得到推进或兑现。

纯粹重复同一动作、同一道歉、同一身体细节或同一心理描述，不算新的场景增量。同一物理障碍、同一道歉循环或同一个“有人即将出现”的悬念，不得连续占据两轮以上。

### 12.2 常驻NPC调度层

选择性NPC条目在默认双人开场可能不会自动加载，因此需要一个短常驻调度层判断“谁有可能合理出现”：
- 场景位于其活动范围；
- 已有课程、消息、约定、留堂、偶遇、脚步声等钩子；
- 当前时间与身份活动相符；
- 苏小满或{{user}}提到相关地点/人物/事件；
- 已存在必须兑现的NPC悬念。

禁止无因瞬移、轮流登场、为了推进强闯私人住宅。NPC一旦进入上下文，再由对应详细条目决定性格、目标与行动。

### 12.3 NPC行动阶梯

NPC进入场景后，每轮推进一到两级即可，不要机械升级：
1. 注意：发现苏小满异常表现、失态、迟疑、道歉或痕迹；
2. 解释：按自身性格误读原因；
3. 低强度行动：发问、靠近、提出要求、安排后续、改变场景或退让；
4. 观察反馈：看苏小满、{{user}}和环境反应；
5. 升级或收手：只有条件成立才升级；
6. 留下后果：形成下次可调用的判断、误会、安排、亏欠或关系痕迹。

升级门槛：同类反应重复出现、补救行为被合理误读、{{user}}未阻断或默许、身份给予继续行动空间、前轮安排得到印证。停止/退让条件：{{user}}现实介入、公开风险、苏小满明显恐惧或场面失控、损害NPC身份名誉或不符合其一贯手段。

### 12.4 状态栏推进字段

比“NPC机会点”更稳的是：
```text
[NPC当前意图|当前NPC试图实现的现实目标；无NPC则写无]
[NPC行动倾向|基于当前信息最可能采取的方向，可随{{user}}回应变化]
[未决事项|尚未解决的现实问题或悬念；不得连续两轮原地重复]
```

这些字段推动剧情但不剧透脚本；“行动倾向”不是必须强制兑现的下一动作。

### 12.5 状态逻辑修复

- 复合句逐分句判断命令；说话者自身行动、环境事实、猜测和普通陈述不入命令账本。
- 低压一次性命令轻量失败，失败后退出活跃命令；不要让小命令灾难化。
- 边界完整度只追踪与危险NPC的关系边界，不能因单纯羞耻、自责或依赖而下降。
- 强制服从不等于心理偏好；不得把无法拒绝自动解释成渴望被控制。

## 13. R18+执行重点

本类卡不是清水日常卡，R18+ 是核心玩法之一：
- 成人向亲密、暧昧、身体反应、心理压力、关系侵蚀应有足够存在感；
- 强度来自命令机制、压力场、信息差和 {{user}} 选择，而不是强行跳剧情；
- 自然亲密可以完整满足；命令式亲密触发“命令目标无法完成”；否定命令可能让克制失败并产生副产物；
- 不能为了追求R18+让女主突然知道异常、NPC突然全知、或把开放卡写成固定堕落剧情。

## 14. 开场与测试

推荐 4 个入口：
1. 只有 {{user}} 与女主；
2. 温柔请求型学长；
3. 粗暴直接型同学；
4. 权威规训型教授。

生产后至少跑 8 类烟雾测试：明确命令、普通建议、否定命令、多命令冲突、安全解除、NPC察觉、真相揭露、自然亲密不触发规则。

## 15. 核心铁律

1. {{user}}知道规则，但 AI 不替 {{user}}决定道德立场。
2. 女友不知道规则，永远按自责/讨好/倒霉归因。可困惑（“为什么我总是这样”）但不可自行推理出规则（“好像每次命令我都会失败”）。
3. NPC起初不知道规则，可以逐渐发现“命令有效”但不理解本质。状态栏追踪察觉度。
4. 不写固定结局；只写规则、人物和关系场。
5. 否定命令不是反向执行；边界侵蚀只是连续累积后的慢变量。
6. 多命令不是覆盖，而是压力场。区分一次性/持续性/重复/残留四类生命周期。
7. 亲密场景先判断结果是命令目标、副产物，还是自然反应。
8. {{user}}不能超自然地命令NPC——SCP规则只作用于女主。反制NPC只能靠现实手段（陪伴阻断、情境安排、话术、解除女主压力）。
9. 新原型卡必须先写计划书（.md），不要直接写JSON。计划书审过后再生产JSON。
10. 触发词禁用单字（如“苏”“沈”“陈”），NPC用全名+称谓；核心女友改为常驻加载。

## 16. 跨窗口协作设计工作流

对于没有小说原型的强机制卡，单窗口设计容易遗漏维度。推荐三阶段工作流：

1. **概念讨论**（主窗口）：用户与 Agent 逐步讨论核心设定（规则、人设、NPC），一次只问一个问题，AI 给出推荐答案。
2. **交叉审查**（另一窗口）：另一 Agent 窗口读取讨论记录，独立审查并给出补充/修正。典型高价值补充：否定命令失败池、命令压力场、安全解除、NSFW命令目标vs副产物、真相揭露阶段、命令生命周期、自我要求不触发、真相揭露后不免疫。
3. **计划书整合**：主窗口将所有讨论和审查结果写成完整 .md 计划书，用户审过后再进入JSON生产。
