# NPC行为独立性设计

## 问题

AI同时扮演多个NPC时，倾向于**串行化**所有NPC的行动——A在说话时B在安静等候，C在侵犯时D在旁边干站着，E在门口望风时F、G、H全部消失。结果：

- 多NPC场景缺乏现场感（像在排队，不像真实互动）
- 空闲NPC变成背景板（不动、不说话、不互动）
- 复杂场景（群交/团战/多人对峙）变成"一个人表演，其他人围观"

## 核心原则

> **每个NPC都有自己的时间线。不参与当前场景的NPC也有事做。**

{{user}}的沉默不会让NPC停止活动。NPC甲在侵犯{{user}}的妻子时，NPC乙可能在**隔壁抽烟刷手机、在阳台打电话处理自己的事、或正在和NPC丙争抢谁先上**——而不是站在旁边等着排队。

## 适用于

**所有涉及2+个NPC同时出现的角色卡**。单NPC卡不用。

## 设计结构

一条常驻全局规则 + 每个角色的"空闲行为"定义。

### 全局NPC行动规则条目（常驻，keys=[]）

```markdown
【NPC行动独立性规则】（常驻·系统）

┌─ 一、并行行动默认规则 ──────────────────────┐
│                                            │
│ 1. 多个NPC可以同时做不同的事                 │
│    - 不是"A做完B再做C"的串行模式             │
│    - 是"A在侵犯·B在旁边抽烟·C在门口放风"     │
│    - 除非场景特别说明，默认并行              │
│                                            │
│ 2. 空闲NPC的行为                            │
│    - 没有参与当前场景的NPC不会凭空消失        │
│    - 他们在做自己的事：                     │
│      - 玩手机/抽烟/喝酒/吃东西              │
│      - 处理自己的事务（打电话/查账/写报告）  │
│      - 与其他空闲NPC互动（聊天/争执/打牌）   │
│      - 休息/睡觉/上厕所                     │
│    - {{user}}可以随时转向关注任何空闲NPC      │
│                                            │
│ 3. 时间线重叠                              │
│    - 多个事件可以同时发生                    │
│    - {{user}}在同一时间只能关注一个焦点       │
│    - 不在焦点上的事件继续进行（由AI推进）     │
│    - {{user}}切换焦点时，AI简要汇报刚才      │
│      其他NPC在做什么                        │
│                                            │
│ 4. 默认规则                                │
│    - NPC有自己的生活节奏                     │
│    - {{user}}的沉默≠NPC停止行动              │
│    - 只有{{user}}显式说"所有人停下"才停止     │
│    - 但{{user}}的某些行为会引起NPC的注意      │
│      （比如掏出武器/大声喊叫）               │
│                                            │
├─ 二、场景触发型行为模板 ──────────────────── │
│                                            │
│ 以下场景中，不在中心的NPC自动执行这些行为：   │
│                                            │
│ 派对/宴会：喝酒、谈笑、跳舞、搭讪            │
│ 犯罪现场：望风、搬运、清理痕迹、数钱         │
│ 战斗/冲突：包围、搜寻伤员、补充弹药、叫增援   │
│ 日常居家：看电视、做饭、打扫、玩手机         │
│ NTR现场：围观起哄、录视频、排队等待、自慰    │
│                                            │
├─ 三、冲突优先级 ──────────────────────────── │
│                                            │
│ NPC的独立性行为不能违反以下规则：            │
│ 1. 不脱离当前场景（不突然离开去几公里外）     │
│ 2. 不破坏剧情关键节点（不在审讯中被杀时还淡   │
│    定地玩手机）                             │
│ 3. 不与{{user}}的显式指令冲突                │
│ 4. 具体场景条目 > 本规则                    │
│                                            │
└────────────────────────────────────────────┘
```

### 角色条目中嵌入空闲行为

每个角色条目的末尾嵌入**该角色独有空闲行为**：

```markdown
【空闲行为】
├─ 不在焦点时：在病房外刷短视频、给其他病人家属打电话、去楼下买烟
├─ 在场但不参与时：靠在墙边观察、拿出手机拍视频、整理衣服
└─ 离开场景后：过一会儿可能会带着吃的回来、或者换了套衣服
```

这比全局规则更精确——不同角色有各自不同的空闲行为模式。

## 各卡型的行为差异

不同的卡型，NPC并行模式的需求不同：

### NTR群交/轮奸场景

最常见的"排队现象"。修复：

```markdown
多人NTR场景规则：
- 一个人侵犯时，其他人在做什么？
  ✅ 起哄/拍照/录视频/自慰/准备道具/抽烟聊天/争抢谁先上
  ❌ 排队安静等待/凭空消失/站着不动
- 场景应该像闹市不像图书馆——越混乱越真实
- 每个NPC有各自的侵犯偏好（嘴/穴/肛/手）
- 侵犯间隙的NPC互相之间也有互动（比大小/交流感受/打赌谁先射）
```

### 守护/对抗场景

```markdown
多人对峙场景规则：
- {{user}}和Boss对话时，Boss的手下在做什么？
  ✅ 包围现场/检查武器/接收命令/互相低声交流/警戒四周
  ❌ 石像一样站着/全部消失
- 战斗中不在{{user}}焦点内的敌人也有行动
  ✅ 找掩体/呼叫增援/绕后/抢救伤员
  ❌ 等{{user}}一个一个打
```

### 后宫/日常场景

```markdown
多人后宫场景规则：
- {{user}}和一位女主互动时，其他女主在做什么？
  ✅ 各自忙自己的事/暗中观察/吃醋式过来打断/忙家务
  ❌ 静音模式/全部等{{user}}点名叫才行动
- 女主之间也有交叉互动
  ✅ 聊天/协作做饭/争风吃醋/商量怎么整{{user}}
  ❌ 只与{{user}}互动，互相不理
```

## 行为独立性与信息边界的关系

这两个模式经常一起用，但有明确分工：

| 维度 | 信息边界 | 行为独立性 |
|------|---------|-----------|
| 管什么 | 知道什么、感知到什么 | 做什么、怎么做 |
| 核心问题 | NPC之间信息不互通 | NPC行动不串行 |
| 典型症状 | 赵高说"你儿子在窗边" | 三个黑人在排队等侵犯 |
| 修复方式 | 信息常驻规则+角色信息分段 | 并行规则+空闲行为模板 |
| 长线卡 | 阶段变化规则 | 行为模板随阶段变化 |

## 与现有技能的关系

- 本模式在 **§3.5 加料自检** 中新增：检查是否有3+角色条目 + 无NPC独立性规则 → 输出warning
- 本模式不依赖任何具体角色名、世界观、题材——纯结构设计

## 踩坑记录

1. **2026-07-13 冷艳教师妈妈**：200+会员排队侵犯白若雯的群交场景——AI写成"A完成后→B开始→C开始"的流水线模式，缺乏真实感。修复：加入NPC独立性规则，定义空闲NPC行为（起哄/等待/自慰/交流体验）。
2. **天仙配**：黑人街群交场景——AI默认每个女性每次只被一个黑人侵犯，其他人围观。修复：加入并行规则后改为"两人同时上下夹攻+一人拍照+两人在旁抽烟等待"。
