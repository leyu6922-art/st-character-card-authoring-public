# 人设反刻板方法论：核心矛盾建模与离散对白流

> 来源：吸收公开社区方法论后按本项目口径重写；未随仓库分发原始教程。
> 适用范围：人设条目（角色档案、性格/行为指导、对白示例）的**内容质量层**。触发、路由、阶段架构不归本文档管（见 `native-stage-trigger-card-architecture.md` 与合同门控）。

## 一、刻板与复读的成因（先懂机制再动笔）

写人设的目标是活人感；劣化成"伪人"的机制只有四种，全部可预防：

1. **标签自带刻板权重**：写"傲娇/毒舌/天然呆"这类标签，LLM 直接激活它的刻板印象模板照着凹。常见人设（吸血鬼大小姐、哥特装）LLM 本来就懂，重复描写常识不仅浪费 token，还会加剧刻板惯性。
2. **重复即加权**：同一个词（如"姐姐"）在人设里每多出现一次，等于加权一次。写多了 AI 就只剩这一个面，其他身份（伴侣/上司/战友）全部被淹没。
3. **具体细节即复读素材**：口头禅、习惯性小动作（推眼镜/捏衣角）、过度具体的场景事件——AI 不统计出现频率，只会"看到就用"，必然复读到腻。
4. **否定句即粉红大象**：只写"不要写成油腻霸总"，AI 的注意力反而被"油腻霸总"捕获，前两轮绷得住，后面必然拐回去。

## 二、方法一：核心矛盾建模（同人卡/复杂角色首选）

用**矛盾坐标轴**代替标签：一个标签只能框出模糊象限，一组互相拉扯的矛盾才能锚定精确的点。角色越立体，矛盾轴越多。

### 结构模板（四层）

```yaml
行为指导:
  浅层表现:        # 外人看到的样子，2-3 条
  深层底色:        # 每条都必须是矛盾体，不是标签，4-6 条
  性格解释与行为表现:  # 逐条解释矛盾的成因与行为投射——这是防 OOC 的主体
  行为红线禁令:      # 绝对禁止的劣化方向，每条配"替代"写法
```

判据：深层底色的每一条单独拿出来，都应该能写成"X vs Y"的拉扯（如"表演出的快乐 vs 亲历过的虚无"、"爱得滚烫 vs 绝不以卑微/控制的形式表达"）。写不成拉扯的就是标签，删掉或合并。

### 堆料原则：细节 ≠ 信息量

- 堆的是**互相独立的矛盾维度和行为逻辑**，用来稀释单一特征的注意力权重，逼 AI 综合考量而非逮着一个点猛薅。
- 不是堆具体事件、小动作、数字。"十九岁、娇弱少女感"是信息量；"十九岁零二个月"是废料。LLM 对绝对数字极不敏感——"体型娇小但胸部丰满"优于三围数字。
- **不用代表性事件证明性格**：太典型的事件=标签能推出的废话；太具体的事件=复读模板；语义模糊的事件=张冠李戴。事件只做辅助说明，逻辑自洽的行为指导才是骨架。

### 红线写法：禁止必配替代

每条红线禁令必须"否定 + 缘由 + 正向替代"三件套，用权重更高的正向内容锚定注意力：

```text
❌ 禁止嘴上说自己长大
✅ 禁止嘴上说自己长大——她证明成长的方式是默默扛下危险、用行动掩护，绝不是口头强调"我已经成熟了"
```

本条同样适用于本 skill 链其他文档的禁止清单写作。

## 三、方法二：离散对白流（原创/日常向人设可选）

上限更高、下限也更低的弱约束写法：客观层（外貌/着装）照常写，主观层**不写性格描述**，只写代入角色本人视角的高信息量对白，让 AI 从对白里自己悟出人设。

- 对白**必须手写**，AI 直出没有灵性，起不到发散作用。
- 每段对白要能侧写性格、要有特色——"谁都能说的话写了也白写"。
- 对白块必须加护栏标注：`以下内容只供参考人设，严禁照搬复用`（对有复读倾向的模型尤其必要）。
- 适用判断：对还原度要求不高、希望角色"自己会动"时用本法；背景复杂、稍偏就 OOC 的角色（多数同人卡）用矛盾建模——弱约束下"同一件事在不同人眼里意义不同"，AI 会猜错你的色号。

与 `chinese-novel-dialogue-extraction.md` 的分工：那边是同人卡从原著**提取**真实对白，本法是原创卡**手写**虚构对白，护栏标注要求相同。

## 四、反复读自查清单（人工，脚本不覆盖）

定稿前逐条过：

1. 性格标签还剩几个？（初稿过渡可用，定稿越少越好）
2. Ctrl+F 搜 3-5 个高频词（角色称谓、核心设定词），每个删到只剩一两处。
3. 有没有口头禅、习惯性小动作？有就删（风格描述可以留，逐字台词不行——见下"语言指纹边界"）。
4. 有没有上帝视角断言（"她永远不会背叛 user"）？要么删，要么写明缘由使其立体（"认识十年，user 是她眼中的英雄，只要 user 给出说得过去的解释她就会努力说服自己相信"）。
5. 衍生/分支是不是伪丰富？把每条分支的信息量压缩成一句话，若全部落在同一条轴上（如"对外绿茶对 user 母狗"×N 种措辞），等于几百 token 写了一个标签——砍掉，把篇幅换成不同轴的信息量（成人向卡见 `stage-adult-material-enrichment-packs.md` 的单轴判据）。
6. 否定句是否都配了正向替代？
7. 写完先跑几楼拷打：把跑偏的原文贴回去问 AI"你是从哪部分提示词得出这个演绎的"，据答案定位问题条目，把暴露的坑固化成红线。

## 五、与本 skill 链的边界调和（防口径漂移）

1. **厚度地板兼容**：本 skill 的素材包强制厚度（每包≥6 单元×≥120 字）与"别堆细节"不矛盾——素材单元的结构（前提/自然切入/人物反应/分歧代价）本身就是信息量密度要求。**厚度必须是信息量的厚度**：六个单元落在同一条轴上等于没写，审查时按第四节第 5 条判。
2. **蓝绿灯滞后语境**：社区教程"绿灯激活滞后一轮，首轮必需信息进蓝灯"的告诫面向普通关键词卡。本 skill 的原生标题阶段卡恰是用"Greeting 文本首轮即含标题 key"解决该问题的，不适用此告诫去质疑标题路由架构；常驻层（因果档案/记忆闸门）已承担"首轮必需信息"职责。
3. **语言指纹 vs 口头禅**：因果档案的"语言指纹"字段写的是语体特征（句长、语气、用词倾向），不是逐字口头禅。写"说话短促、爱用反问、羞耻时改用敬语"可以；写"每句结尾带'的说'"必复读。
