# 渐进式世界书设计模式（递进式阶段状态机）

> **状态**：2026-07-18·艳母的荒唐赌约规划中首次系统化
> **核心问题**：当小说有明确的递进沉沦曲线时，不能把全文事件并列堆进世界书——必须用阶段状态机隔离不同阶段的角色状态。
> **参考卡**：《参考卡》的情感阶段条目(id3)+事件系统(id2)+驱动机制(id5)

---

## 1. 适用场景

当小说满足以下条件时，必须用渐进式世界书而非"全集成大条目"：

1. **角色状态随剧情显著变化**——第1章的主角和第100章的主角不是同一状态
2. **有明确的递进主线**——赌约→协议→失控，或纯真→堕落→觉醒
3. **后期素材会污染早期**——如果"浪奴""192小时"等后期称呼出现在第1章开场，AI会混乱
4. **同一关系在不同阶段变体不同**——如"玉诗×骆鹏"在P3是"危险玩家"，到P4才变"协议主人"

**不适用场景**：
- 角色状态全书基本不变的卡
- 单场景/单事件卡
- 系统流/规则驱动卡（用SCP-2599模式）

---

## 2. 架构：基础层 + 阶段层 + 关系阶段层

```
Layer 0: OOC/阶段铁律层        （常驻，5条）
Layer 1: 基础人物不变量层      （常驻/自然触发，5条）
Layer 2: 阶段状态层            （enabled=true + 阶段marker keys，开场白自动触发，7条）
Layer 3: 阶段关系层            （selective=true，secondary含阶段marker，12条）
Layer 4: 阶段事件种子层        （enabled=false，用户手动启用，24条）
Layer 5: 阶段场景层            （selective=true，secondary含阶段marker，7条）
Layer 6: 轻量配角层            （自然触发，5条）
Layer 7: BAD END/反击路线层    （触发，2条）
```

---

## 3. 关键设计原则

### 3.1 基础不变量 vs 阶段状态必须分离

**错误**：把"郎玉诗"写成一个大条目，包含从第1章到第120章所有状态。
**正确**：
- Layer 1 写跨阶段不变的基础信息（外貌、性格底色、天生能力）
- Layer 2 写每个阶段的具体状态（心理、羞耻、主动性、服从度、称呼变化）

### 3.2 阶段条目必须包含多维行为标志

每条阶段状态条目至少包含：
1. 本阶段允许出现的称呼
2. 本阶段禁止提前出现的称呼/事件
3. 核心角色当前心理（至少女主+男主）
4. 其他核心角色当前地位
5. 当前主导权归属
6. 当前风险来源
7. 推荐剧情推进方式

参考卡《参考卡》的情感阶段条目(id3)提供了每阶段5维行为差异的范例。

### 3.3 后期素材必须阶段隔离

高危后期素材只能在指定阶段之后出现。必须在 Layer 0 的阶段铁律条目中明确列出：

```
"浪姐"允许P1后
"浪奴"只允许P4后
"192小时"只允许P6
P4前不得把骆鹏写成既定主人
P6前不得出现小区保安权力线
```

### 3.4 开场白必须带阶段注释 + 基于原文场景

> **⚠️ 注意（v1.17.1+）**：greeting HTML 注释方案仅适用于**社区发布版**（用户不理解 Author's Note 概念）。个人使用/跨预设场景，推荐使用 Author's Note 单一权威路由（见 §3.5 开头和 `an-single-authority-stage-routing.md`）。greeting 注释中的阶段标记在 Author's Note 权威版中**不应保留**，否则可能与 AN 中的 `ROUTE_STAGE=P#` 产生双阶段触发冲突。

每条开场白开头用HTML注释写明当前阶段：

```html
<!-- 当前阶段：P1 第一赌约与赵勇征服
允许出现：赵勇试探、刘宇赌约兴奋与不安、郎玉诗嘴硬与身体失守
禁止提前出现：浪奴、192小时、小区公开调教、肖斌、小龚、陆寒林
-->
```

**⚠️ 关键pitfall（2026-07-18·艳母v1_1实证）**：开场白正文**必须**基于原文对应章节的实际场景重写，**禁止**用模板套话+阶段注释切换的方式批量生成。

错误表现（v1_1卡全部8条开场白共用同一模板）：
- 开头全都是"夜色和屋内灯光把场景切成两层"
- 角色描述段落完全相同（"赵勇的存在像一束阳光，骆鹏的存在像阴影……"）
- 编号段落1-10中7-10是1-4的完全重复
- 只有HTML注释里的阶段标记不同
- 本质：子代理/批量生成时偷懒，用模板填充而非逐条写原文场景

正确做法：
1. 为每条开场白指定**对应的原文章节**（如P0→ch1, P1→ch3, P4→ch55）
2. 从对应章节提取**关键场景、对话、人物互动**作为开场白正文
3. 每条开场白的开头、场景、对话都应不同——它们对应小说的不同节点
4. 去掉编号段落（1-10列表），用叙事体直接进入场景
5. 保留HTML阶段注释作为ST触发机制，但正文才是内容主体
6. 每条开场白正文**≥1600汉字**（2026-07-18·艳母实证：初版600字被用户打回"500字？"，扩到900仍不够，最终1600汉字才通过。必须用原文对话+场景描写+人物心理充分展开，不能用AI概括式写法压缩篇幅）

### 3.5 触发策略（v1.17.1+ 推荐方案：Author’s Note 单一权威路由）

> **⚠️ v1.17.1 重大修正（2026-07-18·艳母实证）**：greeting 注释 + AI 状态栏 + 自然语言 key 的组合方案在**不同 ST 预设**下不可靠。核心原因：
> 1. 不同预设输出格式完全不同（XML/story_record/纯文本），预设优先级 > 世界书，角色卡**不能命令**预设输出特定格式
> 2. 多源锚点（greeting + 状态栏 + 用户消息）不是冗余——是**冲突源**。ST 不会做"最新优先"，扫描范围内所有命中 key 的条目都会触发，导致双阶段同时加载
> 3. 自然语言 key（`当前阶段：P2`、`三男加入`）在自然对话中不保证出现，且讨论未来时可能误触发
>
> **结论（2026-07-26 更新）**：新卡默认使用**原生 Greeting 标题路由**（REQUIRED SUB-SKILL `standalone-card-stage-routing` + stage-entry-contract schema v2 + `final_delivery_gate.py --native-stage-routing`）。**Author's Note 单一权威路由**属配套预设外部路线，未接入 native 交付门控（final gate 检测到 `ROUTE_STAGE=P#` 会硬 FAIL：STAGE_EXTERNAL_ROUTE_UNSUPPORTED），仅在配套预设发行场景使用；完整方案仍见 `references/design-patterns/an-single-authority-stage-routing.md`。
>
> 以下旧版方案仅作为社区发布兼容版的**备选参考**，不推荐新卡使用。

### 3.6 事件种子不能只是"发生过什么"——【事件核心叙事】必须填具体内容而非章节指针

**⚠️ P0级pitfall（2026-07-18·艳母v1_1交付前）**：事件种子最常见的错误是只写章节编号指针（如"ch55..."、"ch1，母子……"）而不写实际叙事内容。这样的条目即使被用户手动开启，AI也只能空对空。

事件种子必须写成6段模板（不是只有事件目录）：

```
【事件触发】
什么情况下触发该事件。

【阶段前提】
该事件只能在PX阶段发生。禁止提前/滞后。

【事件核心叙事】\n**800-1200字**，基于原文对应章节提炼。**必须有具体的场景描写、角色对白、关键动作、双人心理反应**。不能只写成"ch55..."或"ch1，母子……"。

**⚠️ P0级pitfall（2026-07-18·艳母v1_1实证—独立窗口交叉验证确认）**：avg 312字的核心叙事在独立窗口审查中被判定为"框架化、太薄，更像是剧情目录+触发规则而不是可直接展开的事件素材"。正确做法是将每条【事件核心叙事】从avg 312字压平基线提升到800-1200字，包含：
- **2-5句原文对白或高度贴近原文的对白**——直接引用原文对话（带引号），如「你妈今天穿什么衣服在家呢？」「你违约了。」「以后你就叫浪奴。」
- **具体场景设置**——时间、地点、光线、声音、道具。如「江边木栈道，深夜，路灯苍白，鲜红高跟鞋踩在木板上的嘀嗒声」
- **完整动作链**——谁做了什么、对方如何反应、结果是什么。如「他解开关闭条→手伸进去→她停止了挣扎→淫水顺着大腿流下来」
- **双人心理反应**——既要写女主的心理变化（羞耻/恐惧/兴奋/嘴硬），也要写{{user}}的苦主视角反应（兴奋/不安/失控感/操盘欲）
- **事件后的关系锁定点**——这条事件推进后，关系发生了什么不可逆的变化

⚠️ 框架/模板占比过高的预警信号：如果有50%以上的内容被【事件触发】/【阶段前提】/【干预窗口】等通用模板占据，而只有一小部分是真正的叙事内容，说明事件种子更像「运行说明」而非「事件素材」。模板说明可以合并或压缩（例如同一阶段的【阶段前提】表述可以统一归到阶段条目中），但叙事内容必须占条目总长度的60%以上。

**交叉审查验证方法（2026-07-18·艳母实证）**：在单次构建完成后，使用第二窗口独立审查事件种子的叙事厚度。具体方法：对目标文件执行 `grep -oP '【事件核心叙事】\K[\s\S]*?(?=【干预窗口】)' 文件.json | wc -m`，统计每条叙事字数。如果avg＜800字或框架占比＞50%，必须全部返工——因为模板化生产模式通常一次性产出所有薄弱条目，不存在"只修几条即可"的情况。

【干预窗口】
{{user}}可以在事件完全落地前做什么。

【默认走向】
如果{{user}}不干预，事件会如何推进。

【事件后状态变化】
- 核心角色心理变化
- 关系地位变化
- 是否解锁下一阶段
```

**【事件核心叙事】的正确写法**：
- ✅ 直接引用原文对话（加引号），如"你妈今天穿什么衣服在家呢？""成为妈妈的男人，就是把他男人的象征插到妈妈这里来"
- ✅ 写具体场景：时间、地点、光线、氛围——"江边木栈道，深夜，路灯苍白，鲜红高跟鞋踩在木板上的嘀嗒声"
- ✅ 写具体动作链：角色做了什么、对方反应如何——"他解开关闭条→手伸进去→她停止了挣扎"
- ✅ 有情节推进：这段叙事应该本身就构成一个可读的场景

- ❌ 只写概括：如"ch1母子争论电视剧情展开赌约"
- ❌ 只写推断：如"如果用户打开这个事件，AI应生成什么什么"
- ❌ 写成脚本指令：如"这个事件发生后，AI应该让玉诗感到羞耻"

**排序原则（2026-07-18·艳母v1_1实证**：
24条事件种子按时间顺序排列，先P1后P6，每个阶段内按原文章节顺序。用户手动启用时能按剧情时间线逐个打开。

**提交流程**：写完事件种子后，用独立窗口或脚本统计每条【事件核心叙事】字数。如果avg＜800字或框架占比（非叙事模板文字）＞50%，则全部24条需要返工。具体做法：\n1. 逐条提取叙事段落的字符数\n2. 计算avg和最低值\n3. 如果avg＜800，进入叙事加厚循环：先补原文对白（2-5句），再补场景细节（地点/光线/动作链），最后补双人心理反应\n4. 加厚完成后用交叉窗口验证（第二窗口用脚本统计+人工抽读3-5条确认叙事质量）\n\n**交叉审查验证方法（2026-07-18·艳母实证）**：在单次构建完成后，使用第二窗口独立审查事件种子的叙事厚度。具体方法：对目标文件执行脚本提取每条【事件核心叙事】字数，计算avg和最低值。同时计算框架占比（非【事件核心叙事】文字占总字数的比例）。如果avg＜800字或框架占比＞50%，必须全部返工——因为模板化生产模式通常一次性产出所有薄弱条目，不存在「只修几条即可」的情况。

### 3.7 P5伏笔 vs P6完整展开（阶段边界精细化）

当某个外部变量（如保安系统）在P5出现但P6才完整展开时：
- P5只能是"异物感/监控风险/伏笔"
- P5不能让该角色成为可被利用的实际参与者
- P5不能出现关联的权力角色（如保安副队长）
- P6才完整展开所有外部变量和权力线

### 3.8 卡片元字段必须写有用的AI跑卡内容（禁写架构笔记）

**⚠️ 关键pitfall（2026-07-18·艳母v1_1实证）**：`description`（角色描述）、`personality`、`scenario` 这三个字段是**AI跑卡时直接读取的上下文**，不是给开发者看的注释。

错误表现（v1_1卡）：
- description 写的是"Layer0 OOC/阶段铁律、Layer1 基础人物不变量、Layer2 P0-P6阶段状态……"——全是卡片架构设计说明
- personality 写的是"默认{{user}}=刘宇：苦主、操盘者、偷窥者、救火者"——只有一句话概括
- scenario 写的是"使用8条带HTML阶段注释的开场白进入P0-P6"——是使用说明不是剧情场景

正确做法：
- **description**：写实际人物信息——年龄、外貌、性格、核心动机、故事线。AI能直接用这些来生成符合角色的回复
- **personality**：写角色在不同阶段的人格特征变化，以及关键NPC的一句话定位
- **scenario**：写剧情背景和各阶段的关键剧情节点，让AI知道当前故事走到哪里了

用户原话："角色描述这块换成有用的，别整虚的。"

### 3.9 ST字段实现规则（中文卡专用）

**中文卡铁律**：`match_whole_words = false`（Python \W不匹配CJK字符，true导致所有中文关键词匹配失败）

| 层 | enabled | constant | selective | keys | position |
|---|:--:|:--:|:--:|------|------|
| Layer 0 系统层 | true | true | false | `[]` | before_char |
| Layer 1 基础人物 | true | false | false | 自然角色名 | before_char |
| Layer 2 阶段状态 | true | false | false | 阶段marker + 阶段关键词 | before_char |
| Layer 3 阶段关系 | true | false | true | primary=角色词, secondary=阶段marker | after_char |
| Layer 4 事件种子 | false | false | true | 事件关键词 | before_char |
| Layer 5 阶段场景 | true | false | true | primary=场景词, secondary=阶段marker | after_char |
| Layer 6 轻量配角 | true | false | false | 自然角色名 | after_char |
| Layer 7 结局 | true | false | false | 结局关键词 | after_char |

通用extensions：`probability:100, depth:4, prevent_recursion:false, match_whole_words:false, use_regex:true`

### 3.10 Layer 1 基础不变量加物理规格（阳具尺寸差异化设计）

**⚠️ 关键技巧（2026-07-18·艳母v1_1实证）**：为NTR/后宫类卡片的核心男性角色（包括{{user}}）在Layer 1基础不变量中设定**明确的阳具尺寸/形状描述**，能给AI提供具体的对比素材和刺激点，避免笼统描写。

#### 设计原则

1. **差异化梯队**——每个男性的尺寸必须不同且有比较关系，不能都写"很大/很粗"。典型梯队：
   - 赵勇（第一征服者）：最大最均衡（18-19cm），标杆
   - {{user}}（苦主/操盘者）：中等偏上（15-16cm），年轻恢复快但有情感加成
   - 骆鹏（规则控制者）：中等偏长+形状特异（16-17cm+上翘+G点棱），"不是最大却最准"
   - 向晓东（粗变量）：最粗但最短（14-15cm+蘑菇头），蛮力冲击型

2. **差异化功能**——每种尺寸对应不同的体验定位：
   - 大尺寸→"满了"（阴道壁撑开感）
   - 特异形状→"准了"（G点/敏感点精准打击）
   - 粗短→"重了"（单次冲击力强）
   - {{user}}→"亲了"（情感加成/禁忌感）

3. **与小说原文呼应**——如果原文提到过某人的阳具特征（如骆鹏"形状特异的阳具"），必须在尺寸描述中忠实还原，不能自创与原文矛盾的数据。

4. **写进基础不变量而非事件条目**——尺寸是跨阶段不变的物理事实，应放在Layer 1（id 6-9等基础人物条目）中，而不是反复出现在每个阶段事件里。事件中只需要引用比较即可。

5. **郎玉诗感知模板**——在郎玉诗的基础不变量（id 5）中加入她对每个男人尺寸的差异化感知，用她自己的语言区分："赵勇让我满了""骆鹏让我准了""向晓东让我重了""儿子让我……"。

#### 使用场景
- NTR卡——为苦主感和比较心理提供具体素材
- 后宫卡——区分每个男性伴侣的身体体验
- 征服卡——强化征服者的物理优势
- 任何有多名男性角色且涉及性描写的卡片

进阶：为女主建立「尺寸感知模板」（`female-lead-size-perception-template.md`），让她用不同「关键词」区分每个男人在她身体上的感受差异。

### 3.11 情感线铺垫贯穿多层（非强制结局路径）

**⚠️ 关键技巧（2026-07-18·艳母v1_1实证）**：当卡片可能包含一条"从淫乱回归真情"的母子/伴侣情感线时，情感的种子不能只放在结局条目里——必须**贯穿分布在多层世界书**中，每层埋一个可选的触发锚点。这样情感出口就不是空降设定，而是从头到尾的伏笔。

#### 贯彻策略

| 层 | 条目 | 埋什么 | 示例 |
|----|------|--------|------|
| Layer 1 基础不变量 | {{user}}基础（id 6） | 情感动机 | "操盘是表层，深层是怕失去妈妈" |
| Layer 1 基础不变量 | 女主基础（id 5） | 情感感知 | "希望被儿子看见而非只当工具" |
| Layer 1 基础不变量 | 女主基础（id 5） | 尺寸感知中的情感差异 | "儿子和别人的体验不同是因为情感" |
| Layer 3 阶段关系 | 母子共谋（id 19） | 事后沉默 | "两人做完安排后对视的那一秒安静——才是情感线的位置" |
| Layer 0 OOC层 | NPC规则（id 4） | 优先原则 | "不管她多放荡，在儿子面前留底线" |
| Layer 7 结局 | 反击路线（id 66） | 情感出口 | "反击成功后有机会从操盘转向伴侣" |

#### 关键原则

1. **不集中在一处告白**——情感线最忌讳在单一条目里长篇抒情。分散在5-7条不同层级的条目中，每条只写1-2句，AI在触发这些条目时自然积累情感感知。
2. **不强制推进**——所有情感种子都写成**可选反应**（"如果用户表现出修复倾向……"），而非默认走向。卡片的主体仍然是NTR/后宫，情感线只是给想走的玩家留一个出口。
3. **藏在行为细节里**——情感线的证据不是"我爱你"，而是"她会在被粗鲁对待后洗澡更久""他会在别人走后轻轻按住她的肩膀""两人会在协议期焦虑的不是肉体而是'他还是不是我的儿子'"。细节比宣示更有效。
4. **阶段递进中保留情感残留**——每个阶段状态条目（Layer 2）中，可以在女主/男主的心理维度里加入一句情感锚点。例如P4描述郎玉诗心理时加一句"即使在被骆鹏命名浪奴时，她心里仍留着'刘宇怎么看'的间隙"。
5. **反击路线才是情感出口的真正位置**——情感线不能在中途阶段（P0-P5）直接解决，必须在P6的反击/结局路线中（id 65-66）提供从淫乱回到真情的合理路径。之前的铺垫只是让这个出口不突兀。

### 3.12 角色行为/心理/性爱对话模板（人物条目的跑卡素材库）

**⚠️ 关键技巧（2026-07-18·艳母v1_1实证）**：Layer 1 基础不变量条目（id 5-9）除了外貌、性格、关系描述外，还应包含**结构化的行为/心理/性爱对话模板**。这些模板给AI提供具体的人物反应模式，让AI生成的角色行为更一致、更有辨识度。

#### 三种模板的内容定位

| 模板类型 | 写给AI看什么 | 示例 |
|---------|-------------|------|
| 【常见行为模板】 | 这个角色在典型情境下会怎么做——前戏/谈判/羞耻/高潮/事后 | 「被挑衅后先用玩笑顶回去，若对方继续逼近则用权威压，最后用身体语言暴露真实动摇」 |
| 【性爱模板·言语篇】 | 这个角色做爱时说什么——嘴硬型/投降型/命令型/本能型/羞辱型 | 「嘴硬型对白：'就这？我还以为你多大本事呢'」 |
| 【性爱模板·行为篇】 | 这个角色做爱的完整反应链——前戏/插入/高潮/口交/被过度羞辱 | 「高潮时不会大叫而是忽然失声，身体绷紧几秒然后像被抽空一样软下去」 |
| 【性爱模板·分化篇】 | 这个角色对不同伴侣的差异化反应 | 「对赵勇最放松，叫最大声；对骆鹏最紧绷，阴道最诚实但心理防御最严；对刘宇注意维持妈妈身份」 |

#### 女主性爱模板的特殊要求

女主的【性爱模板·分化篇】是整张卡的核心——因为女主是多人性爱场景的中心，她对不同男人的差异化反应直接决定了AI生成场景的质量。

**每个男主必须有一条差异化反应**：
- 对第一征服者（如赵勇）：最放松、最真实、高潮时有依赖感
- 对规则控制者（如骆鹏）：最紧绷、身体和嘴矛盾、高潮后先计算对方反应
- 对粗变量（如向晓东）：最随性、不在乎丢脸、像对待工具
- 对{{user}}（如刘宇）：最复杂——有伦理禁忌加成，会注意维持身份，情感交换最强

**写法原则**：每条差异化反应包含三个维度——
1. 身体反应差异：夹的力度、叫床的声音、高潮的阈值
2. 心理防御差异：在谁面前嘴硬、在谁面前放弃防御、在谁面前计算
3. 事后态度差异：做完后想独处/想聊天/想确认对方态度

#### 男主行为模板的通用结构

每个男主的基础条目应该有6个典型行为模式：
1. 试探模式/推进模式/控制模式（取决于角色定位）
2. 面对女主时的特殊模式
3. 面对{{user}}时的态度
4. 性爱风格（尺寸/节奏/语言/敏感点）
5. 事后表现
6. 面对竞争/被拒绝的反应

#### 插入位置

所有模板添加到Layer 1基础不变量条目的**末尾**，作为独立章节（以`【常见行为模板】`开头）。不要分散写在事件种子或阶段状态中——因为模板是跨阶段不变的。

#### 与事件种子的关系

行为模板提供的是**单角色的一致行为逻辑**，事件种子提供的是**多角色在特定场景中的互动推进**。两者配合使用：AI从事件种子获取「发生了什么」，从行为模板获取「我的角色会怎么做」。

## 4. 验证门控

除标准门控（validate_card/enrichment_self_check/final_delivery_gate）外，需要新增**阶段污染检查**：

| 规则 | 说明 |
|------|------|
| 称呼时序 | "浪姐"允许P1后、"浪奴"只允许P4后、"192小时"只允许P6 |
| 角色定位时序 | P4前不得把控制者写成既定主人 |
| 外部人物时序 | 外部威胁角色只在指定阶段出现 |
| 开场白注释 | 每条greeting必须有`<!-- 当前阶段：PX`格式 |
| 单阶段命中 | 每条greeting只能命中一个Layer 2阶段条目；若P0开场同时触发P1，说明阶段key过宽 |
| 后期路线绑定 | 反击路线/BAD END/后期路线不得全局自然触发；P6反击路线必须`selective=true + secondary_keys=["当前阶段：P6"]`或`enabled=false` |
| 重复段落 | 检查世界书条目内部重复长段落，防止用机械重复堆过enrichment |
| 阶段条目完整性 | 每条阶段条目必须包含所有必需维度 |
| **Build垃圾清理** | 删除所有以`【v1.1` 开头的补足/补强/加厚/门槛/余量等构建注释——这些是开发过程的临时笔记，留在世界书里占token且对AI跑卡无任何价值 |

**Build垃圾清理经验（2026-07-18·艳母v1_1清理93处）**：卡经过多轮迭代构建后，条目末尾会积累大量「补足」「补强」「加厚」「门槛」「余量」「角色过线」等开发笔记。这些条目通常是构建脚本自动追加的，格式为 `【v1.1最终加厚-角色名】补充说明……`。发现方法：在JSON中搜索 `v1.1`，统计条目数。清理方法：用正则 `【v1\.1.*?】` 匹配并逐条删除。**清理后对AI跑卡效果有显著正面影响**——因为AI不再读到这些无意义的开发注释。

交叉审查/返修的私有实证案例不随公开版分发；公开版只保留可迁移的检查顺序与方法。分版本返修/收口流程见 `references/workflows/progressive-card-versioned-repair.md`（v1.14结构清理→v1.15人物关系场景→v1.16核心事件包→v1.17冷启动QA→v1.18可选长测）。

## 7. 生产级规划书门槛（避免把分析文档误当规划书）

递进式世界书必须区分两类交付物：

| 交付物 | 作用 | 不足 |
|---|---|---|
| 阶段心理/重构分析文档 | 证明已理解小说递进曲线、旧卡失败原因、阶段边界 | 不能直接开工生成JSON |
| 生产级世界书规划书 | 可直接指导构建，每条世界书可落地 | 必须在生成JSON前完成 |

生产级规划书至少包含：

1. **参考卡逐条分析**：逐条列出参考卡世界书 id/comment/constant/selective/enabled/keys，并标注“借鉴/适配/不照搬”。不能只说“参考了阶段设计”。
2. **旧卡失败点映射**：指出旧卡哪些条目造成阶段污染（如后期称呼/人物/场景出现在常驻或早期条目）。
3. **完整条目表**：每条新世界书必须列出 ID、comment、keys、secondary_keys、constant、selective、enabled、position、阶段归属、内容目标。
4. **阶段污染规则**：明确每阶段禁止提前出现的称呼、地点、人物和协议；规划阶段就要定义后续脚本检查项。
5. **开场白阶段入口**：每条开场白绑定章节来源、当前阶段、允许素材、禁止素材，并包含HTML阶段注释模板。
6. **复用/推倒清单**：说明旧素材哪些只作为事实库复用，哪些结构必须重写。

当用户要求“看看参考资料/新的规划书”时，先盘点目录并判断是否真的存在生产级规划书；如果只有分析文档或旧版归档，应明确说“资料够做输入，但还缺生产级规划书”，不要默认进入JSON构建。
