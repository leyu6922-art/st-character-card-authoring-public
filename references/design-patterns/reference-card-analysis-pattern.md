# 参考卡深度分析模式（2026-07-18·艳母的荒唐赌约实证）

> **问题**：用户提供参考卡（如《参考卡.json》）时，不能只看"结构思路"——必须逐条分析世界书条目，提取具体可借鉴的设计模式。
> **用户纠正**：只说"参考了阶段设计"是不够的。必须列出每条条目的设计模式，标注"借鉴/改/不照搬"，并映射到新卡架构。

---

## 1. 参考卡分析流程（6步）

当用户提供参考卡 JSON 时：

### Step 1: 列出所有世界书条目

逐条列出 id、comment、constant/selective/enabled、keys、position。这是分析的基础。

### Step 2: 识别每条的设计模式

每条条目归类为以下模式之一：

| 模式 | 特征 | 典型例子 |
|------|------|---------|
| 角色档案 | constant+keys非空，内容=人物信息 | 顾清裕(id0) |
| 行为指南 | constant，内容=场景类型×行为规范 | NSFW指南(id1) |
| 事件系统 | constant+含触发/告知/干预/执行结构 | 绿帽事件系统(id2) |
| 阶段条目 | constant或keys触发，内容=阶段×行为标志 | 情感阶段(id3) |
| 视角/描写控制 | constant，内容=描写比例/视角规则 | NSFW内容生成指南(id4) |
| 驱动机制 | constant，内容=为什么故事必须发生 | 素心照月功(id5) |
| 终阶段专属 | constant或keys触发，内容=终阶段行为变化 | NSFW终极篇(id6) |
| 过渡阶段 | constant，内容=过渡期心理/行为 | 混沌期(id7) |
| 多入口触发 | keys触发，多个keys指向同一内容 | 归真期(id8)+终极阶段(id9) |
| 变量控制器 | preprocessing+getvar/setvar | 事件控制器(id10) |
| 事件种子 | keys触发，含叙事+逻辑标记 | 事件_混沌期刺杀(id11) |
| 事件后沉淀 | constant，内容=事件后情感/独白 | 日记(id12) |

### Step 3: 标注每条的借鉴决策

对每条标注三种决策之一：

- **✅ 借鉴**：设计模式可直接用于新卡，只需换内容
- **🔄 适配**：设计模式需要改造才能用于新卡（如维度不同、触发方式不同）
- **❌ 不照搬**：设计模式不适合新卡，明确写出原因

### Step 4: 映射到新卡架构

将借鉴/适配的模式映射到新卡的具体条目层级。例如：

```
参考卡"情感阶段"(id3) → 新卡 Layer 2 阶段状态层
参考卡"事件系统"(id2) → 新卡 Layer 4 事件种子层（增加干预窗口）
参考卡"驱动机制"(id5) → 新卡 Layer 0 赌约/协议索引
```

### Step 5: 提取增量设计元素

从参考卡中提取新卡原本没有的设计元素。这是最有价值的部分——用户让你参考这张卡，就是因为里面有你没想到的东西。

常见增量元素：
- **干预窗口**：事件触发后用户有时间干预（参考卡的事件系统）
- **阶段行为标志**：每阶段写5维行为差异（参考卡的情感阶段）
- **阶段内嵌心理独白**：角色在阶段内的真实想法（参考卡的日记系统）
- **多入口触发**：同一内容用多个keys触发（参考卡的归真期+终极阶段）
- **事件种子含叙事**：事件不是空壳而是有完整场景文本（参考卡的刺杀事件）

### Step 6: 写入规划书的专门章节

参考卡分析结果必须写入规划书的独立章节（如"§二、参考卡设计模式分析"），不能只在脑子里记着。用户需要看到你具体借鉴了什么、为什么不照搬什么。

## 2. 常见反模式（避免）

| 反模式 | 为什么不行 |
|--------|-----------|
| "参考了阶段设计思路" | 太笼统，用户不知道你具体借鉴了什么 |
| "结构有价值" | 空话。什么结构？哪条条目？什么设计模式？ |
| 只看条目数和大小 | 参考卡的价值在设计模式，不在体积 |
| 照搬剧情/关系模型 | 参考卡的小说和目标卡的小说完全不同 |
| 忽略非显眼条目 | 事件控制器(id10)、日记系统(id12)等"辅助条目"往往有最有价值的设计模式 |

---

## 3. 与渐进式世界书的关系

当目标卡使用**渐进式世界书**（阶段状态机）架构时，参考卡分析尤其重要：

- 参考卡的**阶段条目**设计直接影响 Layer 2 的写法
- 参考卡的**事件系统**设计直接影响 Layer 4 的写法
- 参考卡的**驱动机制**设计直接影响 Layer 0 的写法
- 参考卡的**事件后沉淀**设计可以丰富阶段条目的内容

渐进式世界书详见 `references/design-patterns/progressive-worldbook-design.md`。

如果用户要求横向判断“两张卡哪张更好”（而不是要求把参考卡拆解后写入规划书），使用 `references/workflows/card-comparison-review.md`：同时比较素材厚度、跑卡稳定性和交付合规性，并先给评价结论，不默认返修。
