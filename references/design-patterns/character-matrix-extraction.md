# 多方位矩阵文档提取模式（小说→角色卡中间产物）

> **状态**：2026-07-19·艳母的荒唐赌约多方位矩阵文档提取
> **核心理念**：对于100+章的大型小说，不能直接从原文跳到角色卡JSON——需要一个结构化的"角色矩阵文档"作为中间产物，把小说中分散的行为/态度/关系/心理信息按维度聚合。

---

## 1. 何时需要

| 条件 | 判断 |
|------|------|
| 小说章节 > 30章 | ✅ 需要矩阵文档 |
| 核心女性角色有3+个不同男性关系 | ✅ 需要矩阵文档 |
| 角色状态随剧情显著变化 | ✅ 需要矩阵文档（配合渐进式世界书） |
| 小说 < 10章且关系简单 | ❌ 直接用小说全方位提取.md |

---

## 2. 文档结构模板（11节）

```markdown
# {角色名} 多方位矩阵文档

## 一、人物基础档案
  身份/外貌/核心需求/恐惧/防御机制/决策方式

## 二、NSFW行为矩阵（按对象分类）
  每个男性一个子节，每个包含：
  - 关系定位（一句话）
  - 性行为演变轨迹表（阶段/章节/行为内容/玉诗状态）
  - 专属称呼与互动模式
  - 态度关键词
  - 关键对话原文（带章节标注）
  - 阳具特征（尺寸/形状/女性反应）

## 三、态度/心理矩阵
  - 多人态度光谱对比表（公开/私下调教/身体反应/心理状态）
  - 心理防线崩溃轨迹（阶段→关键事件→状态变化）
  - 核心心理矛盾表（矛盾维度/表现/代表章节）

## 四、行为模式库
  - 情绪反应模式（7种：害羞/愤怒/享受/矛盾/服从/恐惧/自信）
  - 性行为特征模式（敏感度/高潮表现/体位偏好/口交/肛交等）
  - 社交行为模式（面对不同人的行为差异）
  - 日常行为模式

## 五、关系演变时间线
  每个重要关系一条弧线，用时间轴格式

## 六、关键场景语料库
  按类型分类：征服/羞耻/商业精英/性爱描写
  每条含：原文引用+章节标注

## 七、差异化矩阵
  如：阳具差异化矩阵（尺寸/形状/反应/核心能力）

## 八、场景-反应矩阵
  不同场景下对不同人的反应差异表
  暴露程度阶梯（从1级到N级）

## 九、补充行为语料库（原文精读补充）
  从子代理/补充阅读中提取的细粒度语料

## 十、特殊维度分析
  如：恐惧层级分析（从最高到最低）
  恐惧/欲望演变曲线

## 十一、角色的多面性
  如：商业精英面、母性保护面、被征服面等
```

## 3. 提取流程

### 3.1 第一轮：参考资料扫描
1. 读取已有的"小说全方位提取.md"（如果存在）
2. 读取已有的角色卡JSON（如果存在旧版）
3. 读取章节摘要报告（如果存在）

### 3.2 第二轮：原文精读（并行子代理）
对资料不充分的章节范围，派2-3个并行子代理分段读取：
- 子代理1：前段（如第25-38章）
- 子代理2：中段（如第40-60章）
- 子代理3：后段（如第63-97章）
每个子代理输出：NSFW场景/对话/关系变化/心理时刻

### 3.3 第三轮：关键章节补读
对子代理未覆盖的关键章节（如最后20章），直接用execute_code批量提取关键词行

### 3.4 合并写入
将所有数据按11节结构合并写入矩阵文档

## 4. 与现有文档的关系

| 文档 | 定位 | 内容焦点 |
|------|------|----------|
| 小说全方位提取.md | 世界观+人物档案+事件时间线 | 全局视角，覆盖所有角色和事件 |
| 章节摘要.md | 逐章事件记录 | 按章节顺序，事件粒度 |
| **多方位矩阵文档.md** | **角色行为/态度/关系聚合** | **按维度聚合，聚焦核心女性角色** |
| 递进式世界书规划.md | 世界书条目设计 | 条目ID/keys/阶段归属 |
| 成人素材加厚规划书.md | 具体加厚执行方案 | 哪些条目需要补充什么内容 |

多方位矩阵文档是**角色卡构建的核心输入**——它把分散在120章中的角色信息按维度聚合，让构建者可以直接查找"玉诗对赵勇的NSFW行为演变"或"玉诗在不同场景下的恐惧层级"。

## 5. Pitfalls

### P1：不要跳过矩阵文档直接做卡
对于大型小说，直接从原文跳到JSON会导致：
- 角色行为不一致（不同阶段的描写冲突）
- 关系演变不连贯（缺少中间过渡）
- NSFW内容厚此薄彼（某些关系写得薄）
- 对话语料不足（AI生成时缺乏原文锚点）

### P2：矩阵文档必须有原文引用
每个行为/态度/反应必须标注章节来源。纯概括（如"玉诗对赵勇很依赖"）不够——需要原文对白和描写作为AI跑卡的素材。

### P3：并行子代理的章节分配要均匀
不要让一个子代理读50章而另一个只读10章。按章节大小和内容密度均匀分配。

### P4：矩阵文档是活文档
在角色卡迭代构建过程中，如果发现某个维度数据不足（如某个男性的语料太薄），应回到矩阵文档补充，而不是在JSON里临时编造。
