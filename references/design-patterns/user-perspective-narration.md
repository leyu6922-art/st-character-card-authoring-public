# {{user}}视角与旁白解说机制

> Extracted from SKILL.md lines 319-445 (2026-07-05 示例玄幻项目案例总结)

## {{user}}视角原则

开场白和正文必须用"你"来描写{{user}}的感官体验，不是第三人称旁观。

```
❌ 第三人称旁观：王启坐在桌前，看着照片狞笑。
✅ {{user}}视角：你从一阵剧烈的咳嗽中醒来。嘴里全是灰尘和霉菌的味道。
```

玩家就是{{user}}，不是在看别人的故事。

## 旁白解说机制（Inline Narrator）

当卡有复杂机制（超自然道具、特殊规则、多阶段系统）时，用旁白在正文关键段落旁实时解释，而不是在开场白末尾堆一坨说明。

**格式**：`【旁白：解说内容】`（方括号标签，不带星号——星号会被预设正则隐藏）

**⚠️ 旁白的星号格式可能被预设正则隐藏（2026-07-08 实测修正）！**

许多ST预设带有"隐藏内心话"正则脚本，匹配 `/\*[\s\S]*?\*/g`（所有`*...*`包裹的内容）。旁白的 `*【旁白：xxx】*` 格式正好被这个正则捕获并隐藏——用户看不到旁白。

**修复方案**：旁白格式改为不带星号的方括号标签：`【旁白：解说内容】`。

**⚠️ 旁白规则在system_prompt中大概率被预设覆盖（2026-07-08 实测修正）！**

预设的指令权重远高于角色卡的system_prompt。不管哪个预设，它们都会用自己的框架覆盖角色卡里的规则。旁白规则写在system_prompt里，效果极不可靠。

**更可靠的注入路径**：将旁白规则写为世界书的**常驻条目**（`constant=True`, `position=0`），而非system_prompt。世界书条目在上下文中的位置比system_prompt更靠前，被预设吞掉的概率更低。

**⚠️ 如果角色卡是PNG文件，必须直接修改PNG内嵌的世界书！** 编辑外部世界书文件没有用——ST读的是PNG内嵌的`character_book`。

**⚠️ 旁白必须在system_prompt中显式声明规则（2026-07-08 实测修正）！**

模型不会因为first_mes里有旁白示例就自动延续这个格式。实测（示例玄幻项目）：first_mes有7段旁白，但AI后续回复完全没有旁白——模型只把它当作first_mes的特殊格式，不认为自己也需要用。

**修复**：在system_prompt的铁律后面添加显式规则：

```
【旁白规则】在叙事关键节点使用旁白解说，格式为【旁白：解说内容】（方括号标签，不带星号——星号会被预设正则隐藏）。旁白用于：
- 机制解释：道具的使用流程、指令效果、副作用等
- 风险提示：敌对角色在附近、使用道具的危险性
- 进度提示：角色数值变化、阶段跃迁条件
- 行动引导：列出当前可选的行动方案
- 角色心理：NPC的内心想法和潜意识变化
每轮回复至少包含1-2段旁白，穿插在叙事段落之间，不要集中在末尾。
```

**验证方法**：新开对话后检查AI回复是否包含`【旁白：`格式的段落。如果没有，说明system_prompt中缺少旁白规则。

**使用时机**：
- 开场白：密集使用（5-7段），一次性解释核心机制
- 正文：在关键节点使用（首次使用道具、首次亲密互动、阶段跃迁）
- 不要每段都加，只在需要解释机制时使用

**旁白内容类型**：
- 机制解释："这就是恶魔相机的血祭仪式——拍照、血书、点燃、碎片飞回"
- 风险提示："注意：龙傲天就在隔壁，使用相机极其危险"
- 进度提示："角色D的堕落值已达50，即将进入下一阶段"
- 行动引导："你可以选择：A.继续使用相机 B.等待角色D主动来访"

**示例（示例玄幻项目开场白片段）**：
```
你从枕头底下摸出那部冰冷的金属仪器——恶魔相机。外壳像某种活物的鳞片，
在昏暗灯光下折射出暗紫色微光。

【旁白：恶魔相机是你唯一的武器。它可以摄取目标的灵魂碎片，通过血祭仪式
下达指令，操控对方的心理和行为。但每次使用都会消耗你的灵魂——噩梦、暴虐
冲动、甚至被相机内的冤魂吞噬，都是代价。】

桌上摆着一张照片。照片里一男一女……

*【旁白：龙傲天是你最恨的人。不是因为过节，只是纯粹的嫉妒。角色D是他
最珍视的女人，也是你第一个目标。注意：龙傲天武功极高，能感知灵魂波动。
在他附近使用相机极其危险。】*
```

**效果**：玩家边读故事边理解机制，不需要跳到末尾看说明。

## 状态栏强制显示

在system_prompt中用铁律强制AI每次回复第一行显示状态栏：
```
【铁律】每次回复的第一行必须是状态栏。不可省略、不可模糊、不可用"同上"代替。
```

**⚠️ 开场白豁免条款（2026-07-07 实测修正）**：

system_prompt铁律要求"每次回复第一行必须是状态栏"，但first_mes和alternate_greetings通常不以状态栏开头。这会导致AI第一轮困惑——规则说必须有，但示例没有。

**解决方案**：在铁律后加豁免条款：
```
【铁律】每次回复的【第一行】必须是状态栏。格式参见世界书"状态栏系统"条目。不可省略，不可模糊，不可用"同上"代替。例外：开场白（first_mes/alternate_greetings）中可以省略状态栏，从第二轮开始必须显示。
```

**替代方案**：在开场白开头补状态栏（更一致但增加字数）。

状态栏应包含：角色状态、关系阶段、量化数值、时间/地点/在场、活跃指令。

## 主动剧情推进规则

在system_prompt和世界书中加入NPC主动行动规则，避免AI被动等待：
- NPC有自己的行动逻辑，会主动找{{user}}
- 时间跳过时AI主动推进并触发事件
- 每3-5轮完成一个小事件，不要让剧情停滞
- 用NPC的行动或环境变化来推动场景转换
