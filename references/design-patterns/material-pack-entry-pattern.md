> **历史/legacy 路线边界**：本页 `阶段P#` marker 素材包来自旧 external route_state 架构。它不能作为 native Greeting-title 卡的阶段 key；native 素材必须并入相应四包，并以完整 Greeting 标题精确绑定。

# 素材包条目设计模式（Material-Pack Entry）

> **状态**：2026-07-19 · 艳母的荒唐赌约 v1.17.3 首次完整实施
> **核心问题**：阶段路由、关系逻辑、人物心理框架已经就位，但"触发后 AI 有框架没血肉"——缺少可直接调用的成人向素材（调情语料、淫语句库、身体反应链、性事件示例）。
> **本方案**：新增独立的"素材包条目"，与行为/规则条目职责分离，以 keys=阶段P# + position=4 跟随阶段触发，不修改路由。

---

## 1. 为什么需要独立的素材包条目？

### 1.1 传统做法的两个死胡同

**死胡同A：把成人素材塞进旧条目**
- 关系条目（id 17-28）职责是"关系逻辑/行为边界"——再加成人素材会变成大杂烩
- 阶段主条目（id 10-16）职责是"阶段状态/规则"——加成人素材会模糊阶段规则
- 人物基础条目（id 5-9）职责是"跨阶段不变量"——加成人素材会变成全文堆砌

**死胡同B：用事件种子承载成人素材**
- 事件种子默认 disabled，普通跑卡时 AI 读不到
- 事件种子是"按需触发的事件核"，不是"每轮随身的素材库"
- 事件种子有严格的前置条件/干预窗口/默认走向结构

### 1.2 素材包条目定位

```
独立新增，不改旧条目
跟随阶段自动触发（keys=阶段P#，不依赖 secondary）
position=4 (after_char)，不抢阶段规则主导权
与旧条目互补：旧条目提供"发生了什么→怎么反应"，素材包提供"说着什么话→身体怎么失控"
```

## 2. 条目模板

```json
{
  "id": 72,                    // 紧接原最大 id 之后
  "keys": ["阶段P0"],           // 跟随阶段自动触发；不加 secondary
  "secondary_keys": [],
  "comment": "成人素材·阶段P0·火玫瑰基准线",
  "content": "【本阶段成人向核心味道】\n...",
  "constant": false,
  "selective": false,
  "enabled": true,
  "position": 4,               // after_char
  "extensions": {
    "position": 4,
    "depth": 4,
    "scan_depth": 2,
    "probability": 100,
    "match_whole_words": false,
    "selective": false,
    "sticky": 0
  }
}
```

### 关键参数说明

| 参数 | 值 | 原因 |
|------|-----|------|
| keys | `["阶段P#"]` | 跟随阶段稳定触发。不加自然语言 key、不加 secondary |
| selective | false | 不需要 secondary 过滤——素材是全局的，只按阶段划分 |
| position | 4 (after_char) | 素材包是"辅助资料"而非"行为规则"，放在正文后不抢主导 |
| scan_depth | 2 | 只扫描最近 2 条消息，避免旧阶段素材残留 |
| sticky | 0 | 不黏着——切阶段后旧素材自然掉线 |
| probability | 100 | 确保每次触发都加载 |

## 3. 内容模板（7 段式）

每条素材包 1500-2600 中文字，7 个结构化段落：

```text
【本阶段成人向核心味道】
一句话定性本阶段的性张力——"P1 是身体防线第一次被打穿"、"P4 是规则压迫下的屈服"。
不写抽象规则，写"这阶段的肉味本质是什么"。

【妈妈对不同人的性反应差异】
- 对赵勇/第一征服者：最放松、嘴硬但身体诚实、关系从征服→玩伴
- 对骆鹏/规则控制者：最紧绷、语言防御失灵、从警惕→服从→工具化
- 对向晓东/粗变量：轻蔑中带好奇、工具化使用、身体冲击大于心理
- 对刘宇/{{user}}：最复杂——身份压力、被儿子看见的羞耻、情感纠缠
- 对外部人物（P5/P6 阶段）：警惕与利用交替、熟人社会压力

【调情语料】
6-12 句可直接给 AI 套用的调情对白。分角色写，不要同一种语气。
必须贴近原文味道——从原文章节提炼或高度仿写，禁用通用黄文话术。

【淫语/羞辱/挑逗句库】
4-8 句按"谁对谁说什么 / {{user}}如何听见"拆分。
重点保留原文的称呼梯度（阿姨→浪姐→浪奴）和语言权力关系。

【身体反应链】
3-4 条完整链条。每条包含：触发动作 → 女主第一反应 → 嘴上防御 → 身体背叛 → 对方推进 → 事后残留。
格式：A → B → C → D → E（用 → 箭头连接，每条 80-150 字）。

【性事件示例】
2-3 个短事件，每个 200-400 字。
必须有：地点、人物、动作推进、对话、{{user}}视角、事件后关系变化。
每个示例就是一个可直接展开的性场景种子。

【禁止提前出现】
列出本阶段不能使用的后期称呼、协议、外部人物、行为。
例如："不允许出现'浪奴'（那是P4的事）""不允许出现小区保安（那是P6的事）"
```

## 4. 生产流程

### 4.1 素材来源

必须从原文章节提取，不要 AI 凭空编。

```bash
# 工作流
1. 确认每个阶段对应的章节范围（如 P1 = ch03-ch09）
2. 读取关键章节，记录：对白片段 → 场景描写 → 行为链 → 称呼/语言梯级
3. 整理成采集表（每阶段一个文件或 JSON 块）
4. 按 7 段式模板写素材包
5. 验证：至少 8 句原文/近原文对白 + 3 处以上原文场景细节 + 3 条以上原文行为链
```

### 4.2 CJK 内容写入（重要 pitfall）

Python `execute_code` 中直接写 CJK 长字符串会触发 `SyntaxError: invalid character '。' (U+3002)` 等错误。

**可靠工作流**：

```text
step 1: write_file → 把纯文本内容写入独立的 .txt 文件（无 lint 检查，支持 CJK）
step 2: execute_code → 读 .txt 文件内容，组装成 JSON entry，写入角色卡
step 3: 清理临时文件
```

### 4.3 写入后修复 extensions

新条目用最小模板写入后，`validate_card.py` 会报 `缺少顶层字段: ['addMemo', 'insertion_order', 'use_regex']` 和 `extensions缺少字段: [...]`。

修复方法：从**已有通过 validate 的条目**（如 id=10 阶段主条目）复制扩展字段模板：

```bash
1. tpl = entries_by_id[10].get("extensions", {})
2. 对每个新条目：缺失的 k、v 从 tpl 复制
3. 特别注意：top-level 的 addMemo=True、insertion_order=100、use_regex=True
```

## 5. 与现有条目类型的对比

| 维度 | 阶段主条目 | 关系条目 | 事件种子 | **素材包条目（本模式）** |
|------|-----------|---------|---------|----------------------|
| 职责 | 阶段状态/规则 | 关系逻辑/边界 | 事件核 | **语料/句子库/反应链** |
| enabled | true | true | false | true |
| selective | false | true | true | false |
| secondary | 无 | ROUTE_STAGE=P# | ROUTE_STAGE=P# | 无 |
| position | 0 (before_char) | 4 (after_char) | 0 (before_char) | 4 (after_char) |
| 触发 | 阶段 marker | primary+secondary | 用户手动启用 | 阶段 marker |
| AI 用途 | "当前什么规则" | "关系怎么发展" | "如果选这个事件" | **"说什么、什么反应"** |

艳母的荒唐赌约 v1.17.3（2026-07-19）：

## 7. 扩展方向

- 如果素材包内容过多（超过 3000 字），可以拆成"轻素材包"（仅语料）和"重素材包"（全文）两个条目
- 如果单阶段有多个不同男性角色，可以按角色拆分（如"P1·赵勇专供素材包"）
- 素材包的 position=4 保证不抢规则条目前置，但如果 AI 仍然不引用素材，可以在 OOC 条目中追加"请查看最近的素材库条目"
