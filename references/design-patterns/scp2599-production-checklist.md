# SCP-2599式规则驱动开放卡 · JSON生产检查清单

> 来源：SCP2599_苏小满卡生产会话（2026-07-17）
> 用途：计划书已定稿后，直接生产 chara_card_v3 JSON；不要重新评审计划书或扩展大设定讨论。

## 1. 生产定位

当用户明确说“计划书已定稿，直接生产 JSON”时：

1. 只读取计划书与本 skill 的规则驱动参考文件。
2. 不重新评审计划书，不展开新设定讨论。
3. 按计划书条目清单直接组装卡片。
4. 完成后用真实脚本验证，而不是口头声称通过。

## 2. 结构要点

SCP-2599式开放卡通常不是传统NTR/守护/G型；核心是“知情男友规则操盘型开放卡”。

推荐固定结构：

- 顶层与 data 层同步：name / description / personality / scenario / first_mes / mes_example。
- `spec = chara_card_v3`，`spec_version = 3.0`；data 层也必须双写。
- `data.character_book.entries` 内嵌世界书。
- 世界书精简 10 条：世界观、规则引擎、核心女友、3个NPC、校园群像、NSFW文风、旁白、状态栏。
- 少事件、重机制、重角色、多入口、状态栏；不要生成固定事件线。

## 3. 开场白数量坑

如果计划书列出“开场白1 = first_mes，开场白2-4 = NPC入口”，但 validate 要求 `alternate_greetings >= 4`：

- `first_mes` 使用开场白1。
- `alternate_greetings` 放开场白2-4。
- 额外补 1 条不锁线的中性入口，例如“二人独处 / 安全解除 / 自然亲密 / 残留压力”入口。
- 额外入口必须服务机制，不要新增固定剧情路线。

## 4. 触发词与验证负载

规则驱动卡的状态栏和开场白会频繁写到 NPC 名字；如果选择性 NPC 条目用普通字符串 key（如 `沈知行`、`赵猛`、`陈翰`），可能导致所有 greeting 都触发全部 NPC 档案，validate 出现触发负载偏高。

可用 regex key 避开状态栏 `NPC察觉|沈知行:` 这类冒号标签：

```json
沈知行: ["/(?:沈知行(?!:)|沈学长|沈师兄)/"]
赵猛:   ["/(?:赵猛(?!:)|痞子同学|体育生赵猛|那个体育系的)/"]
陈翰:   ["/(?:陈翰(?!:)|陈教授|陈老师|舞蹈教授)/"]
```

同时在无关 greeting 的状态栏里尽量写“其他外部压力源未在场”，避免为说明未出场而误触发角色档案。

## 5. 规则引擎必须覆盖

规则引擎条目必须完整写入以下硬点：

- 命令 vs 建议边界。
- 规则二：命令目标无法完全完成。
- 三通道失败：身体 / 注意 / 情境。
- 否定命令 = 持续性任务 + 失败结果池；不是语义反转。
- 边界侵蚀是慢变量，只在连续愧疚补救 + NPC持续施压 + 未安全解除时逐步发生。
- 命令压力场：多命令不覆盖，按即时性/具体性/距离/情绪/权威/{{user}}情感重量竞争。
- 安全解除 = 压力衰减，不是魔法句式；危险解除本身可能成为新命令。
- 自我要求不触发异常。
- 真相揭露后不等于免疫。
- NSFW 中区分“命令目标 / 副产物 / 自然反应”。

## 6. 状态栏格式

每个开场白末尾都应包含完整状态栏，且保留这些字段：

```text
<char_status>
[角色名|苏小满]
[衣着|...]
[表情|...]
[主导命令|...]
[活跃命令|...]
[残留压力|...]
[最近失败|...]
[边界完整度|...]
[关系压力|...]
[NPC察觉|沈知行:...；赵猛:...；陈翰:...]
[心声|...]
</char_status>
```

心声必须是苏小满第一人称，并且不知道异常；只能自责、困惑、努力理解或求助。

## 7. 专项扫描

validate_card.py 通过后，还要额外脚本扫描：

- JSON 结构、top/data 同步、entry count、alternate count。
- entries / extensions / position / addMemo。
- 状态栏字段是否在所有 greeting 中存在。
- 是否存在单字触发词。
- 是否误写“对NPC下命令有异常强制力”。
- 是否把边界侵蚀写成必然结果。
- 是否让苏小满知道/推理出异常。
- 是否让NPC知道SCP规则。

## 8. 8类机制测试报告

交付时用简短表格报告以下 8 项是否 PASS：

1. 明确命令。
2. 普通建议。
3. 否定命令。
4. 多命令冲突。
5. 安全解除。
6. NPC察觉。
7. 真相揭露。
8. 自然亲密不触发规则。

## 9. 交付话术

最终回复只给：

- 输出路径。
- validate_card.py 真实结果。
- 关键结构统计。
- 专项扫描结果。
- 8类机制测试表。

不要粘贴大段 JSON，不要重新解释计划书。
