# 世界书触发专项审查模板

> 用于新卡交付前、旧卡修复前/后、社区反馈截断/回空/误触发时。目标是确认条目触发有逻辑、稳定、可解释；不是单纯压 token。

## 使用方式

在 skill 根目录运行：

```bash
python scripts/audit_worldbook_triggers.py <卡.json> -o <触发审计报告.md>
```

同时保留 `validate_card.py` 输出。两者职责不同：

- `validate_card.py`：阻断结构错误和硬错误。
- `audit_worldbook_triggers.py`：生成可读触发矩阵，辅助判断触发设计是否合理。

## 1. 触发意图是否清晰

逐类检查：

| 条目类型 | 合理触发方式 | 不合理信号 |
|---|---|---|
| 系统/OOC/状态栏 | constant=true, keys=[] | 常驻条目带keys、每轮强制项过多 |
| 核心角色速览 | 自然角色名/常用称呼触发，250-600中文字，自足可用 | 只有“角色名档案”死key；速览太薄 |
| 深度档案/语料库 | 专用key按需触发，comment标注“深度/专用key/按需” | 未标注按需却所有opening不触发 |
| 场景条目 | 具体地点/场景词；需要范围时 selective=true + secondary_keys | `家/学校/房间/手机/日常` 等泛词无范围绑定 |
| 关系/NTR矩阵 | 角色A×角色B、关系专名、阶段词 | 多个角色共用一个大条目，任一key触发整包 |
| 事件种子 | enabled=false 或专用剧情key | 被first_mes误触发、变成首轮固定剧情 |

## 2. 必修问题

以下任一存在即必须修：

1. `secondary_keys` 非空但顶层 `selective=false`：副词被 ST 忽略。
2. 仅 `extensions.selective=true` 而顶层 selective 不为 true：ST 读取顶层字段。
3. 硬泛key误触发：`家/人/你/学校/老师/妈妈/妹妹/手机/日常` 等普通句能触发。
4. first_mes/alternate 拉入无关深度档案。
5. 核心角色/威胁档案只有“档案/设定”这类人工复合key，正常聊天永远不触发。
6. 速览+深度档案模式中，速览低于250中文字或不能独立支撑基础描写。
7. 多主题大条目任一角色名触发整包无关内容。

## 3. 普通句反证

至少检查报告中的普通句反证。原则：普通闲聊不应加载剧情/场景/深度档案。

| 普通句 | 期望 |
|---|---|
| 我要回家。 | 不触发泛“家”场景；若触发必须是明确“林家宅/比企谷家”等专名 |
| 学校今天很安静。 | 不触发全部校园深度场景 |
| 有人在房间里唱歌。 | 不触发私密房间/卧室深度条目 |
| 你看见那个人了吗？ | 不触发“人/你”泛key |

## 4. 高负载判断边界

高字符数/高请求体不是自动失败。先问：

1. 触发内容是否相关？
2. 是否由泛key/secondary失效造成？
3. 是否把无关深度档案拉进首轮？
4. 是否卡内写死太多每轮强制输出项？
5. 用户是否已实测稳定多轮运行？

如果触发审计合格且多轮稳定运行，即使请求体很大，也不判卡失败。外部预设/API/模型安全问题按 `references/st-technical/card-vs-runtime-boundary.md` 处理。

## 5. 修复顺序

1. 结构字段：selective/secondary/top-level 与 extensions 同步。
2. 泛key：删除单字/普通词，改专名或范围绑定。
3. first_mes误触发：拆速览/深度档案，深度档案专用key按需。
4. 多主题条目：按角色/关系/场景拆分。
5. 常驻输出项：只审卡内强制项，必要时合并/按需。
6. 重跑 `validate_card.py`。
7. 重跑 `audit_worldbook_triggers.py`，确认普通句反证清零或有合理解释。

## 6. 报告结论格式

```text
触发审计结论：通过/需修复。
主要证据：secondary被忽略 X→Y；硬泛key X→Y；first_mes触发条目/字符变化；普通句反证结果。
剩余warning：列出事件种子enabled=false、按需素材首轮不触发、常驻数量偏高等是否符合设计。
边界说明：若某预设/模型偶发截断但卡内触发审计通过，按运行环境问题备注，不作为角色卡结构失败。
```
