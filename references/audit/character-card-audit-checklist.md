# 角色卡条目质量审查清单

## 审查维度

对每个世界书条目（character_book.entries[]）执行以下5项检查：

### 1. 常驻条目深度
- **A级**：≥500字，有实质世界观/规则/角色设定内容，不灌水
- **B级**：300-500字，内容有用但不够深入，缺少细节或示例
- **C级**：<300字，或内容空洞/重复已有条目

### 2. 对话示例角色声线一致性
- 对话必须体现角色的核心人格特征和情感弧线
- 关键检查点：
  - 角色前后变化是否有对比（如黑化前后的用语差异）
  - 关键事件后的微妙态度变化是否体现在措辞中
  - 不同角色之间的声线是否有区分度（不是所有人说话方式一样）
  - 声线要符合角色背景（商人角色有算计感、公主角色有傲慢感等）

### 3. 行为模板可用性
- **A级**：具体到场景、动作序列、触发条件，AI可直接执行
- **B级**：有方向性描述但缺少具体动作序列
- **C级**：仅笼统描述（如"表现忠诚"），无可用细节

### 4. 触发条件重叠检查
- 多个条目使用相同/相似keys时会产生触发冲突
- 特别关注：同类型事件条目（如多个NTR事件触发条目）
- 解决方案：细化keys到具体场景，或使用selective模式+secondary_keys区分

### 5. 条目间联动检查
- 系统性条目（威慑度、堕落度等）应与其他条目形成因果链
- 检查：状态变量变化 → 角色行为变化 → 场景反应 的传导是否完整
- 缺失联动 = 世界书有状态系统但条目行为不随状态变化

## 输出格式

```
条目ID | 质量评级(A/B/C) | 问题描述 | 修复建议
```

示例：
```
ID=12 | B | 常驻条目仅350字，角色背景缺少童年创伤细节 | 补充童年经历段落，增加与指挥官相遇的具体场景描写
ID=15 | C | 触发keys["NTR事件","堕落"]与ID=14完全重叠 | ID=15改为keys["不挠","cosplay"]，细化到角色专属场景
ID=20 | B | 行为模板只写"表现热情"，缺少具体动作 | 增加：主动拉手、靠肩、用胸部蹭手臂等具体行为序列
```

## 审查流程

1. 先列出所有条目的ID、名称、keys、content长度概览
2. 逐条目审查5个维度，标注评级
3. 交叉检查：keys重叠、条目间联动缺失
4. 汇总输出审查表 + 优先修复建议（C级优先，联动缺失次之）
