> 版本: v1.5（2026-07-15 · G型审查拆为 G-Common/Greeting/选开三层；选开模式为默认）
> 覆盖: 全部卡片原型 + G型双模式 + F型复用审查 + 修卡场景

---

## 使用流程

**任何卡审查 = 模板1(初始卡·结构层) + 该原型对应的内容层模板。**

```
做完卡 →
  ① 跑 validate_card.py（自动门控）
  ② 按初始卡模板 逐步骤审查结构层
  ③ 按卡原型选择内容层模板 逐步骤审查
  ④ 输出综合报告 → 修复 → 重跑validate_card
```

## 各模板审查维度

### 模板1：初始卡审查（所有卡第一步）
- Step 0: validate_card.py（硬性门控）
- Step 1: 读计划书
- Step 2: 计划书 vs 实际（按内容关键词映射）
- Step 3: 内容深度（弹性标准 + 计划偏差双维度）
- Step 4: 内部一致性（{{user}}身份/角色名/阶段矛盾/条目内重复/开场白角色覆盖）
- Step 5: 小说原文对照
- Step 6: 结构完整性（addMemo/extensions/position/keys/selective）
- Step 7: 输出审查报告

### 模板2：NTR苦主卡审查（A型）
- 堕落阶段闭环（4阶段定义→触发→行为→追踪）
- 苦主体验规则（自欺机制/预知天赋/废物定位）
- NTR男性行为逻辑独立性
- NTR关系矩阵覆盖完整性
- NTR场景描写库（当面绿帽/不同风格覆盖）

### 模板3：NTL变体卡审查（C型）
- {{user}}身份确认 + system_prompt完整性
- 条目类型分类 + 跨卡污染检测（清单A/B对比）
- NTR矩阵覆盖完整性
- 上下文判断（合理残留 vs 污染）
- 多卡相似度对比（区分"预期相似"和"应差异化"）
- Find-replace残留检查

### 模板4：守护卡审查（B/D型）
- 唤醒/觉醒系统闭环
- 决策树/多结局完整性
- 反转道具系统（代价/次数限制）
- 内部一致性（原版描写库的上下文说明）

### 模板5：禁忌后宫征服卡审查（E型）
- 保密系统闭环（公开/私下切换/安全等级/暴露后果）
- 公开/私下双模式完整性（每女主）
- 权力反差描写
- 场景安全等级一致性
- 多女主协调机制
- 反AI顺从（保密相关拒绝理由）

### 模板6：修卡审查

### 🆕 F型叙事观察卡审查（复用模板2变体）
- {{user}}身份必须是无形观察者/旁观者，而不是苦主或征服者
- system_prompt 必须定义观察/介入/回避三种行为模式及后果
- NPC必须能自主推进：观察者沉默时，施暴者/受害者仍按自身计划行动
- 介入必须有风险/限制，不能默认万能救场
- 旁白规则必须解释观察者机制、风险提示、行动引导
- 使用 NTR苦主卡模板时，删除“苦主体验/堕落闭环/NTR关系矩阵”硬检查，替换为“观察者规则/NPC自主推进/介入风险”

### 🆕 G型专项审查（多视角内置卡）

先判定触发模式：**选开模式是默认**；Greeting 模式是发布给不操作世界书 UI 用户的备选。两种模式共享 G-Common，但专项检查不同。不要把 greeting-secondary 要求套到选开模式。

#### G-Common（两种模式都必查）

| # | 检查项 | 方法 | 覆盖 |
|---|--------|------|:--:|
| C1 | 共用层零 `{{user}}` | grep 角色/场景/事件/语料 content；系统/身份条目例外需说明 | validate common |
| C2 | 人物关系锚点无相对称谓漂移 | 查“自己的妹妹/亲生母亲/父亲/侍妾”等，改成绝对关系 | validate warning + 人工 |
| C3 | 交付含“导入卡片世界书”说明 | 交付说明必须写清 ST 导入步骤 | 人工 |

#### G-A：Greeting 模式专项（备选）

| # | 检查项 | 方法 | 覆盖 |
|---|--------|------|:--:|
| A1 | 视角段 `selective=true + secondary_keys` | 检查条目字段 | check 42 |
| A2 | greeting 首行身份标记 | `【▎身份：XXX】 key1 key2` | check 45 |
| A3 | greeting-secondary key 对齐 | Python: `greeting_keywords ∩ entry_secondary_keys ≠ ∅` | check 42 |
| A4 | 每身份≥2条视角段 | 按 secondary_keys 分组计数 | check 44 |
| A5 | 视角隔离/多轮维持 | ST `<Lore>` 实测：只含对应视角段，连续4轮仍加载 | 人工 |

#### G-B：选开模式专项（默认）

| # | 检查项 | 方法 | 覆盖 |
|---|--------|------|:--:|
| B1 | 身份条目 `constant=true, enabled=false` | 非 false 会默认加载冲突；非 true 可能被误触发 | check 14/46 |
| B2 | comment 必须含「选开」 | 便于玩家在 ST 世界书 UI 识别 | check 46 |
| B3 | content 前300字明确定义 `{{user}}` | 必须能单独定义当前玩家身份 | check 46 |
| B4 | 不混用 selective/secondary | 选开靠手动启用，不靠 selective AND | check 46 |
| B5 | greeting 视角中性 | 不含身份标记/绑定某身份的行为和内心 | check 47 + 人工 |
| B6 | 交付含选开使用说明 | 导入世界书 → 每次只启用一个“选开”身份条目 | 人工 |

#### G-C：选开/自然触发契约专项（新门控）

| # | 检查项 | 方法 | 覆盖 |
|---|--------|------|:--:|
| C1 | 四类 `entry_role` 明确 | 读取 `extensions.entry_role`；旧卡推断只能作为迁移 warning | validator |
| C2 | 身份与功能开关分离 | `identity_toggle` 只能是身份；导演协议/场景边界必须是 `feature_toggle` | validator |
| C3 | 独立事件可达 | 每个自然事件至少覆盖人物/场景/行动三类中的两类，并用普通句做反误触发 | validator + trigger audit |
| C4 | 元标签不作唯一 key | `事件库/种子库/描写库/语料库/档案` 不得作为唯一 primary key | validator |
| C5 | 素材归属明确 | 描写/语料素材必须常驻或挂到角色、场景、事件自然路径 | 人工 |
| C6 | 破折号密度合理 | 连续破折号只用于对白打断/必要停顿，不代替正常叙事句法 | warning + 人工 |


### 模板6：修卡审查（原编号）
- 确认改动范围
- 改动条目逐条验证
- 波及范围检查
- 未改动但有联动风险的点
- 改动范围>15条自动升级为全量审查

## 设计原则

1. **全部通用版**：模板中的代码示例使用 `[方括号]` 占位符，agent从实际卡的system_prompt/计划书中提取具体值
2. **零硬编码**：不含任何小说专属角色名、地名、特征词
3. **先结构后内容**：模板1覆盖所有卡共通的格式/结构/一致性检查，模板2-5按原型覆盖专属内容层
4. **弹性标准**：字数检查有绝对底线+计划偏差双维度，不机械套数字
