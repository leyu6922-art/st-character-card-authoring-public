# 修卡审查启动模板（通用版）

> **两种使用模式**：
> - **制卡流程内**（agent自审）：直接读取本模板内容，按步骤逐项执行，不复制到新窗口
> - **交叉验证**（用户手动）：复制本模板全部内容→替换所有 `[方括号]` → 在新Hermes窗口发送
>
> 替换所有 `[方括号]` 内容为实际值。
> 修卡≠从零审查。修卡是"外科手术"——只查改动的条目+改动影响到的条目。

---

审查修改后的角色卡。**修卡模式下，只审查改动波及的范围，不全量重审。**

## 0. 确认改动范围
先问清楚（或从对话历史推断）：
- 改了哪些条目？（ID列表）
- 改了什么？（内容替换/新增段落/重写/新增条目/删除条目）
- 为什么要改？（用户反馈了什么具体问题？）

## 1. 跑脚本（每次修卡后必跑）
```bash
python "<HERMES_HOME>/skills/creative/st-character-card-authoring/scripts/validate_card.py" "[卡文件路径]"
```
同时生成触发回归报告：
```bash
python scripts/audit_worldbook_triggers.py [卡文件路径] -o [修卡触发回归报告.md]
```
若本次新增/重写了内容，再跑：
```bash
python scripts/enrichment_self_check.py [卡文件路径] --repair-mode
```
重点看**新增的error/P0**——修卡经常引入新问题：批量替换误改不该改的条目、新内容触发结构回归、constant条目keys被意外修改。

## 2. 改动条目逐条验证
对每个被修改的条目：
- ✅ 修改解决了反馈的问题吗？
- ✅ 修改是否引入了新矛盾？（读改动条目content，搜关键词看是否和其他条目冲突）
- ✅ 修改是否破坏了条目结构？（extensions字段丢失？constant标记被误改？keys被清空？）

## 3. 波及范围检查（修卡最易漏的）
修改了条目A→影响了条目B/C/D。**不要只改截图处**，先生成全卡 scan list：
```python
# 提取反馈/修改内容中的关键词（角色名/关系词/机制名/变量名/阶段名/道具名/key词）
# 扫 description/system_prompt/first_mes/alternate_greetings/entry comment/keys/secondary_keys/content
# 如果引用方式和修改后的定义不一致→矛盾
# 关系称谓重点：自己的妹妹|亲妹妹|亲生母亲|自己的母亲|父亲|公公|婆婆|儿媳|侍妾|丫鬟|主人
```
- 例：把角色档案中的某个行为从A专属改为B专属→检查状态栏/事件种子/描写库中的该行为是否需要同步修改
- 例：新增了一个道具条目→检查结局触发条件是否提到这个道具

## 4. 未改动但有联动风险的点
- alternate_greetings：改了角色定位但没改开场白？→开场白还是旧视角
- system_prompt：改了{{user}}能力但没改system_prompt？→AI不知道新能力
- 状态栏模板：新增了状态字段但没更新状态栏模板？→新字段永远不会被AI使用

## 5. 输出审查报告
只报三类问题：
- 🔴 修改未解决原问题（改了但没改对）
- 🔴 修改引入新问题（改了A坏了B）
- 🟡 边界波及（改动的涟漪效应）
- 🟢 顺手可修（和本次修改无关但一眼看到的明显问题）

**不报的问题**：不属于改动范围的其他条目问题（那是全量审查的事）。

**如果改动范围>15条或>50%条目→升级为全量审查**，用初始卡或NTL变体卡模板。

**即使改动≤15条，只要涉及以下任一项，也升级为触发专项/全量审查**：
- `keys / secondary_keys / selective / constant / enabled / prevent_recursion`；
- `system_prompt` 中 {{user}} 身份或世界规则；
- G型身份条目 / greeting 身份标记；
- 常驻系统条目合并/删除；
- validate 或 audit 出现新增 error/P0。
