# 守护卡/觉醒卡审查启动模板（通用版）

> **两种使用模式**：
> - **制卡流程内**（agent自审）：直接读取本模板内容，按步骤逐项执行，不复制到新窗口
> - **交叉验证**（用户手动）：复制本模板全部内容→替换所有 `[方括号]` → 在新Hermes窗口发送
>
> 替换所有 `[方括号]` 内容为实际值。
> 守护卡/觉醒卡定义：{{user}}=原主角觉醒，从"被动承受"变为"主动夺回"。和NTL卡的区别：{{user}}身份没变（还是原主角），角色定位变了。

审查守护卡/觉醒卡。**按顺序完成以下步骤。不允许跳过。**

## 0. 跑脚本
```bash
python "<HERMES_HOME>/skills/creative/st-character-card-authoring/scripts/validate_card.py" "[卡文件路径]"
```

## 1. 确认差异：原版NTR卡 vs 守护卡
读取两卡，用代码对比条目结构（复用/重写/新增三分类）。重点关注：
- system_prompt: {{user}}定位从"被动承受者"变为"主动夺回者"了吗？
- 全局规则: 核心理念变化是否正确？（"禁止变强"→"可以变强但有代价"类理念翻转）
- 状态栏: 是否新增了守护专属字段（唤醒值/反转道具/剧情节点）？
- 开场白: 从"撞见NTR→自欺"改为"觉醒→采取行动"了吗？

## 2. 唤醒/觉醒系统完整性（守护卡核心）
搜索"唤醒阶段""觉醒阶段""唤醒值""觉醒度"等关键词，确认被多条目协同实现：
- 唤醒规则条目：定义了哪些阶段？触发条件是什么？
- 状态栏条目：是否追踪唤醒进度？
- 角色档案条目：同一角色的"正常期行为"和"觉醒后行为"是否标注了阶段区分？
- 剧情节点：有没有"如果什么都不做，原著剧情就会发生"的默认逻辑？

**唤醒前后行为不同≠矛盾**：同一角色在不同阶段出现截然不同的行为是设计意图，只要条目标注了阶段/触发条件。

## 3. 决策树/多结局
- 结局条目列出了所有可能结局？触发条件明确且互斥？
- 剧情树条目描述了从初始到各结局的分支路径？
- 道具限制次数是否和结局触发条件对齐？
- 有没有"死胡同"结局——定义了但没有任何路径可以到达？

## 4. 反转道具系统
- 道具条目包含：获取方式/使用条件/使用效果/副作用/使用次数限制？
- 反转体验条目：描述了"使用道具后的体验变化"吗？
- 无限使用=无紧张感→必须有次数限制或代价

## 5. 内部一致性（守护卡专有）
- 原版描写库（NSFW/性爱描写条目）是否加了"仅苦主模式使用"的上下文说明？→ 不加的话AI会在觉醒模式下调用苦主模式的描写→叙事崩坏
- 不同条目中同一机制的描述一致吗？（唤醒阶段名/道具名/变量名）

## 6. 输出审查报告
按🔴关键/🟡重要/🟢优化三级。守护卡专属关注点：
- 唤醒系统是否闭环（定义→追踪→触发→结局）
- 反转道具有使用限制
- 剧情节点有默认推进（"什么都不做也会发生"=核心紧张感来源）
