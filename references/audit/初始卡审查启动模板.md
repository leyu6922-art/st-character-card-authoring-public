## 2. 计划书 vs 实际（按内容关键词映射，不按ID数字）
⚠️ **计划书的ID编号和实际卡的ID编号几乎永远不会一致。** 直接对比ID数字=大量假阳性。

**正确做法：按条目comment+keys中的关键词映射层级。** 从计划书提取每个层级的期望关键词，在实际卡中搜索匹配。

```python
# 从计划书提取期望层级 → 在实际卡中搜索（T28：必须搜comment+keys+content[:200]）
plan_layers = {
    "系统常驻": ["关键词1", "关键词2", ...],  # 从计划书复制
    "角色A档案": ["档案", "性格", "征服阶段", "对话"],
    # ...
}
for layer, keywords in plan_layers.items():
    missing = [kw for kw in keywords
               if not any(kw in e.get('comment','') or kw in ' '.join(e.get('keys',[])) or kw in e.get('content','')[:200] for e in entries)]
```

⚠️ **T28(2026-07-12)：必须搜keys字段**。关键词"唐幂恋情"在keys中而非comment/content中，漏搜keys导致假阳性。"文风锚点"在comment中为"文风与氛围锚点"——用子串匹配(`in`)而非精确匹配。

**判断缺失的优先级**：核心系统缺失→🔴 / 角色条目缺失→🟡 / 场景替换→🟢

## 3. 内容深度（弹性标准 + 计划偏差，双维度）
| 条目类型 | 低于多少报🟡 | 低于多少报🔴 | 注意 |
|---------|------------|------------|------|
| 角色条目 | <1000字 | <500字 | 标准线1500，±30%弹性 |
| 系统规则 | <500字 | <200字 | 轻量系统（状态栏/旁白）天然偏薄 |
| 事件种子(enabled=false) | <300字 | <150字 | 种子轻量但需有关键场景要素 |
| 描写/对话库 | <500字 | <200字 | 覆盖场景类型数比字数更重要 |
| NTR关系条目 | <400字 | <200字 | 含侵犯史+行为链+触发关键词（非矩阵≥600，矩阵≥300） |
| 开场白 | — | <1400字 | validate_card硬性要求，无弹性 |

**⚠️ 除了绝对值底线，还要检查计划偏差**（有规划书时）：
```python
for e in entries:
    plan_size = plan_sizes.get(e['comment'], None)  # 从计划书提取
    if plan_size:
        diff_pct = (len(e['content']) - plan_size) / plan_size * 100
        if diff_pct < -50:  print(f"🔴 计划{plan_size}→实际{len(e['content'])} ({diff_pct:.0f}%)")
        elif diff_pct < -30: print(f"🟡 计划{plan_size}→实际{len(e['content'])} ({diff_pct:.0f}%)")
```
**计划偏差和绝对值底线分开判断**：468字的事件种子虽然>150绝对值底线，但若计划1500字(-69%)→仍需报🔴。

子代理截断的判断：内容突然中断/句子没写完/大量"……"→截断。内容完整但简洁→正常。

## 4. 内部一致性
- {{user}}身份：system_prompt + description + personality + 所有条目中的{{user}}引用 → 一致吗？
- 角色名：同一个角色在不同条目中用了不同称呼？→ 是设计的多trigger还是混乱？
- 阶段矛盾：两个条目对同一角色的描述相反？→ 是不同阶段（设计意图）还是真矛盾？
- 外貌一致性：同一角色的外貌在不同条目中是否统一？
- **条目内重复段**（子代理merge artifact）：检查同一content中是否有标题相近的重复段落
  ```python
  import re
  for e in entries:
      sections = re.findall(r'【(.+?)】', e['content'])
      # 检测相似标题对：'X·补充设定' ↔ 'X·详细设定' → 🟡 疑似子代理重复
  ```
- **开场白角色覆盖**：first_mes中是否提及了计划书列出的所有核心角色？
  ```python
  fm = d.get('first_mes','')
  core_chars = ['[角色1]', '[角色2]', ...]  # 从计划书/SP提取核心角色列表
  for char in core_chars:
      if char not in fm:
          print(f"🟡 first_mes 未提及 '{char}'")
  ```
- 🆕 **开场白重复/补字灌水检查（T48/T77）**：
  - 同一句 `【旁白：...】` / `【系统：...】` 是否出现多次？
  - 是否有连续重复行、双版本拼接、`pad_to/填充/重复补字` 残留？
  - validate_card.py v5.0 已自动拦截明显重复，但审查窗口仍需人工读 first_mes + alternates。
- 🆕 **触发可达性抽查**：核心角色/威胁档案是否有自然角色名 key？速览是否自足（≥250-350中文字）？是否存在 `角色名档案/设定` 作为唯一 key？
- 🆕 **ST实测建议**：如可进入ST，查看 Prompt Itemization / `<Lore>`，确认脚本触发矩阵与实际注入一致。
- 🆕 **角色名一致性（T43·乖妈妈卡213处教训）**：不同条目对同一角色（尤其是{{user}}）的称呼是否一致？

  ```python
  # 从系统条目#0 提取正确的 {{user}} 称呼
  sys0 = entries[0]['content']
  # 搜全卡是否存在其他变体名（如"小雪" vs "小雨"）
  variants = ['[变体1]', '[变体2]']  # 从计划书提取可能混淆的名字

  ```
- 🆕 **裁剪后残留引用（T49·武林卡22处教训）**：如果卡经历过角色裁剪，是否已做全卡扫描？

## 6.5 人设内容质量（人工，脚本不覆盖；方法论见 references/design-patterns/persona-contradiction-modeling.md）

- **高频词加权检查**：对人设/常驻条目 Ctrl+F 搜 3-5 个高频词（角色称谓、核心设定词），每个超过 2 处即隐性加权，判🟡并给删减位置
- **单轴伪丰富检查**：把衍生/分支/素材单元各压成一句话，若多条互相等价（同一反差换措辞重复）判🟡——几百 token 等于一个标签
- **复读素材检查**：口头禅、逐字习惯小动作、上帝视角断言（"她永远不会X"且无缘由展开）→ 判🟡
- **否定句检查**：裸"禁止X"无正向替代的红线 → 建议补"替代：Y"（粉红大象效应）
