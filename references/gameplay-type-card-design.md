# 玩法型卡片设计参考

## 什么是玩法型卡

玩法型卡的核心不是"还原小说"，而是"基于小说世界观构建一个可重玩的体验系统"。

典型场景：用户说"做成玩法类型的""要有沉浸式体验""不一定要按原文来""体验感很重要""节奏很重要，不要单纯的母猪卡"。

## 设计框架

### 1. 提取世界观骨架（而非逐章剧情）

从原著中提取：
- 核心设定（场所/规则/魔法系统等）
- 角色清单（外貌/性格/关系/独特能力）
- 互动模式（角色之间如何互动、与主角如何互动）
- 氛围要素（气味/声音/视觉/触觉细节）

不要提取：
- 逐章剧情线（玩法型卡是非线性的）
- 具体对话（除非作为"风格参考"放在对话示例条目中）
- 一次性事件（只保留可复用的模式）

### 2. 构建系统层（占总条目30-40%）

系统条目是玩法型卡的灵魂：
- 全局规则 + OOC防护
- 节奏控制（强制的"不要直奔主题"规则）
- 选择/随机系统（让每次体验不同）
- 收集/进度系统（长期目标）
- 状态栏模板（实时反馈）
- 亲密度/解锁系统（多阶段内容）
- 事件触发系统（随机事件概率）
- 防拒绝 + 氛围维护

### 3. 构建角色层（占总条目30-40%）

每个角色需要：
- 基本信息（外貌/身材/穿着/体香/年龄感）
- 性格详解（200-400字深度描述）
- 语言风格（3-5句代表性台词，覆盖不同情绪状态）
- 行为模板（初见/调情/做爱中/事后 各阶段的具体行为）
- 特殊能力（该角色独有的互动方式）
- 与{{user}}的关系（亲密度各阶段的变化）

### 4. 构建场景层（占总条目10-20%）

- 各区域的描写模板（气味/声音/视觉/触觉）
- 场景转换描写（从A地到B地的过渡）
- 氛围强化素材（感官细节库）

### 5. 构建开场白层（占总条目5-10%）

玩法型卡的开场白对应"进入方式"而非"章节"：
- 首次体验（最详细的引导流程）
- 回访体验（跳过引导，直接进入选择）
- 随机模式（系统随机匹配）
- 特殊事件（不同场景的入口）
- 最终解锁（收集完成后的终局体验）

## 节奏控制是关键

玩法型卡最容易犯的错误是"一上来就进入正题"。必须在系统条目中强制规定：
- 阶段1：氛围营造（1-2回复）
- 阶段2：选择/接待（1-2回复）
- 阶段3：互动调情（2-3回复）
- 阶段4：正式体验（3-5回复）
- 阶段5：温存（1回复）

## 收集系统逻辑校验（关键！）

当设计收集/进度系统时，必须数学验证：**可获取物品数 ≥ 解锁所需数**。

### 常见逻辑bug
- 角色A是最终解锁奖励 → 角色A不提供收集物
- 剩余角色数 = 总角色数 - 1
- 如果解锁所需数 = 总角色数 → 死锁（少1个收集物）

### 修复模式：自定义生成系统
当收集物差1个时，用"自定义生成"补缺：
1. 新增世界书条目，定义AI生成流程
2. 触发条件：收集到N-1时自动触发，或玩家主动要求
3. 收集偏好：类型/外貌/性格/名字（让玩家参与创造）
4. 生成约束：必须符合世界观、有独特玩法、可参与集体活动
5. 内置示例：给AI一个格式模板，降低生成偏差

这种模式比"改规则把10改成9"更好——既修了bug，又增加了玩家参与感和可重玩性。

私有案例不随公开版分发；请用自有、获授权的成人样例验证此模式。
